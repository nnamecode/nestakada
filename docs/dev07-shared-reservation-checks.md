## RC07-LEASE — единственный writer/reconciler

Новый закрытый coordinator использует существующий PostgreSQL: session advisory key7342810601, `pg_try_advisory_lock` без ожидания, вне SQL transaction. Контекст lease запрещает reentrance и вход с active transaction/autocommit=false, запоминает connection object и backend PID. Перед каждым DB phase проверяет тот же открытый connection/PID; reconnect внутри lease не допускается. Finally проверяет/снимает именно свой session lock; исключение/утрата связи — fail closed, без автоматического повтора. Backend death освобождает session lock; чужой живой lease даёт BUSY503. Новых lockfiles/DB pending-моделей нет.

Lease охватывает reconciliation→admission/book→blob I/O→короткий DB commit→postcommit measurement/release. Content→auth xact locks берутся только в коротких DB phases; SQL transaction не удерживается при HTML normalization, file hash/write/fsync. При recovery сначала lease, затем content xact lock: если старый TX ещё держит его, bounded lock timeout даёт отказ, а не доказанную absence. Fresh owner/session/generation и canonical semantic DTO fingerprint/selector binding остаются обязательными; exact metadata replay предшествует старым source/FS/child.

## RC07-MEASURE — принятый assigned-share профиль B

Actual core = pg_total_relation_size прежних8 shared roots один раз + actual st_blocks allocation всех own blob/orphan/journal/dirs. Отдельно вывести полный AssetUsage root physical bytes, allRefs и ownRefs. Own refs определяются permanent SharedIdentityReservation: kind=sharedrevision+usage shared_block либо shareddraft+usage draft, с bound block. Доля `ceil(usageRootBytes*ownRefs/allRefs)`;0 own→0, own>all/неполное измерение→отказ. Это назначенная доля, **не физически причинённые каждым snapshot байты**. Не заряжать весь AuditEvent: аудит/WAL/backup имеют отдельный эксплуатационный/log budget; audit failure внутри mutation откатывает её, его физический рост в диагностике не объявляется0.

До book/blob выполнить prospective share forecast: учитывать все новые bindings как own+total additions; ожидаемое удаление старых own bindings не вычитать из предварительной верхней доли. Текущий physical Usage root плюс измеренный PG growth allowance профиля участвуют в forecast. Пример обязательного отказа: own=0/all=0 при раздутом1ГиБ Usage root, новая собственная ссылка назначила бы весь root — fixed4МиБ reserve не скрывает этот скачок. Page writers/cleanup могут менять знаменатель во время file I/O; final fresh content phase пересчитывает реальные refs/root/share и отказывает при нехватке, оставляя blob учтённым orphan. Рост доли от чужой cleanup не называется универсально предотвращённым.

Candidate для испытаний, **не уже принятые числа**:4МиБ полного hold на операцию; дополнительный FS metadata charge4096B на каждый own file/directory. Они будут заменены/подтверждены finite corpus и margin, не «теоремой×2». Профиль связывается с фактическими PG/version/schema/index signature и FS facts из calibration report; drift/неизвестность закрывают writes. Actual allocation, назначенная Usage доля, calibrated FS charge и held amount показываются раздельно. Полный hold остаётся целиком до outcome proof: не пытаться восстановить неизвестный baseline/«неиспользованный остаток» из11-field book после crash.

RC-REV001: SQL rollback может оставить AssetUsage bloat при ownRefs=0, и назначенная доля тогда0. Для этого0004 добавляет persistent SharedBudget.retained_debt_bytes (default/db_default0). Доказанный post-book abort атомарно создаёт terminal SharedReceipt(result_code=aborted,result_id=null) и увеличивает debt **только** на profile.usageAbortDebtAllowance (candidate512КиБ до calibration новых refs→rollback), а не на весь4МиБ hold: own PG/FS уже измерены actual. Full hold должен покрыть core/FS growth+этот debt component+settlement/margin; это отдельно проверяется конечным corpus. Debt не обнуляется автоматически.

Квитанция abort связывает operation/actor/generation/block/action/fingerprint/source_stamp/reservation_profile и новый immutable reservation_book_sha256. Она не является частичной успешной публикацией. Exact повтор после abort возвращает409 SHARED_OPERATION_ABORTED/outcomeKnown=true, не исполняется снова; UI сбрасывает только uncertain intent и требует нового явного Check/manual intent. При pre-admission отказе **до book** нет abort receipt/debt. Reconcile найденного abort receipt проверяет тот же book SHA и не начисляет debt второй раз; one-lastSettledUUID без постоянной квитанции недостаточен. Unknown/mismatch/overrun оставляют book/fault latch и отказ. Controlled unlink разрешён только после settlement commit+fresh measurement; его crash/retry не создаёт второй debt.

Предварительное условие: accounted current + prospective-share increase + existing holds + new full hold ≤268435456 и actual COUNT+snapshotIncrement≤10000. Fresh precommit и postcommit проверки требуют accounted actual + удержанный full hold ≤cap и COUNT≤10000; double charging занятого внутри текущего hold допускается как консервативный запас. Успех никогда не объявляется при измеренном превышении. Обнаруженный выход за проверенный профиль/measurement failure закрывает дальнейшие writes; использовать existing SharedBudget.accounting_version как persistent code-owned fault latch, не временный лог/TTL. Сбой записи latch сохраняет неразрешённый book и отказ.

## RC07-FLOW — book→file→atomic metadata→resolve

1. Под lease строго scan/read все journal entries. Unknown/corrupt/multiple-unresolved book закрывает новые операции, не трактуется как0. В короткой content transaction получить исход **того же** operation: receipt должен совпасть по book actor/generation/block/action/fingerprint/sourceStamp/profile/bookSHA; reserve сверяется с profile. 0004 добавляет immutable receipt.source_stamp, reservation_profile, reservation_book_sha256 (blank/DB default='' legacy); source не реконструируется по изменившемуся current. Known committed receipt не требует живого старого source. Отсутствие receipt доказывается только после content lock/завершения предыдущего TX и при отсутствии permanent operation identity; receipt отсутствует, а его reservation существует —UNKNOWN. Ошибка SQL или mismatch —UNKNOWN, book сохраняется.
2. Known committed либо доказанный aborted outcome можно завершить только после fresh полного measurement и проверки cap/profile. Orphans/PG bloat/Usage share остаются в actual; не вычитать их по ожидаемому rollback. Только затем controlled journal unlink: перечитать тот же book под flock, проверить исход/имя/inode/hash, unlink только эту запись, fsync всей цепочки и recheck named anchors. Это release конкретной брони по доказательству, не auto cleanup истории/blob. При ошибке durability ответ unknown/refusal; повтор не создаёт вторую mutation.
3. Для новой операции fresh context/base/media/proof+prospective quota → durable candidate-profile book с теми же11 полями SJR (новый code-owned profile ID после calibration gate). Только после admission писать immutable blob вне SQL; Check не сохраняет входящий HTML. Candidate не активируется через HTTP/env debug bypass.
4. Короткая atomic phase повторяет owner/session/context/Asset checks и свежую квоту, записывает file descriptor без HTML TextField body, refs/pins/identity/receipt/current и audit. Before commit actual+full hold/count проверяются снова; ошибка откатывает logical writes. После commit отдельно доказать receipt+fresh measurement, затем release. Потерянный ответ не возвращает ложное «откачено»; exact replay прежний result/gone без нового blob/версии.

Draft: existing draft меняется только при explicit matching draftBasis; current-mode не перезаписывает незнакомый draft. Basis сохраняется до explicit rebase, stale current отвергается целиком. Apply owner-draft явно потребляет выбранный draft/его usages/pins; current-mode не удаляет отдельный draft неявно. Restore prepare удерживает source/base без публикации, explicit Apply создаёт новый snapshot с source provenance и terminal consume stage/pin release. Безопасная очистка orphan/history и новые lifecycle команды не возникают автоматически из quota refusal.

Commit-time UI ACK: новая additive0004 добавляет nullable SharedReceipt.result_revision для номера сохранённого draft;0001–0003 не меняются, старое неизвестное значение не угадывается. Ответ `editorContext` — frozen `{baseRevisionId,sourceMode,draftBasis,stageId}`: apply→current/result UUID; draft→owner-draft/{result UUID,result_revision}/receipt.base_revision_id; restore_prepare→restore-stage/result stage UUID/receipt.base_revision_id. Gone и legacy draft без counter→editorContext:null. Никогда не подставлять latest Draft.revision или более новый current вместо зафиксированного результата: последующий stale Check должен честно отказать. JS/template меняет координатор отдельно: epoch/cleanEpoch, RAM-only uncertain intent со стабильными operationId/body/query для ручного повторного запроса, без autosave/storage; dirty не очищается при изменившемся вводе или gone. Backend/JS ACK tests обязательны до enable.
