# DEV-07 — HTTP check-only: сценарии до кода

2026-10-31. D-329/D-330/D-331, V07-001..011/015. Подготовлено до HTTP-тестов и подключения check-handler. Это ожидаемые результаты, не свидетельство прохождения. Источники: [editor contract](dev07-editor-contract.md), [runtime checks](dev07-runtime-checks.md), [transport amendment](dev07-transport-amendment.md), [processing profile](dev07-local-processing-profile.md), [normalizer checks](dev07-normalizer-checks.md), [V07](dev07-checks.md). Точные error JSON/API и wiring ещё подтверждает автор handler; ниже не вводятся новые URL, статусы, сроки или права.

Область этой когорты — POST проверки PageInput без save, draft commit, публикации или использования квитанции для записи. Предложенный check URL берётся из технического контракта, а тест привязывается только к фактически подтверждённому маршруту. Реальные write/replay/restore/renderer остаются отдельными последующими когортами. Большое тело разрешено только на точных трёх Page POST из принятого профиля; будущие save/draft здесь не получают фиктивный handler ради теста.

## Синтетические исходные условия и oracle

Локальные настоящие пользователь owner, назначенный employee с text-only, назначенный employee с price grant, чужой employee, visitor; собственные Page/current revision и отдельный owner draft-canary. Права/сессии/generation создаются штатными моделями/сервисами, без fake authenticated request. Исходный текст, прайс и canaries синтетические; реальные секреты не попадают в evidence. Исходные UUID и объекты строго ограничены fixture run; уборка не удаляет чужие данные и permanent audit/identity/operation ledgers.

Положительный контроль использует настоящий child/bootstrap/producer и существующий PG, а не mocked normalized result. Негативные unit spies допустимы для доказательства порядка admission/read/parse и адресной fault injection, но не заменяют положительный pipeline или сокетное испытание. До/после сравниваются current revision/payload, число и ID истории/Stable, draft basis/payload, refs/stages и content-operation receipts. Разрешённый bounded denial audit проверяется отдельно; он не равен изменению контента. Подписанная checkReceipt является stateless proof проверки, а не новым commit receipt или автоматическим разрешением сохранить.

## Разделение доказательств и readiness

1. `app/page_editor/test_check_http.py` после разрешения root: настоящие Django/PG сессии/grants/current, handler+child positive, strict DTO, early-order failure spies, signature/basis/recheck races и отсутствие мутаций. RequestFactory/client не доказывают socket deadline/framing/Nginx bypass. Подмена child output допускается лишь в fault/order test с отдельным названием.
2. Отдельный root-run transport corpus: реальные Nginx/gunicorn sockets, header-only early denial, CL/TE/framing, slow/abort/concurrency, exact-location profiles, no request buffering to disk и measurements полного максимума. Нельзя объявить весь H07 пройденным по unit-набору или прежним20 runtime guard tests.
3. Реальный browser UI (память вкладки, явная retry/нормализация, cache/storage, отсутствие выполнения HTML) требует фактического editor UI/DOM. До него H07 доказывает только server check; V07-008/016 остаются отдельными. Текущая задача не создаёт fake editor/public renderer.
4. `test_tables.py` и дополнения `test_policy.py` — только после frozen exact table/relative-URL-context API от исполнителя, с самостоятельными positives и отрицательными regression. Изменять прежний ControlledUnsupported oracle молча нельзя: готовность подтверждается новой capability и фактическим результатом.

Фактическое уточнение после запуска:19frameworkHTTP/PG tests и отдельнаяaudit regression PASS; после отдельной plain-normalization правки8child tests PASS. [Точный объём свидетельств](dev07-check-implementation.md). Это не прохождение всех H07 в полном объёме: socket/Nginx/framing/slow/max64МиБ/GUI остаются pending. Предыдущие pure/runtime PASS не переносятся на HTTP. Готовность основного check endpoint,64MiB end-to-end и всего DEV-07 не утверждается.

## Уточнённая первая когорта от автора

Root подтвердил только `POST /manage/pages/<uuid>/edit/check/`, первоначально **current-only**. DTO имеет ровно protocol/generation/baseRevisionId/editingFrom/draftBasis/stageId/changes. draft/stage получают явный409 `EDITOR_CAPABILITY_UNAVAILABLE`, без успешного proof; media/layout пока также неподдержанные возможности до READY/protected integration. Поэтому H07-009/022 сейчас проверяют контролируемый отказ, а не положительную готовность этих интеграций.

Успех: protocol=`page-editor-v1`, inputFingerprint, normalisedChanges, normalisationChanged, fieldWarnings с **field/code**, checkReceipt, baseRevisionId. Никакое message не ожидается сверх этого frozen subset. Ошибка внутри handler: `{ok:false,code:fixedcode}` с согласованным статусом; PrivateAccessMiddleware сохраняет HTML401/503, а CsrfViewMiddleware HTML403 до view. Для этих ранних границ проверяются статус/no-read/no-store, JSON не требуется. Конкретные коды сверяются с фактическим API, не с текстом исключений. Квитанция без нового TTL, связана с actor/generation/Page/base/permissionHash/policy и raw+normalized fingerprints; полноценный write-consumer ещё отсутствует.

Порядок: middleware identity/gate/Page grant/CSRF до тела; `inspect_context(actor,page_id,generation)` делает короткий snapshot внутри engine gate; затем slot, `read_json_bytes`, `normalize_input(raw,trustedcontext)` и повторное сравнение контекста перед подписанием. Во время read/child `connection.in_atomic_block` должен быть false. В integration допустим независимый cross-connection advisory try-lock и наблюдательный child stub для порядка; настоящий child-positive остаётся отдельным обязательным контролем. Shared4MiB не является capability этого endpoint. Точные import names/fixture wiring ещё ожидаются до исполняемого кода.

Минимальный предлагаемый набор `test_check_http.py` после разрешения: (1) owner real-child positive/no mutations; (2) employee text/price positives; (3) visitor/foreign/CSRF denial с exploding-body spy; (4) DTO/type/protocol/field refusal; (5) current/base/generation conflict; (6) explicit draft/stage/media capability refusal; (7) profile64/5 selection и budget denial; (8) permission/base race перед подписанием; (9) actual signed proof bindings/tamper; (10) no transaction/advisory lock observation; (11) bounded no-input errors/logging; (12) busy/release/fault recovery. Эти unit/integration проверки не закроют socket-only H07-004/005/014..017 или максимальный measured H07-012 без отдельных фактических запусков.

## Что нужно от автора перед исполняемыми тестами

- Фактический URL name/method и закрытые request/response/error shapes; точный supported check subset и основа current/draft/stage.
- Admission→CSRF→slot→body→child→parent recheck порядок, реальные names reader/child/signer seams и возможность наблюдать границы без новых клиентских debug switches.
- Server-owned profile selection, exact Nginx locations, Content-Length/TE handling и способ прервать настоящий WSGI read. Не предполагать gunicorn socket доступным без evidence.
- Trusted child context/result DTO, signature payload/verifier API и dependency recheck; отсутствие plaintext secrets/DB settings у child.
- PG fixture/service APIs и безопасная run-scoped уборка; конкретные locked rows для независимого lock-probe и разрешённые no-input audit assertions.

## Первый подготовленный исполняемый subset

После разрешения root и чтения frozen source записан `app/page_editor/test_check_http.py`:20 методов с подслучаями. После отдельного возобновления DEV07-Q003/D-333 добавлена регрессия CHECK-HTTP-REV-003: три настоящих forbidden-field POST сотрудника должны увеличить AuthSession.denied_page_count по одному, создать только одну первую SEC_PERMISSION_DENIED с occurrence_count=1/Result.DENIED и без lower-bound/input canary, не выдать checkReceipt и не изменить current/draft/history/refs/commit receipts. Новый тест ещё не выполнен. Используются TransactionTestCase/настоящие PG models+DEV05 services, реальные login sessions/CSRF и настоящий child. Для Django Client заменён только `views.read_json_bytes` на чтение framework request.body: Client не имеет требуемого WSGI socket. Поэтому это **framework HTTP**, не успешная приёмка product transport. Fault/order/race wrappers обозначены в именах, их результат не выдаётся за неподменённый socket proof.

Test-only ROOT_URLCONF включает реальный `http_urls`, а test-only MIDDLEWARE вставляет фактический EditorAdmissionMiddleware перед CsrfViewMiddleware. Product URLconf/settings не подключены этими тестами. Multipart owner/foreign exploding-read, foreign JSON, visitor, invalid CSRF/Origin, disabled session и late session invalidation проверяются отдельно; позднее завершение сессии ожидает401 `EDITOR_SESSION_ENDED`. Старый proof после смены semantic policy отвергается даже с прежним context; no-TTL signing не даёт права игнорировать текущую policy.

В subset также actual-child safe normalization/text/price/SEO, no content/draft/history/refs/commit-receipts mutation, current-only capability отказ, DTO/unsafe whole refusal, server64/5 profile selection, reader fault, current/grant race, signed claims/tamper и bounded error response. No-lock testcase проверяет in_atomic_block=false и доступность двух действительных advisory locks с независимого PG connection в reader и перед реальным child; это не все row-lock/interprocess/slow-upload сценарии. Busy/failure/retry пока адресные fault tests, не два настоящих Nginx соединения. H07-012/014..019/025 и browser UX требуют дальнейших отдельных evidence в обозначенном выше объёме.

Новые пакеты/настройки не требуются этим документом. Docker/network/install/runtime этим QA-агентом не выполнялись; подготовленный код пока НЕ ПРОВЕРЕН. Следом — freeze тестов, независимое ревью и запуск координатором; первая ошибка фиксируется с основанием повтора, вторая эквивалентная без нового условия останавливает работу.
