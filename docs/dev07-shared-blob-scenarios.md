## Первый инкремент и границы

Проверяются низкоуровневый immutable private blob store, новая metadata migration0002, единый body resolver и actual quota-read PG+FS. Не проверяется успешный product Draft/Apply/restore: неизвестный полный reservation profile остаётся закрытым. Нет fake profile, обхода admission, прямой записи fixture с последующим названием «успешный Apply» или автоматической очистки истории/orphans.

Пути/IDs назначаются доверенным сервером, а не HTTP/HTML. Перед тестовым кодом фиксируются точный root/layout/fan-out/имя, закрытая форма key, filemode metadata (storage mode/key/length/SHA), предельное число scanner entries и правило измерения allocated blocks файлов/каталогов. Первый инкремент не назначает недоказанный inode/allocator reserve. Нельзя превратить технические границы scanner в новые пользовательские бизнес-лимиты. Если формат/профиль не определён, сценарий остаётся gated, а не подстраивается под удобный результат.

Низкоуровневый blob roundtrip сам по себе не доказывает безопасность произвольного HTML, renderer, публичную выдачу или browser RAM. В fixture допускается заранее приготовленный безопасный UTF-8 текст; будущий функциональный pipeline обязан по-прежнему использовать настоящий shared child/schema/Asset проверки. Filemode история читает настоящие файлы, а не ожидаемый HTML из тестовой переменной.

## Независимые oracle

SHA256/UTF-8/длина ожидаемого содержимого считаются независимо до вызова store; фактические bytes повторно читаются через новый descriptor после завершённого write/close. `lstat/fstat` собственного файла проверяют regular file, правильного owner,0600 иnlink=1; каталоги закрытые, traversal без symlink. FD/FS trace наблюдает **настоящие** операции без подмены успешного write/fsync. Тест не выводит body, secrets, absolute production paths или raw exceptions; отчёт ограничен ID сценария/фиксированным кодом/размерами/SHA/булевыми фактами.

Успех durable write означает фактическое полное write/flush/fsync файла и успешный fsync родительского каталога до возврата publishable metadata. Наблюдение порядка вызовов и повторное открытие — свидетельство системных вызовов/протокола, не имитация отключения питания и не гарантия конкретного оборудования.

Файловый oracle не ограничивается `len(body)`: он измеряет actual allocated bytes=`st_blocks*512` собственных файлов и каталогов. Независимый обход `lstat` не следует ссылкам и сверяет **все** собственные entries, включая orphan/partial. Это только фактическая аллокация, не полный quota charge/верхняя граница скрытых FS затрат. Первый инкремент возвращает fsMetadataReserveAvailable=false, reserveBytes=null и оставляет profile выключенным; недоказанный ненулевой inode floor не выдумывается. Нельзя суммировать один и тот же inode дважды либо зачесть hardlink как нормальный способ экономии: неожиданное nlink!=1 — отказ. Unknown/unreadable/racy filesystem state не превращается в0байт.

До/после metadata операций сравниваются current/draft/history/schema/pins/refs/receipts и выбранные Page; для большого состава используется полный bounded ID/hash manifest. Orphan FS и logical DB state наблюдаются отдельно: SQL rollback не удаляет и не обнуляет уже занятый файл.

## Additive миграция и сохранность старых данных

Для migration теста historical models/schema состояние получают из фактического Django migration graph, а не из текущего класса с другим save(). Корпус и schema до/после читаются независимо.0002 только добавляет metadata/constraints и сохраняет любые существующие legacy inline HTML без переписывания bytes/ID/hash/current/refs. Предположение о пустой истории не является предусловием: отдельная fixture подтверждает сохранность непустых legacy revision/draft. Проверки выполняются в собственной изолированной unit fixture; миграция/DDL живого приложения, ручной DROP старых bodies или изменение history ради теста запрещены. Перевода inline в file в первом инкременте нет; будущий перенос потребует отдельного проверяемого контракта. Malformed новые file descriptors по-прежнему отклоняются, filemode missing не получает inline fallback.

## Что остаётся закрытым

Durable operation reservation journal/held book, attributable AssetUsage metadata reserve, автоматическая reconciliation, successful product write profile, replay/unknown-commit/crash protocol, реальные75%/256МиБ и simultaneous last reservation — последующие отдельные ворота. Будущие backup/restore должны включать metadata+blob+reservation generation; проверка файлового store не является выполненным DEV-22/23. Native browser сохранность несохранённого ввода, публичная композиция/меню/ETag и другие браузеры также не закрываются этими low-level тестами.

После независимого ревью технического контракта и этого QA документа координатор выдаёт ограниченный список исходников/тестов. Root запускает только проверенный frozen cohort. Итог помечает каждый ID PASS/FAIL/не исполнено, фактическую FS/DB среду и границы орacles; ни один полный AC или DEV-07 не отмечается выполненным заранее.
