# DEV-06 — ограниченный offline decoder

Основание: разрешённые владельцем DEV06-Q001/Q002, поправка 1 МБ = 1 000 000 байт. Старые 10 МиБ в черновиках не являются лимитом реализации. Этот пакет — только `tools/media_worker`; upload/application/Compose/зависимости сюда не входят.

План до кода: MW01 — JPEG/PNG/WebP настоящие байты и extension/MIME/signature; MW02 — точные byte/pixel/side границы, включая положительный 40MP RGBA; MW03 — EXIF orientation6 с заранее известными углами/300×400 и без EXIF/XMP/ICC/text; MW04 — заданная alpha и размеры 1920/480 без upscale; MW05 — truncated/animated/unsupported/mismatched input; MW06 — строгий bounded JSON, duplicate/unknown fields, UUID/path/symlink/повтор команды; MW07 — реальный дочерний timeout/reap и заполненный exchange; MW08 — корректная физическая receipt/hash и отсутствие исходных метаданных в выходе. Полные HTTP/права/private-original и legacy214 — отдельная интеграция, не имитируются этим worker.

Unix socket `/exchange/media-worker.sock` в том же согласованном tmpfs, mode0660, единственный последовательный job. App UID10001, worker UID10002, общий GID10001; job-каталог0770, input0640, выходы0640. Фиксированный корень `/exchange/jobs/<canonical-lowercase-UUID>`; только input.bin, job.lock, main.webp, preview.webp, receipt.json. Одна JSON-строка до4096байт с точными полями: version=1, job_id, extension (нормализованный `.jpg/.jpeg/.png/.webp`), mime, input_sha256, input_bytes. Никаких путей, URL, команд, base64 или имён пользователя. Job.lock создаётся O_EXCL: повтор команды в том же job-каталоге не исполняется. App удаляет законченный exchange-каталог перед следующей постановкой; долговременный UUID реестра медиа сюда не переносится.

Daemon не импортирует Pillow; отдельный процесс использует ограниченный набор OPEN formats JPEG/PNG/WEBP, signature+verify+полный load без разрешения truncated/animation, 40MP/10000px. Вход до1MB читается единожды в immutable bytes/BytesIO, сверяется SHA-256. EXIF применяется in_place до уменьшения, затем создаётся только маленький чистый RGB/RGBA-буфер; WebP quality82, lossy, alpha сохраняется. Метаданные не передаются encoder. Parent проверяет короткую receipt и реальные output bytes/hash; исходный файл не меняется. Новая пригодность Asset определяется будущей app-интеграцией, не этим JSON.

15с — общий deadline обработки принятого соединения; дочерний процесс запускается в собственной process group и убивается/reap по deadline. Сервер не имеет DB/HTTP API. Cgroup512MiB/1CPU/pids64/noNetwork/readonly/capdrop и tmpfs128MiB устанавливает/измеряет координатор; `peak_rss_kib` дочернего процесса не заменяет проверку общего cgroup/OOM. Точные 40MP RGBA/EXIF и actual ENOSPC должны пройти в реальном контейнере до допуска. Отсутствие универсального polyglot detector не выдаётся за свойство Pillow: наружу выходит только вновь закодированный WebP.

API `serve()` использует только фиксированные production пути. В тестах `process_job` получает доверенный TemporaryDirectory, это не поле сетевого протокола. Документация API Pillow проверена по официальным [ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose) и [Image.thumbnail](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.thumbnail). Исполнитель не устанавливал зависимости и не запускал Docker; фактических результатов пока нет.

Запуск проверок координатором в уже подготовленном проверяемом образе: readonly bind `tools/media_worker` → `/worker`, рабочий каталог `/worker`, writable `/tmp`; команда `python -m unittest -v test_worker`. Интеграция: daemon `python /worker/worker.py`, общий tmpfs `/exchange` и заданные UID/GID; отдельный fixture-процесс `python /worker/probe.py --positive` (40MP RGBA+EXIF6 и JPEG+EXIF6, реальный socket и replay) и затем `--full` (реальный ограниченный ENOSPC и отсутствие success receipt). Fixture helper требует Pillow, но не DB/app/private mounts. Positive generator работает отдельно от worker cgroup: пиковая память worker должна измеряться по его cgroup/memory.peak и Docker OOM, а не только полю receipt или памяти generator. Helper удаляет только известные имена своего UUID job, без recursive delete. Daemon создаёт jobs0770 при отсутствии, сохраняет inode существующего сокета и отказывается поверх него запускаться.

Адресные REV003/single-frame: receive перед каждым чтением ограничивается min(2с, остаток общего15с), прогресс по одному байту deadline не продлевает. Parent повторно проверяет deadline после физической проверки receipt/хешей; sendall получает только оставшееся время. После исчерпания времени соединение закрывается без success, а JSON timeout не отправляется за пределами бюджета. PNG acTL и WebP VP8X animation-bit/ANIM/ANMF отклоняются структурно даже с одним кадром; chunk lengths проверяются в пределах входного буфера. Строки ANIM/acTL внутри легитимных text/XMP не являются animation markers. Добавлены validity-control однофреймовых APNG/WebP, положительные metadata false-positive, повреждённые длины и детерминированные slow-drip/send/post-verification deadline-проверки. Подготовлено 21 проверка, фактическое исполнение пока не выполнено исполнителем.

## Фактический результат и допуск к локальной интеграции

31.10.2026: 21 unit/protocol/decoder проверка PASS за 8.723 с на минимальном image. Через настоящий Unix socket отдельно прошли PNG RGBA 40 Мп с EXIF6 (2.529 с) и JPEG RGB 40 Мп с EXIF6 (1.375 с). Ожидаемые размеры 1200×1920 и 300×480, альфа, отсутствие EXIF/ICC/XMP, неизменность исходника, реальные SHA и отказ повтора проверены helper, а не объявлены самим worker. Исходные файлы укладываются в согласованный 1 МБ.

Пик cgroup памяти 414359552 байта (~395.2 МиБ) при максимуме 536870912; max/oom/oom_kill=0. CPU 1, pids64, UID10002/GID10001, network none, cap-drop ALL, no-new-privileges, readonly root; сеть фактически недоступна (errno101), секретов/приложения/медиатеки/Docker socket нет. Заполнение общего tmpfs дало ENOSPC и контролируемый отказ без success receipt. Проверка реального subprocess timeout убивает и reap дочернего процесса; slow-drip общий deadline проверен детерминированно, без ожидания 15 с.

Независимый рецензент прочитал реальные receipts, пересчитал три SHA снимка и подтвердил достаточность для ограниченной локальной интеграции. REV003 (общий deadline) и single-frame animation исправлены и повторно проверены. Native/vendor-остаток, точная минимизация и пределы ELF описаны в dev06-worker-security.md; полный CVE-аудит не заявляется.

Артефакты: work/dev06-20261031/worker-{units.txt,positive.json,full-exchange.json,isolation.json,inspect-before.json}; снимок worker-source/manifest.json. Идентичность image/base/исходников/зависимостей — environment/media-worker/candidate-receipt.json. Образ содержит Pillow, проверенный worker-код подмонтирован отдельным readonly снимком; это ещё не упаковка production.

После проверки собственные контейнеры остановлены и удалены, образы/доказательства сохранены. После снятия последнего монтирования Docker tmpfs действительно пуст; отсутствие прежнего socket при контрольном монтировании ожидаемо и проверено отдельно. Постоянные данные ядра/БД не удалялись.
