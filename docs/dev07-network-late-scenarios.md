## NET07-007 — действительные права и сессия меняются во время body read

Начальный положительный контроль: настоящий назначенный employee с разрешённым main_text проходит Check. Для write заранее получить настоящий CheckReceipt текущего base и один operationId через существующий HTTP. Синтетический JSON подходит текущим правам; последние bytes ещё не отправлены. A обязан дойти до реального slot-held, reader-enter и deadline-enter, normalize-enter0/request-end0. Требуются actual observer и независимый NB flock witness, не факт client.write либо sleep.

| NET07-007.grant | A — employee Check. Owner отдельной настоящей сессией/CSRF делает form POST `/manage/employees/<id>/grants/` с `page=<own Page UUID>, action=revoke`. Только после actual303 к employees дослать весь A JSON. | Настоящий child обрабатывает допустимый ввод по первоначальному server context; поздняя проверка отказывает403 EDITOR_FIELDS_FORBIDDEN. Slot/timer/duplicate FD действительно освобождены; отсутствие sampled PID не заменяет normalize counters. |
| NET07-007.session | Восстановить grant реальным owner action=set с ранее разрешёнными intro_text/main_text=on; не добавлять price. Owner controls: после каждого отказа, до восстановления доступа employee, новый owner Check проходит на той же Page. Это исключает ложный PASS «всё приложение перестало отвечать». Grant возвращается только существующим owner action, employee после reset входит настоящим login с новым synthetic password; userId тот же, generation актуальна, Check вновь проходит. Старый cookie/generation не становится действительным из-за нового входа в другом context. Вновь полученный proof не переносится в ранее сохранённый старый request автоматически.

Проверки по каждому A: body действительно завершён; reader/normalizer enter+exit по1, slot exit/request end по1; timerAlive=false/duplicateClosed=true/slotFdClosed=true/expired=false. Ответ private/no-store, только fixed code. Observer outcome не угадывается по позднему401/403: JSON-fault может быть перехвачен view вне обёрнутых seams, поэтому actual HTTP status/code и обязательные events проверяются отдельно. No-reader/no-child oracle ранней авторизации из NETWORK_6 не применяется к этому позднему отказу.

## NET07-008 — полный Save, непрочитанный ответ и точный manual replay

Нужно воспроизвести потерю результата на стороне application client, сохранив настоящий writer. Предлагаемый детерминированный способ: отдельный raw socket перевести в paused/no-response-consumer состояние до отправки; не ставить callbacks, читающие/декодирующие response data, и не вызывать read/resume/pipe. Отправить весь подготовленный Save Buffer с корректными Content-Length/CSRF/query/proof/opId. Только сумма client.write не доказывает доставку: независимо дождаться actual reader-exit/deadline-exit и normalize-enter, затем terminal request и существующего scoped receipt/domain witness. После этого закрыть непрочитанное соединение.

Ни ядро, ни Nginx не обязаны «не доставить ни байта»: response мог находиться в kernel/Node buffers или уже быть записан сервером. Проверяемое утверждение — application test client его не прочитал и не разобрал; этот способ не доказывает сетевой RST точно между commit и write. При невозможности bounded passive witness — FAIL/pending, а не искусственный sleep или ответ от test endpoint.

| Шаг | Проверяемый исход |
|---|---|
| NET07-008.full | Настоящий owner Save получает полный canonical input, реальный normalizer и короткую атомарную запись. Пока application client не получил результат, его состояние — UNKNOWN. Общая семантика допускает0или1 полный commit, но не partial; выбранный положительный terminal200+receipt witness обязан подтвердить именно один произошедший commit, а не ложную успешность transport. |
| NET07-008.replay | Отдельное явное действие клиента под тем же actor и актуальной допустимой session повторяет EXACT Buffer/query/operationId/checkReceipt/base. Новый traceId, никаких вновь сгенерированных content IDs/автоповтора. Ответ200 с тем же operation_id/result_id/action/result_code и replay=true; current/history/refs/pins/receipts/version audit не получают второй результат. |
| NET07-008.same-op-changed | Отдельный отрицательный запрос оставляет operationId, но меняет canonical text body. |
| NET07-008.stale-new-op | Отдельный отрицательный запрос заменяет только operationId новым, оставляя старые proof/base/body. После исходного commit текущий base уже другой. |

Для same-op-changed требуется409 EDITOR_OPERATION_CONFLICT; для stale-new-op —409 EDITOR_BASE_CONFLICT. Ни один отказ не возвращает successful result_id/checkReceipt и не создаёт второй content receipt/версию/публикацию. Эти запросы — намеренные negative tests, а не продуктовый retry после UNKNOWN. Успешный exact replay не означает, что новый operationId со старым proof допустим.

Сравнение after-first-commit→after-replay→after-negatives включает точный набор content receipts и versionAuditCount, не только конечный текст. Исходный receipt ищется по собственному opId в existing guarded observer; он не вставляется напрямую. В таблице запросов сохраняются только безопасные собственные IDs/status/codes/hash equality flags, а не raw body или токен. Здоровый owner Check после reconciliation подтверждает освобождение slot и работоспособность профиля.

Важная граница: тестовый privileged observer может знать terminal/receipt раньше, чем client. Продукт не получает нового observer endpoint и не использует его для определения успеха; legitimate клиентский механизм здесь только существующий exact-operation retry. Намеренно paused test socket не объявляется реализацией пользовательского интерфейса UNKNOWN. Полный browser same/different identity RAM matrix и все draft/stage/media/FS-late-race сочетания остаются отдельным остатком.
