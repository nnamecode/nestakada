# DEV07-RST — завершённая подготовка восстановления: проверки до кода

2026-11-01. Продолжение DEV-07 после TP2 по поручению владельца «давай дальше». Это ограниченный срез существующих D07-018/019/028 и частично D07-017/029, V07-007/009, V05-017. Новые правила, зависимости, TTL, права владельца на чужой stage и формат editor DTO не вводятся. Результаты будут записаны отдельно после фактического исполнения и независимого ревью.

## Ожидаемые проверки

| ID | Действия и проверяемый результат |
|---|---|
| RST-001 | Собственная held-подготовка читается и проверяется через настоящий editor HTTP; current/history не меняются, исходные source/base pins сохраняются. Это положительный контроль работоспособного пути перед отрицательными проверками. |
| RST-002 | Явная отмена собственной подготовки освобождает её pins. Editor GET/state/Check и новый Save с прежним stage отказывают без candidate/HTML/checkReceipt и без публикации. Повтор исходной операции stage_restore возвращает сохранённый terminal result released без кандидата и новых domain/audit записей. |
| RST-003 | Собственный stage применяется отдельным проверенным Save ровно один раз, с provenance/consume. Editor GET/state/Check больше не выдают candidate; точный повтор Save возвращает прежний durable результат, не создаёт новую версию. Новый operation ID не превращает consumed stage в доступный источник. |
| RST-004 | Настоящая смена current делает старую подготовку invalidated штатным version command. Её pins освобождены; selected-source отказывает, replay исходного stage_restore честно отражает terminal invalidated без кандидата. Сами read/check не публикуют и не создают новую подготовку. |
| RST-005 | Изменение прав actor делает held stage несовместимым. До следующей штатной semantic invalidation выбранный источник уже недоступен; read не выдаётся за немедленный cleanup hook. Точное восстановление прежних прав до invalidation может снова разрешить held stage на той же source/base: новый постоянный запрет не вводится. Последующий настоящий current commit штатно invalidates stage и освобождает pins. Автоматического переноса source/base нет; полная generation/session матрица отдельно. |
| RST-006 | Второй сотрудник с действующими такими же правами на ту же Page, а также владелец не получают и не применяют чужой stage знанием UUID. Отмена чужого stage запрещена. Проверяются собственный положительный stage и сохранность чужих status/pins/current. Page grant сам по себе не считается доказательством stage actor binding. |

Для каждого случая сравниваются current, история, stage/status/source/base/actor, pins и durable operation receipts. Допустимые denial-аудит и session touch отделяются от domain mutations. Отказы используют фактический существующий fixed-code contract; ожидания не меняются ради прохождения теста без статического обоснования и независимого ревью.

Framework использует настоящие PostgreSQL/session/CSRF/child/DEV05 APIs и существующий явно указанный body-reader seam; он не доказывает Nginx/socket поведение. Отдельный Chromium/Nginx набор проверит видимые terminal results/replay, запрет подстановки и чужой stage на синтетических данных. Fixture ограничена своими проверенными IDs; системный Route и постоянные ledgers не удаляются.

Независимое precode-ревью подтвердило этот test-only срез. Terminal replay означает настоящий сохранённый operationId/preparation исходного stage_restore; отмена дополнительно проверяется своим исходным operationId. Generic409 editor selected-source безопасен, но не равен terminal-specific представлению собственного stage_read. Последнее остаётся явным незакрытым UX-пунктом D07-018 и не считается реализованным этим набором. Продуктовый код меняется только при подтверждённом дефекте, после отдельного технического ревью исправления.

Gone после физического удаления stage, полная stale-generation/identity/RAM/MAX/media/legacy/browser матрица, production/public renderer и восстановление резервной копии не входят в этот срез. Отсутствие этих доказательств остаётся в общей матрице D07. Нового API удаления stage для теста не вводить. Старый сайт/VPS не затрагивать; DEV-07 около 98%, этап 8 около 20%.
