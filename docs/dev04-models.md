# DEV-04 — модели дерева и маршрутов

Основание D-318, REQ-001–007, D-023/239–247, аналитика content-detail и html-reserve §11–12. До кода выбраны частичные проверки модели из LIFE-003/004/005/006, URL-REUSE и URL-TRANSITION: точная идентичность адреса, запрет коллизии Page/redirect, непереиспользуемые UUID, отсутствие циклов/каскада, ручной публичный порядок и пропуск скрытых предков. Полные HTTP/UI e2e требуют DEV-29/03/15 и не запускаются через fake fixtures.

Модельные сценарии DEV04-M01..M12: (01) безопасный новый Page/пустое имя/закрытый тип; (02) добавление в конец/rename без смены позиции; (03) parent self/multilevel cycle rejection; (04) скрытие предка не меняет детей; (05) PROTECT любого ребёнка; (06) точный slash/case/query/alias, без нормализации; (07) единое уникальное пространство primary/alias/redirect; (08) одна primary на Page; (09) redirect ссылается на Page, не на redirect, читает актуальную primary; (10) неизвестный/скрытый read-state, без HTTP-обработчиков; (11) legacy route immutable через обычный save, UUID immutable/duplicate insert; (12) конкурентная гонка за родительство/занятый адрес не создаёт недопустимое дерево/дубль. Эти сценарии исполняются как PostgreSQL integration, не выдаются за полные AC.

DEV-04 не открывает публичные маршруты. История/currentRevision/черновики, права, команды публикации/move/delete/change URL, внешний head и tombstone — последующие DEV-07/03/29/15. Model save и ORM ниже — внутренняя граница целостности для разработки/будущих доверенных сервисов, не интерфейс владельца и не замена авторизации/внешнего head.

## Реализованный контракт

Page: UUID, закрытый тип из согласованной карты маршрутов, название до 200 символов, настоящий родитель PROTECT, неотрицательная позиция, собственный флаг публикации. История и SEO здесь не дублируются в пустые JSON-заглушки; их модели появятся в соответствующих задачах. Новый элемент при отсутствии заданной позиции получает конец списка; rename не меняет позицию и URL.

Route: UUID, точный request target (до 2048 UTF-8 байт, сравнение C), primary/alias/redirect/system в одном уникальном пространстве. Primary на объект не более одной. Alias нужен для точного старого 200 (например старая ссылка автомойки и значимые параметры); он не превращается в 301. Redirect хранит ссылку на Page, а чтение получает актуальную primary этого объекта. Отсутствующая primary — явная storage inconsistency, без ложного ответа/Location. SYSTEM резервирует точный ключ; фактические namespace/prefix/resolver checks частных будущих обработчиков должны быть добавлены до DEV-03/29, их адреса не выдумываются здесь.

Старые target/kind/page/is_legacy защищены в обычном save, перенесённые URL не нормализуются. Новые пути проверяются отдельно; чистый suggest_segment следует PR-07 (NFC, ё→yo, щ→sch), не меняет name/старый URL, не обрезает и не добавляет скрытый числовой суффикс. Генератор полного пути/правило слеша типа/owner preview остаются DEV-29. UUID сохраняется; новый instance с существующим ID не перезаписывает запись. Удаление через обычный model/queryset API пока запрещено целиком, оно не является готовой командой удаления пустого родителя.

Внутренний validated save берёт транзакционный PostgreSQL advisory lock CONTENT_LOCK=7342810401 перед проверкой и записью. Это реализация контентного домена PR-08: будущая команда берёт тот же домен до row locks, проверяет права/актуальную редакцию и координируется с head. Нельзя удерживать lock во время сети/перекодирования. Bulk update/create/delete отклоняются. Прямой SQL/внутренний _base_manager не объявлены пользовательским API или защитой от администратора БД. FK/DB-checks/unique constraints дополняют модель; запрет многоуровневого цикла проверяется под lock. Не обещается полный optimistic concurrency/авторизация до DEV-03/29.

resolve_target и public_tree — внутренние read projections, не HTTP handlers. Чтение точного alias/primary различает published/hidden; redirect не строит цепочку из пользовательских URL. public_tree пропускает скрытых предков только в проекции, сохраняет реальное родительство/собственные флаги и позиции; фиксированное верхнее меню не перестраивается. Закрытый редактор/черновики/настоящий импорт не созданы.
