# DEV-07 — локальный профиль чтения и обработки

2026-10-31. **DEV07-Q002 принят владельцем для подготовки и локальных испытаний, D-331.** Подключение handlers только после фактических проверок и независимого ревью; готовность заранее не утверждается. Вместе с dev07-transport-amendment.md определяет согласованную область настройки. Задача — вместить уже допустимый большой прайс и ограничить последствия сложного HTML без повышения ресурсов приложения.

## Предлагаемое поведение

1. До чтения JSON проверяются текущая сессия/generation, Page-доступ, owner-роль при owner-only действии, application/json и CSRF заголовком. Владелец или сотрудник с price-grant может использовать максимум64МиБ только на трёх точных Page-путях из transport amendment. Сотрудник без price-grant — до5МиБ канонического JSON для своих текстовых областей и служебных ID; их принятые лимиты не уменьшаются. Shared HTML операции не получают64МиБ: их собственный малый reader до4МиБ под прежним внешним11МиБ.
2. В одном локальном app-контейнере допускается **одна** такая тяжёлая editor-операция одновременно. До чтения тела берётся nonblocking process/thread-safe файловая блокировка в собственном tmpfs; при занятости —503 и сохранённый ввод в открытой вкладке, без очереди/автоповтора. Ни SQL content/auth lock, ни DB-транзакция во время upload/parse не удерживаются.
3. Абсолютное чтение тела — до120секунд и до установленного byte-budget, включая неверный Content-Length/обрыв. Nginx streaming не пишет большое тело заранее на диск. Точный framing/длина/тайм-аут проверяются на настоящем локальном сокете до допуска; один inactivity timeout Nginx не называется абсолютным deadline.
4. JSON/HTML/CSS нормализуются короткоживущим **дочерним процессом того же принятого Python**, без новой программы/постоянного сервиса/контейнера/порта. Статический исполняемый файл приложения, фиксированный протокол stdin/stdout; никакой пользовательской команды/имени файла. Окружение очищается, открытые дескрипторы не наследуются, пароль/CSRF/session key/секрет БД ему не передаются. Это ресурсное разделение внутри существующего контейнера, не самостоятельная файловая/сетевая security sandbox.
5. Предлагаемые пределы дочерней обработки: адресное пространство384МиБ, CPU10секунд, wall20секунд; результат pipe также bounded. При превышении процесс завершается/reap, current/версии/refs/receipt успеха не меняются, введённый текст остаётся в RAM браузера. После успешной проверки родитель повторно проверяет доменные права/base/медиа и фиксирует короткую атомарную операцию существующим DEV-05 engine.
6. RAM768МиБ/1CPU иpids128 app-контейнера, БД/worker, CSP и Windows остаются прежними. Ресурсный guard должен учитывать родителя вместе с ребёнком; сумма не объявляется подходящей до фактических измерений. Новые библиотеки/контейнер parser-worker этим не вводятся. Старый сайт/VPS/production не используются.

## Что разрешает предполагаемый ответ

Подготовить код и локально проверить этот профиль; подключать соответствующие editor handlers только после фактических положительных/отрицательных проверок и независимого ревью. Если максимальный допустимый payload не проходит эти пределы, не усекать контент и не повышать лимиты автоматически: сохранить результат и предложить исправление. Пределы определяют работу системы, не срок реакции или обязанность владельца.

## Проверяемые основания и границы

- Настоящий schema-valid пример прайса с текстами —43475643байта против11534336 действующего body-limit; это основание выбора транспорта, не доказательство полного handler.
- Кандидатные Python-пробы12PASS: около20000 HTML-элементов разобраны менее чем за1секунду, максимальный наблюдавшийся child RSS53168КиБ. Это ограниченный corpus, не проверка всего будущего producer/JSON/чтения и не гарантия для всех входов.
- До подключения нужны canonical максимум всех полей/Unicode, actual parent+child peak и время; adversarial JSON/HTML; сокетные early401/403 до тела, неоднозначное framing/chunked, медленная/оборванная передача; controlled kill/reap; два параллельных запроса и сохранность ввода; no disk/input/log копии; повторный DOM/permission/FS recheck перед commit.
- Конкретное прекращение блокирующего socket read и непропуск очереди требуют технического ревью кода. Нельзя выдать проверку времени между двумя read за абсолютный тайм-аут.

Альтернатива — сохранить нынешние11МиБ и подготовить другой атомарный протокол больших прайсов; штатный богатый редактор при этом ещё не готов. Молчаливое уменьшение уже принятых границ не предлагается.
