# DEV29-Q002: изоляция HTTP-проверки команд дерева

2026-11-03. **Предложение, не разрешение на изменение прав.** DEV-29 около 5%, этап 8 около 31%. Основание: D-405, CMD29-008. Новых программ, образов, контейнерных служб, томов, портов и увеличения ресурсов не предлагается.

## Зачем требуется уточнение

186 PostgreSQL/Django-проверок, включая 26 новых, прошли за 188,184 с. Код команд прошёл независимое ревью. Проверка через настоящий Nginx ещё не пройдена.

Первый HTTP-helper завершился до получения seed-manifest и до HTTP-запросов с CMD_WIRE_DOCKER. Его stdout/stderr не были сохранены из-за порядка обработки ошибки; точный первоначальный текст отказа неизвестен. Последующая read-only диагностика показала в обычной локальной базе estakada_foundation 3 пользователей, 6 страниц, 22 версии, 3 обычных и 3 AuthSession-сессии, 6 несистемных маршрутов, 0 tree receipts. Это несовместимо с проверенным требованием пустоты seed. Причину отказа связываем с этим условием; исходный код ошибки не выдаём за полученный факт. Старые данные не очищались, seed не повторялся.

В существующей estakada_foundation_unit уже прошёл набор тестов, но tools/foundation_db_init.py намеренно запрещает app_runtime подключение к ней. Поэтому простая подмена имени БД не является допустимым продолжением старого плана.

## Рекомендуемый конечный профиль

1. Сохранить SHA исходников, конфигурации, Docker image/CID/labels, исходные ACL обеих БД и схемы app. Изменения в MAIN не выполнять. Снять read-only контрольные суммы данных MAIN, включая пользователей, версии, сессии, права и постоянные журналы; сырой снимок только в прежнем закрытом private, публично — суммы и счётчики. Остановить приложение и ingress до подготовки.
2. Через прежний привилегированный init-профиль с прежними секретами временно разрешить app_runtime только CONNECT к существующей UNIT, USAGE схемы app, SELECT/INSERT/UPDATE/DELETE на её существующих таблицах, USAGE/SELECT существующих последовательностей. Никаких CREATE, TEMP, членства, изменения владельца или default privileges. Сохранить точный исходный ACL, в том числе grantor/grant option; при неожиданном ACL отказаться. MAIN ACL не менять. Привилегированные секреты не передавать APP.
3. Временный проверяемый Compose override меняет у прежнего сервиса app только ESTAKADA_DB_NAME на estakada_foundation_unit. Остальные source/image/user/mounts/networks/caps/порт 127.0.0.1:8767 прежние. Не запускать units/migrate/init параллельно с HTTP-профилем. Обычный Start запрещён, пока журнал временного профиля не закрыт.
4. Перед записью проверить фактические current_database/current_user, TLS, source SHA и единственность локального запуска. Seed допускается только при пустых User/Page/PageRevision/PageContentState/AuthSession/Session и отсутствии несистемных маршрутов в UNIT. Другие строки не удалять ради допуска. Если UNIT непуста — отказ и возврат прав; повторный сброс тестов для очистки не выполнять. Полный baseline UNIT сохранять приватно, с явными исключениями только для собственной fixture и обычной обработки её auth-состояния.
5. После code/QA-review исправленного helper выполнить конечный CMD29-008 из dev29-tree-commands-http-plan.md: ровно 2 synthetic users, 6 pages, 3 routes, login/CSRF, rename/replay/stale, move/reorder, employee403, SQL-наблюдение и ресурсные измерения. Пароли/CSRF/cookies/tokens остаются в foundation/test/private. Данные/файлы MAIN не использовать. Работа с медиа, общими блоками и APP↔TRUST не входит.
6. Исправить сохранение диагностики: сначала сохранить stdout/stderr и exitCode Docker приватно, затем обработать отказ. Секреты не печатать. При ошибке — остановиться и исследовать сохранённый результат, без автоматического повторного seed.
7. В finally сначала остановить APP/ingress. Для строго адресной очистки собственной fixture запустить один одноразовый helper через **существующий Compose-сервис app** (`run --no-deps --rm`, без service-ports), заняв освободившийся слот остановленного APP. Команда вместо HTTP-сервера — Python-helper, получающий проверенный код/manifest через stdin; настройки UNIT и app_runtime, прежний runtime-secret, read-only source и прежние лимиты APP. Одновременно HTTP APP и helper не работают; новых сервисов/томов/образов нет. Проверить новый полный CID, отсутствие портов, настройки/права/источник до SQL. Это не exec в остановленный контейнер. Init/migrate/units для очистки не запускать. Helper жёстко требует фактическую UNIT/app_runtime и не обращается к MAIN; права runtime в MAIN остаются прежними, абсолютного запрета CONNECT к MAIN этим не заявляем. Очистка только по точным UUID/ownership/baseline; неизменяемые новые operation receipts/UUID/audit оставить в UNIT. Не удалять всю БД, схему, таблицы или том. Прежние UNIT-строки сохранить. Обычная auth-очистка относится лишь к проверенному UNIT baseline, не к MAIN; точный допуск описать и проверить до запуска helper. Helper полностью завершить до возврата ACL.
8. Вернуть UNIT ACL в точности к исходным, подтвердить отказ подключения app_runtime к UNIT и неизменность MAIN ACL/контрольных сумм. Временный override отключить. При сбое восстановления прав или очистки не запускать APP, сохранить журнал незавершённого профиля и сообщить владельцу. Обычный Start допускается лишь после подтверждённого закрытия профиля; проверки восстановления должны исполняться также после перезапуска координатора. В конце Stop, 0 контейнеров проекта, данные/ключи сохранены.

Это временный локальный профиль испытаний, не изменение production-прав. Проверку отказов cleanup/revoke/restart подготовить до запуска. Результат HTTP нельзя считать PASS без восстановления ACL, сохранности MAIN и итогового независимого ревью.

## Альтернативы и согласование

Рекомендуется этот профиль: он использует существующую тестовую БД и проверяет настоящий app_runtime через настоящий Nginx. Альтернатива — пока ограничиться 186 пройденными проверками и оставить CMD29-008 открытым. Создание ещё одного окружения увеличит ресурсы и здесь не предлагается. Очистка обычной локальной БД и изменение пароля существующего nesadmin не предлагаются.

Отдельный ответ DEV29-Q002 требуется по AGENTS.md: «Конкретная архитектура, версии и зависимости проходят отдельное согласование». Меняются временные права UNIT и выбор БД локального HTTP-приложения. D-405 сохраняет силу для команд дерева, но не подменяет согласование этого профиля. До ответа подготовить документацию и независимое ревью; grants/override/seed не исполнять. Старый сайт, VPS, production и push не входят.
