2026-11-03. DEV29-Q002 согласован по D-406. DEV-29 около5%, этап8около31%. Код инструментов ещё проходит ревью; grants/seed не выполнялись.

Инструменты находятся в work/dev29-apply-20261103, вне Git. unit-controller.mjs ведёт закрытый журнал cmd29-unit-admission.json, фиксирует stdout/stderr Docker до обработки отказа, проверяет локальный Docker Desktop/Compose/source/runtime. unit-wire.mjs выполняет конечные реальные HTTP-запросы через Nginx. unit-fixture.py жёстко требует UNIT/app_runtime и прежний local_http.

До seed отдельный prepare читает baseline и создаёт точные запланированные user/Page/Route IDs. Координатор сохраняет manifest приватно до записи. Только после этого seed атомарно создаёт собственные объекты. Это позволяет после потери ответа проверить либо точное собственное дерево, либо доказанное отсутствие seed; произвольная очистка чужих объектов запрещена.

unit-lifecycle.mjs независимо обрабатывает остановку HTTP, адресную очистку, возврат ACL и Stop. Отказ очистки не пропускает отзыв прав. Незакрытый журнал блокирует обычные Start/UnitTests через scripts/local-foundation.ps1; Stop/Status остаются доступны. Recover не повторяет seed/HTTP-команды.

Точность возврата ACL означает совпадение всех исходных полномочий, grantor и grant option. Каталог хранит также raw-представление ACL: SQL GRANT/REVOKE может материализовать NULL (права владельца по умолчанию) как явный эквивалентный ACL. Системные каталоги не редактируются, равенство NULL и пустого ACL не предполагается. Такое изменение представления отдельно отражается rawRepresentationChanged; выдавать его за побитовое равенство каталога запрещено. MAIN ACL/данные не изменяются.

UNIT может исходно не содержать строк AuthResourceState. Допускаются только исходные false-строки и новые пустые sessions/throttle, созданные обычным входом; старые строки сохраняются. Throttle проверяются по точным ID подтверждённых успешных входов, без обнуления/восстановления/сырого удаления. Это явно разрешённое исключение для собственных операционных данных теста, не изменение политики MAIN.

Пройдены восемь офлайн-проверок порядка закрытия при ошибках и повторном восстановлении, восемь проверок фактического guard оболочки, шесть проверок блокировки координатора и первоначальные12ACL-тестов. Это не испытание физического отказа БД и не HTTP PASS. Короткая операция захвата/перехвата lock дополнительно сериализована; авария в этой операции оставляет takeover-record для ручной диагностики, сомнительный lock автоматически не удаляется.
