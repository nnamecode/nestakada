## Что изменилось

Новая миграция0003 связывает происхождение версий и квитанции с постоянным реестром идентификаторов блока и типа записи. Новой таблицы нет: учитываются те же8 корневых отношений PostgreSQL вместе с выросшими индексами.

Применённые0001/0002 не переписывались. Backfill проверяет согласованность существующих identities до обновления; обратная миграция сначала проверяет, можно ли восстановить прежние live FK. Она отказывает при уже удалённом source/base, не удаляя квитанции и не восстанавливая HTML наугад. Удалённый result сам по себе не запрещает обратную миграцию: в0001 для result не было live FK.

Повтор операции и чтение результата сначала проверяют свежую owner-сессию, generation и блок, затем квитанцию. Старые source/base/draft, файлы, нормализация и новый резерв не нужны для точного повтора. Сохраняется прежний canonical JSON fingerprint всех полей DTO; порядок ключей/JSON whitespace не создают другой запрос, изменение HTML/proof/основания создаёт конфликт. Duplicate keys, посторонние поля и несогласованный selector отклоняются.

Удалённый результат возвращает прежний ID с gone=true, без новой версии и воскрешения содержимого. Минимальная JS-ветка gone не очищает dirty и не показывает «Сохранено». Это не проверка всего интерфейса в браузере и не включение положительного Apply.

## Следующий конечный шаг

По [проверенному техническому плану](dev07-shared-quota-profile-proposal.md) подготовить immutable journal primitive и5 сценариев SJR: durable create/fsync/read, exact/conflicting replay, конкурирующее создание, partial/fsync faults и сохранность held-book после SQL rollback/завершения writer. Это ещё не написанный журнал и не готовый резерв. Следом — его сериализация/reconciliation и калибровка достаточного запаса на конечном corpus; каждый принятый успешный commit должен остаться в256МиБ/10000, warning75% сохраняется.

Новых согласований только ради отказа от нашей несогласованной универсальной allocator-теоремы не требуется: подготовка и испытания уже разрешены D-347/D-349. Индексы, metadata, orphans и временные расходы из учёта не исключаются. Unknown outcome не называется rollback. Профиль остаётся закрытым до испытаний и независимого ревью; новые зависимости/ресурсы и production требуют прежних согласований.

Открыты также положительные Draft/Apply/restore/cancel, dirty/nonce при изменении текста во время ответа, полноценная ручная очистка, native UI/Nginx, renderer/menu/public composition и остальные DEV-07 матрицы. При будущем наполнении до75% нельзя молча увеличить нынешние128МиБ tmpfs тестового контейнера: конкретную выделенную область существующего тома и её очистку надо предварительно проверить отдельно.
