Конкретная сущность алиаса/главный canonical и SEO-политика не выбираются молча: старые метаданные/канонические указания сначала фиксируются. URL новой страницы не должен отнять у старого адреса требуемый HTTP-контент. Изменение рекламных кампаний/добавление редиректа не входит в эту карту.

## 2. Карта переноса полей — предложение

| Источник | Целевое логическое поле/проверка |
|---|---|
| requested/effective URL и фактическая цепочка | Точный постоянный маршрут и документированная политика; не нормализовать автоматически регистр/слеш/кодировку/существенный query |
| Дерево/реальные навигационные связи | Родительство и согласованный порядок; URL хранится независимо от дерева; новые позиции по D-247 |
| title/description/H1 | Отдельные значения без автоматического пересоздания; отсутствие метатега не превращать в выдуманное описание |
| Основной/вводный текст | Разрешённая структурированная разметка с исходными словами/таблицами; исключения только по конкретному принятому решению; санитаризация не является рерайтом |
| Таблицы цен | Устойчивые строки/суммы/пометки «от», классы/оси/комплексы там, где они есть в источнике; не делать главную независимым вторым прайсом |
| Галерейный альбом | Название/подписи/порядок/оригиналы и общий ID для каталога, отдельного URL и модальной листалки |
| Ссылки/изображения | Карта source → новый постоянный Asset/логический путь → места использования/история; совпадение имени не даёт права перезаписи |
| Внешние видео/виджеты/счётчик | Реестр разрешённых источников и правовых условий, без безусловного копирования произвольных старых scripts/iframe |
| Контакты/общие блоки | Единый проверенный источник общих данных, отдельные текущие ссылки/снимки по TECH-02; чужие примеры не импортируются как действительные контакты |
| Дата/автор | Исходные сведения, если подтверждены, отдельно от реального времени миграционной операции и технического автора; не приписывать владельцу/сотруднику несделанное сохранение |

Если серверная очистка не может передать требуемое старое содержимое безопасно, записать конкретное расхождение и способ эквивалентного представления к ревью; не обрезать/удалять автоматически. Предложенные лимиты новых полей проверяются по реальному максимуму старого содержимого до включения, а не используются для потери длинного старого текста.

## 3. Медиа: факты и правила

На дату этой сверки `media-inventory.csv`: **641 строка**, из них 632 изображения и 9 CSS; 639 downloaded, две error. Это 630 успешно сохранённых изображений и две ошибочные ссылки, не 632 успешно скачанных файла. 214 строк имеют роль `gallery-original`; их побайтный перенос/хэши подтверждался на предыдущем этапе, заново не выдаётся за выполненный серверный импорт. Архив по-прежнему вне Git и не становится публичной медиатекой целиком.

Правила:

- gallery-original: сохранить байты/SHA-256/происхождение; не WebP-конвертировать, не убирать метаданные и не подменять AI-иллюстрацией;
- illustration-or-layout/прочие: не назначать случайный файл по имени; принять новые согласованные иллюстрации по смыслу страницы/блока, сохранив исходное соответствие и принятое разрешение;
- две error-ссылки разобрать по месту использования: отсутствие исходника — явная проблема карты, не успешная публикация пустого блока/поддельного фото;
- архив CSS/JS не переносится как доверенный код старой CMS; визуальная система создаётся утверждёнными шаблонами и безопасными зависимостями;
- публичные WebP примерно по 50–100 КБ — прогноз новых фото, а не предел для старых оригиналов или приватных исходников;
- ссылки двух HTML-копий входят в удержание медиа. Восстановление версии/замена картинки не переписывает исходный файл, очистка не удаляет общий Asset с живыми ссылками.

Для каждого из 298 файлов в [analytics-media-evidence.csv](analytics-media-evidence.csv) указаны MED-ID, путь, роль, блоки/селекторы, связанные MAP-ID, пример ZIP-entry:строка, размер/SHA и результаты проверки. Проверены наличие всех 298 файлов в ZIP и рабочей медиапапке, равенство SHA между ними; отсутствующих/несовпадающих нет. Включённые в доверенный дизайн SVG-иконки не являются разрешением загрузки произвольного SVG через будущую медиатеку.

В ZIP также лежат **16 файлов без ссылок из этих 92 HTML** — прежние варианты hero/фотополосы и исходники. Они отражены отдельными MED-ID с `source_kind=v3_unreferenced_archive_extra`, `NO_CURRENT_BLOCK_ASSIGNMENT`, нулём ссылок и проверенными байтами; наличие в архиве не делает их выбранным изображением блока или автоматически разрешённым публичным исходником. Всего в evidence **316 строк**: 298 используемых, 16 архивных дополнительных и две ошибочные старые ссылки. Ничего из архива/медиапапок этой сверкой не удалялось.

v3 — свидетельство принятых локальных макетов/файлов, **не готовый production HTML-резерв**: в ней есть заглушки и неполнота legacy-карты, отсутствуют будущие данные Django и известны расхождения прайсов. Будущий перенос сверяется по D-023 и текущим разрешениям, а не заменяется распаковкой ZIP.

## 4. Предложения проверок до приёмки

Карте нужны как минимум: исходный запрос и его конечный материал; старый ответ/цепочка; целевое открытие без подмены; сравнение значимых слов/таблиц; перечень явно разрешённых исключений; медиа/ссылки; метаданные; признак полноты рекламы. Старый base href учитывается при разрешении относительных ссылок, но не становится новым произвольным URL. Неоднозначная кодировка/параметры — отдельная проверка, не агрессивная автоматическая нормализация.

Контрольная миграция выполняется в изолированном окружении на последующих разрешённых этапах. Сначала проверка полного набора, затем разрешение владельца на реальный перенос/выпуск. Архив/старый сайт не изменяется этой процедурой. Учётные записи/пароли/сессии старой CMS, её персональные данные форм и исполняемые плагины не импортируются по одному факту наличия в архиве; их перенос не согласован.
