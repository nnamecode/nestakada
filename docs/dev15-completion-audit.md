### Конкретная совместимость ёмкости и стартового deadline

Действующие серверные ceilings позволяют50000routes+10000tombstones, то есть600страниц по100строк. Клиент имеет общий рабочий deadline30с, Nginx — общий10rps/burst10. Расчёт по текущей конфигурации:600успешных страничных запросов не помещаются примерно в310запросов за30с, ещё без manifest/final head/задержек. Это **вывод из настроек, не измеренный benchmark**. Старт при превышении deadline остаётся закрытым, но обещать успешный старт на полном таком наборе нельзя. В CLOSE-02 нужно подтвердить реально выбранную ёмкость целиком; любое изменение профиля/deadline/протокола требует предусмотренного согласования, не автоматического повышения. Полный64МиБ/600page MAX сейчас не PASS и не обязательство выжать эту ёмкость из прежних ресурсов любой ценой.
