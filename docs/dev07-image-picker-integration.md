## Точный HTTP и DTO

- Owner GET `/manage/pages/<PageUUID>/edit/media/`: закрытый query `folder?`, `q?`, `after?`, без дублей/прочих ключей. До Asset inventory — fresh session/Page/owner admission и рамка query≤существующих16KiB media query. folder — существующий logical POSIX folder, пустой означает весь каталог; фильтр descendants строго `path==folder OR startswith(folder+'/')`, не соседний prefix. q — casefold поиск label/folder/AssetUUID. after — canonical AssetUUID, строгий порядок AssetUUID, следующие50 подходящих элементов и next cursor; это размер страницы UI, не предел хранения. Общие Assets других Page доступны владельцу, нового Page-local запрета reuse нет. Только READY с однозначными MAIN и PREVIEW, не синтетические записи.
- Ответ picker ровно `{items:[{assetId,label,folder,mainFileId,previewFileId,mainUrl,previewUrl}],nextAfter:UUID|null}`. Для пагинации применяется тот же фильтр; nextAfter — последний возвращённый AssetUUID, только если есть следующий подходящий элемент. Нет raw storage key, private-source URL, имени исходного файла, receipt или клиентского MIME.
- `mainUrl`/`previewUrl` picker строит только сервер: `/manage/pages/<PageUUID>/edit/media/picker-files/<FileUUID>/`. **Новый owner-only gate с late authorization**, а не прежний `/manage/media/files/`. Старый media_library.views не меняется. Новый gate разрешает владельцу просмотреть выбранный READY Asset до появления Page usage; сам preview не создаёт refs.
- Selected-source bytes GET `/manage/pages/<PageUUID>/edit/media/files/<FileUUID>/` с действующим exact D07 selector: current — пустой query; owner-draft — source/draftId/draftRevision; restore-stage — source/stageId; explicit rebase сохраняет существующие rebase/targetCurrentId. Дубли и лишние keys запрещены. Ни HTML, ни proof/CSRF/секрет не попадают в URL. Оба byte endpoints имеют только GET и не редиректят на ключ или другой сервис.
- Существующий PageInput получает только уже утверждённые owner keys main_image/preview_image. Значение null либо ровно `{asset_id,alt,alignment,width_px,height_px}`: canonical UUID, plain NFC alt≤300codepoints без однострочных control characters, alignment left/center/right, размеры null либо positive int, не bool/float. Никаких src/path/MIME/fileId/embedded_images/layout в DTO. Null соответствует принятой nullable schema; clear-format/reset/embedded insert не добавляется. Employee любые image keys, даже прежние/null, получает whole403.
- Check response остаётся прежним7keys для current; save — native6keys; draft — существующие8keys. Новый media descriptor transport не добавляется в PageInput. В подписанном check proof допускается закрытое optional mediaEvidence поле только при новом image-bearing check; старые consumed receipts не мигрируются.

Недоступную производную нельзя подменять original/private-source: null URL означает отсутствие доступного preview, не успешную проверку байтов.

## Actual selected-source membership

Для contextual byte gate внутри EditorSlot вызывается настоящий inspect_context/selected_source→candidate_for_stage, а не догадка по stage.source_revision_id. File.asset_id обязан входить именно в effective payload main_image/preview_image; embedded-only AssetUsage не даёт этот доступ. Дополнительно проверяется реальный ledger с external-image slot и соответствующим consumer:

- current — current_page/PageUUID и слот effective reference;
- owner draft — exact owner/Page/draftID/revision/base/hash, draft consumerID и слот;
- restore-stage — held stage actual actor/generation/Page/base/current grants и настоящий восстановленный candidate. Owner image может происходить из исторического source, employee candidate сохраняет current protected imagefields. Соответствующий source/base revision или current consumer/slot выбирается по actual candidate и его существующим refs, а не по одному историческому UUID. Ordinary/Stable kind определяется действительной protection записью. Исторический byte endpoint DEV05 остаётся отдельным правилом D046, не обходом membership этого endpoint.

Проверки выполняются до открытия файла и повторяются после открытия. Source stale/consumed/missing не превращается в current fallback при новом чтении. Picker byte gate отдельно owner-only и не требует заранее придуманного Page usage. MAIN/PREVIEW only; PRIVATE_SOURCE и LEGACY_PUBLIC не выдаются обоими новыми gates. Legacy-only Asset не перекодируется и не появляется как новая WebP selection. Неизменная старая ссылка может сохраняться существующим typed source/engine путём без объявления отсутствующего preview пригодным; новое присвоение требует допустимых производных.

## Сессия, Slot и открытый FD

Перед heavy source/Asset/file scan — metadata-only fresh session/Page/owner admission; Slot приобретается до полного source/файлового хеширования. Внутри Slot: actual selected context или picker owner context, READY/file descriptor, затем `MediaStorage.open_verified(key,{sha256,byte_size})` и WebP header на том же открытом FD. Хеширование/FS — вне domain SQL locks.

После FS выполняются fresh actual AuthSession/generation/actor и текущие Page grants/owner checks с content→auth порядком, повтор actual source/slot/file/READY/descriptor evidence. При любом отказе FD закрывается. Slot удерживается до этих проверок и создания FileResponse; **отпускается до streaming**. FileResponse читает тот же verified FD без reopen. Заголовки: private/no-store, nosniff, image/webp, inline; никаких304/redirect/auth shortcuts. Применяется модель immutable app-managed files и явной cleanup; защита от произвольного внешнего bit flip после проверки/при streaming не обещается. Long SQL locks на время отдачи не удерживаются.

## Check/Save и неизменные квитанции

До выдачи CheckReceipt проверяются **все effective final main/preview refs**, retained и новые, после объединения actual selected server payload с проверенными изменениями. Parent не принимает произвольный Snapshot от клиента. Child выполняет одну strict decode/normalization; новый ImageRef validator не активирует embedded map.

Actual READY, однозначные производные, реальные descriptors и физические SHA/bytes проверяются в EditorSlot, вне content/auth locks. Для полного evidence используется существующий preflight, который проверяет также зарегистрированный приватный источник; приватные данные не возвращаются. Затем late fresh session/grants/source stamp и DB file/READY evidence повторяются до подписи. Optional mediaEvidence в proof связывает проверенные asset/file descriptors/actual SHA с normalized refs; не клиентский hash.

Save сначала делает actual session/generation/current grants и exact permanent receipt replay **до** source/media availability/FS. Поэтому настоящий прежний успех доступен после consume/cleanup и не создаёт новую версию. Default-current fingerprint остаётся прежним `fingerprint(value)`, другие source modes — принятой wrapped схемой D07. При новом write proof/source/effective refs повторно проверяются, E.preflight читает настоящие файлы вне locks, E.check_evidence повторяет READY/descriptors под locks, затем existing current/version/draft/stage/AssetUsage/prune/receipt/audit фиксируются атомарно. Final descriptor recheck не объявляется повторным физическим SHA-чтением.

Missing/corrupt/inaccessible file, ObjectDoesNotExist/OSError, missing/ambiguous derivatives или changed source дают фиксированный контролируемый media unavailable/conflict, не500/partial current. Никакого скрытого physical unlink при замене или rollback; Stable/старые версии/другие consumers сохраняют refs. Existing upload/worker1MB и реальные PNG/JPEG/WebP используются QA; READY не создаётся тестом вручную вместо upload.

## Что готово

Владелец выбирает настоящее готовое фото из медиатеки для главного изображения или превью, видит прежнее/новое и подтверждает «Заменить здесь» либо «Добавить здесь». Изменение сначала остаётся в RAM вкладки. Alt, выравнивание и nullable размеры входят в проверяемый ImageRef; отдельные Check/Save и принятая проверка перед Save сохраняют прежний workflow. «Убрать со страницы» снимает только текущую ссылку после Save, не удаляет файл или историю. Пагинация выдаёт50 элементов; это не квота хранения. Сотрудник видит разрешённые выбранные производные и сохраняет разрешённый текст; image keys в его POST запрещены даже при null/прежнем значении.

Только server-produced URLs открывают MAIN/PREVIEW WebP. По каждому запросу проверяются actual selected source и ledger, actor/Page/grants/generation и точный AuthSession key. После физического SHA/bytes чтения повторяются права, source stamp, READY и descriptors; FileResponse получает тот же проверенный FD, Slot освобождается до streaming. Приватный исходник, guessed несвязанный FileUUID и прямой storage key не становятся download API. Hash/FS IO не выполняется под domain SQL locks. Допущение app-owned immutable files и протокол очистки не выдаются за атомарный snapshot при произвольной внешней перезаписи файла.
