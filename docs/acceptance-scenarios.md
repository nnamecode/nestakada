## 1. Что подготовлено

[acceptance-cases.csv](acceptance-cases.csv) содержит 140 постоянных AT-ID, по одному составному сценарию на каждый из 140 AC; покрыты 63 REQ. У каждого есть конкретные предусловия, действия, нормативный ожидаемый исход, метод, доказательство и ограничения запуска. Это развёртка [матрицы плана](implementation-traceability.csv), а не новая редакция требований.

Ожидаемый исход в CSV воспроизводит исходный AC; его полный контракт/матрицы/числа читаются в нормативном документе. Дополнительные действия делают сценарий воспроизводимым, но не сокращают исходный oracle. Если один AT содержит набор вариантов, каждый вариант исполняется независимо с восстановлением fixture и собственным результатом. «Один AT» не означает один HTTP-запрос/одну проверку.

Доказательство отсутствия SQL требует наблюдаемого счётчика/трассы на тестовом SQL-пути, а не отсутствия одной строки пользовательского лога.

## 3. Обязательные матрицы вариантов

- Поля: для **каждого** нормируемого поля профильного документа проверить empty/пробелы/минимум и границы N−1/N/N+1, тип/Unicode/NUL/control, неожиданный/повторённый scalar key; явные правила optional отдельно. 255 для title/H1, 1000 для description и прочие числа берутся из принятого профиля; прежний исходный контент не обрезается под новый лимит.
- Роли: visitor/other/assigned/owner, direct request и UI; price grant off/on; revoke после открытия; повтор запроса после logout/reset/expiry. Успех одного положительного действия не закрывает отрицательные варианты.
- Версии: ordinary/manual/Stable/current/used base; 9/10/11+ ordinary плюс Stable; server time отличается от пользовательской даты; save/restore/delete/cleanup конфликтуют в заданной последовательности.
- Заявки: две формы, JS on/off; отдельные status-table cells; same intent/same payload, same intent/changed payload, новый intent/same phone, expired intent; смена согласия/CSRF/cookie/time bucket; callback/ответ потерян до/после фиксации. Каждая ветвь имеет собственную проверку request/consent/goal count.
- Условные ответы: no condition/ETag/IMS/оба, GET/HEAD, изменение Page/Header/Footer/nav/price/context; private/no-store и shared-cache отсутствие для персонального/закрытого. Пустой hidden200 не содержит закрытый DOM/canary даже при старом validator.
- Маршруты аварии: каждая строка HTTP-матрицы TECH-03, включая new without snapshot/deleted/hidden/admin/POST и 301 после A→B→C. Кодированные/query-варианты следуют принятому нормализатору, не выдуманному новому маршруту.
- Fault-boundaries: before/after external revoke, commit, finalize, prepare/admission; delayed worker и уже admitted slow response отдельно. Исход операции определяется receipt/ID и фактическими данными, а не одним HTTP-timeout.
- Логи: до/после L, ротация между подтверждением и удалением, удаление своей audit-категории, DB success/file pending, quota с временным файлом; read cursor, ordinary cycle и critical/recovery проверяются независимо.
- Производительность: PERF-NORMAL, PERF-SCAN, PERF-MIXED и PERF-FAILURE по analytics-runtime-detail.md; пики/пороги среды согласуются до запуска. Обычная нагрузка и сканерские пики не смешиваются в среднее миллион/месяц. Ресурсные серии и полезные ответы обязательны.
- Браузеры: семейство/основная версия/ОС/реальное устройство, дата/сценарий/артефакт/ограничение. Недоступная комбинация остаётся непроверенной.

## 4. Независимые проверки, требующие особой среды

AT-201–212, AT-301–305 и AT-406–410 требуют согласованной конкретной схемы ARC-10. До неё текстовый порядок и oracle определены, но нельзя объявить реализованным fault-adapter неизвестного провайдера. Для ночных наборов/возврата обязательны независимые подтверждения, а статический200 не является проверкой SQL.

AT-043/044 и связанные fault-сценарии восстанавливают только **отдельное временное окружение**. Измеряется техническая длительность; срока реакции владельца нет. Сначала проверяются состав/ключи/совместимость/внешние запреты, затем открывается доступ. Отсутствие safety-копии проходит ровно предусмотренный усиленный путь подтверждения, не молча игнорируется.

AT-501–509 используют содержательное сравнение source/target, SHA/альбомы и рекламную выгрузку. Неполученная Q041 не помечается успехом. Два ошибочных исходных media URL имеют явный согласованный исход, 16 архивных extras не назначаются на страницы автоматически.

AT-056/311 требуют реальных browser combinations до приёмки. AT-058/057/312/соответствующие SEO/внешние ресурсы проверяются на заглушках до LEGAL и затем отдельно на фактической разрешённой настройке до запуска.

## 5. Протокол будущего запуска

Для каждой пары AT-ID/variant сохраняются: run ID, дата/среда/версии, fixture IDs и хэши выбранных исходников, шаги, ожидаемый/фактический результат, безопасные артефакты, статус, причина ограничения и связанный AC. Одна строка CSV не содержит фиктивного фактического результата.

Статусы запуска: «пройдено», «не пройдено», «не проверено» с причиной; отсутствие приложения до реализации — ожидаемая причина непрохождения/недоступности, а не основание писать always-pass/skip и считать TEST-01 выполненным. Любой skip сохраняет незакрытый AC. Не применять blanket xfail ради зелёного отчёта.

Тестовый подвыбор ENV-05 согласован D-303: разрешены локальная подготовка инструмента и реализация исполняемых сценариев.
