# Этап 9 — итоговый локальный регрессионный прогон

Дата: 2026-11-15. Статус: план готов; выполнение ожидает доступный Docker foundation.

## Основание

Последний полный guard `401/401` относится к DEV-25. После него в tracked product/test surface добавлены DEV-09M и TEST-10 fixture, поэтому прежний результат остаётся историческим доказательством DEV-25, но не считается итоговым прогоном всей текущей ветки.

Текущий `work/foundation/test/manifest.json` имеет `active=false`. Известный отказ доступа к Docker named pipe уже классифицирован как ограничение host environment, а не ошибка продукта; без изменившегося условия его не повторять.

## Точная граница

Когда Docker снова доступен, выполнить один свежий immutable foundation lifecycle и только следующие именованные команды:

1. `scripts/test-editor.ps1 -Suite all` — общий Django-набор редактора, страниц, shared content, media и foundation.
2. `scripts/test-editor.ps1 -Suite dev13` — заявки и уведомления, отсутствующие в `all`.
3. `scripts/test-editor.ps1 -Suite dev25` — ручной HTML-резерв, отсутствующий в `all`.
4. `scripts/test-editor.ps1 -Suite check` — Django system check.
5. `scripts/test-editor.ps1 -Suite migrations` — отсутствие незаписанных миграций.

`all` уже собирает весь `content` и `page_editor`, поэтому отдельный повтор DEV-09M или TEST-10 fixture не нужен. Не запускать прямой `manage.py test`, wildcard, Playwright или произвольный широкий Docker test command.

## Правила остановки

- Первый отказ сохранить с точной командой и причиной; повтор разрешён только после нового свидетельства или изменённого условия.
- Вторая эквивалентная ошибка останавливает этап; третьей попытки нет.
- Ошибка запуска из-за Docker/host не считается дефектом продукта и не заменяет тестовый результат.
- При product failure исправлять только доказанную причину, затем повторять затронутый именованный suite и не более одного итогового `all`.

## Что этот этап не делает

- не запускает TEST-10 real-browser/manual matrix;
- не подключает VPS, мониторинг, backup storage, аналитику или реальные заявки;
- не выполняет persistent production import/publication;
- не возобновляет DEV-26/27 и не добавляет новые функции.

Успех всех пяти команд закрывает локальную часть этапа 9 и открывает итоговое независимое ревью текущей ветки. Production-like TEST-09, реальные устройства TEST-10 и этап 11 остаются отдельными воротами.
