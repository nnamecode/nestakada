## Минимальная техническая интеграция

- Основной estakada.urls включает page_editor.http_urls и существующий закрытый editor asset handler, не URL policy module page_editor.urls. Template discovery через page_editor в INSTALLED_APPS, EditorAdmissionMiddleware перед genuine CSRF; нормальный local_http, не QA settings/URLConf.
- Foundation D-315 lock/094 base и worker provenance не подменяются. Отдельный проверяемый editor-app artifact фиксирует уже собранный782 runtime, точный094 parent, D-330 package pins/recipe/installed-tree hashes. App/migrate/units используют782: импорт нового основного URLConf реально достигает html5lib, поэтому Django migration/system checks также требуют принятые библиотеки. Base prepare/init/state-init остаются094, worker отдельный; роли/учётные данные migrator и runtime прежние. Непроверенная подготовительная receipt не называется одобренной автоматически.
- Nginx64MiB/streaming/proxy_read_timeout150s — только для3 точных canonicalUUID Page POST check/save/draft. Shared outer11MiB и application reader4MiB, text reader5MiB без price, small actions16KiB сохраняют прежнюю область; большие лимиты не распространяются на весь /manage.
- Тот же local Django runserver --noreload без --nothreading: HTTP concurrency позволяет второму запросу получить согласованный nonblocking BUSY503 до body. Heavy slot остаётся один, child384MiB/CPU10s/wall20s/body120s и все container caps/порты прежние. Production WSGI этим не выбирается. Настройка объяснена владельцу до изменения; отдельное новое согласование для этой интеграции принятого профиля не требуется по независимому precode-ревью.
- Никаких test observers/fault endpoints/reset APIs/QA middleware в normal product configuration. Тестовый seed/observer запускается отдельно CLI и только в test DB, с точными normal settings/source/runtime guards и проверенными собственными IDs.
