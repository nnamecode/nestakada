# DEV-10 — ограниченное предложение по галерее

Статус: предложение D-804 от 2026-11-10; продуктовый код не начат. Основание: D-024, D-218, D-245, D-246, REQ-008/009, AC-008, AC-MIG-003/009 и AC-SEO-004. До ответов владельца `DEV10-Q001` и `DEV10-Q002` это не утверждённый план реализации.

## 1. Цель и доказанные данные

- Один каталог `/gallery-of-works/` показывает 17 альбомов в утверждённом порядке.
- `/gallery-of-works/?page=2` отвечает HTTP 200 без редиректа и показывает точный прежний поднабор из 7 альбомов в прежнем порядке.
- Все 17 прежних адресов альбомов остаются отдельными HTTP 200 страницами.
- Используются одни общие данные альбомов и ровно 214 исходных фотографий. Проверенный реестр содержит 214 уникальных `gallery-original`; отсутствующих файлов, несовпадений размера и SHA-256 нет. Байты фотографий не изменяются и в Git не отправляются.
- Наибольший альбом содержит 32 фотографии. Каталог содержит 17 обложек; даже выбранный каталогом альбом вместе с обложками даёт не более 49 изображений, что укладывается в существующий предел 64 без его увеличения.

## 2. Минимальная реализация без новой тяжёлой архитектуры

Переиспользуются существующие `Page`, версии, права, `Asset`/файлы/связи использования, публичный renderer и безопасная схема содержимого. Новые модели, миграции БД, API, универсальный импортёр, фоновая очередь, планировщик, кэш, отдельное хранилище и новый сервис галереи не нужны.

Каждый из 17 альбомов хранит только собственное название, исходное содержимое и ссылки на свои фотографии. Корень и `page=2` строят карточки из этих же дочерних страниц, поэтому редактируемые копии альбомов и фотографий не создаются.

Карточка каталога является обычной доступной ссылкой на точный самостоятельный URL альбома. Для выполнения D-218 небольшой JavaScript перехватывает только активацию этой известной карточки и открывает тот же каталог с одним строго проверенным параметром выбранного альбома; сервер загружает только этот известный альбом, после чего JavaScript открывает уже отрисованное модальное окно и управляет стрелками, миниатюрами, клавиатурой и закрытием. Без JavaScript обычная ссылка открывает самостоятельную страницу альбома. Никаких запросов к API из браузера и загрузки всех 214 полноразмерных фотографий в один документ нет.

Допустимы только заранее известные значения альбома и две точные формы каталога: корень и `page=2`. Повторяющиеся, лишние или неизвестные query-параметры не выбирают файл, шаблон либо SQL-фрагмент и закрываются предсказуемым 404. Доступ к БД остаётся через ORM, вывод — с autoescape, пользовательская строка не становится путём к файлу, HTML, Django-шаблоном или JavaScript.

## 3. Предлагаемый дизайн отдельного альбома

Самостоятельная страница альбома переиспользует утверждённый визуальный язык D-218, но не повторяет сетку из 17 карточек:

1. Общие Header/Footer и хлебные крошки `Главная → Галерея работ → название альбома`.
2. Один H1 с точным названием альбома и сохранённый исходный текст/подписи, если они есть в проверенном источнике.
3. Крупная текущая фотография без обрезки и изменения исходного файла; стрелки назад/вперёд, счётчик `01 / NN`, горизонтальная полоса миниатюр и видимый фокус.
4. Клавиши Left/Right переключают фотографию, Escape закрывает модальный просмотр; нажатие на крупную фотографию/миниатюру открывает тот же viewer. На телефоне элементы остаются доступны без горизонтального переполнения страницы.
5. Обычная ссылка `Все работы` возвращает на `/gallery-of-works/`. Отдельных ответственных, статусов, лайков, комментариев и иных функций у альбома нет.

Это точечное предложение закрывает недостающий gate D-246/REQ-009. Оно становится утверждённым только после ответа владельца на `DEV10-Q001`.

## 4. Неизвестная цепочка `?page=1`

Архив доказывает, что запрос `/gallery-of-works/?page=1` в итоге приходил на `/gallery-of-works/`, но не сохранил исходный код промежуточного ответа. Поэтому нельзя честно объявить прежним ни 301, ни 302.

Рекомендуемый безопасный и обратимый вариант: временный HTTP 302 на `/gallery-of-works/`, с canonical корня. Это сохраняет наблюдаемое конечное поведение, не выдаёт неподтверждённый постоянный 301 за исторический факт и не влияет на обязательный прямой HTTP 200 для `?page=2`. Выбор требует ответа владельца `DEV10-Q002`; до него цепочка остаётся открытым acceptance-gate.

## 5. Границы следующего плана

После двух ответов владельца отдельно готовятся: точные e2e-сценарии с постоянными `GAL-xxx`, минимальный технический план, независимое ревью плана и только затем отдельное разрешение реализации. В scope войдут корень, `page=2`, 17 прямых страниц, единая выборка данных, viewer, 214 SHA-256, canonical/query-границы и отказобезопасность.

Не входят: публикация на живой сайт, persistent import/apply, изменение исходных фотографий, загрузка оригиналов в Git, ночная автоматика, API, универсальный конструктор галерей и реализация HTML-резерва. Будущий ручной HTML-резерв должен включить корень, `page=2` и 17 самостоятельных страниц; модальное query-состояние не является отдельной обязательной резервной страницей.

## 6. Вопросы владельцу

- `DEV10-Q001`: утвердить предложенный дизайн отдельного альбома и минимальную схему каталога: общие данные, прямые страницы альбомов, server-rendered выбранный альбом и небольшой JS viewer без API/новой подсистемы?
- `DEV10-Q002`: из-за отсутствия доказанного исходного статуса утвердить для `/gallery-of-works/?page=1` обратимый HTTP 302 на `/gallery-of-works/`, а `?page=2` оставить точным HTTP 200 без редиректа?
