## R026-01: durable request, единственный clock и закрытие gate

Существующие шесть actual gates остаются ровно START, INIT, PAYLOAD-C, C, PAYLOAD-T, T. Каждый привязан к новому runId, kind, exact reviewed package/source/proposal/prepared-plan hashes и exact VALUE hash текущих фактов. Никакой общий APPROVED на все фазы, наследование мнения или копирование старой admission не разрешаются.

Runner — единственный источник принятия и закрытия gate. Он фиксирует monotonic t0 непосредственно перед созданием и сохранением request; единый deadline=t0+120000мс. Сериализация, подпись, durable publication, доставка уведомления, InspectReview, работа независимого агента, публикация source, чтение/HMAC/валидация и запись принятия входят в то же окно. Не начинать clock заново после публикации/доставки/обнаружения файла, не переносить deadline после review-gap. Родительский INIT/phase/TTL deadline по-прежнему может остановить раньше; окно ревью не продлевает ни одного родителя.

В append-only authenticated request добавить closed metadata: schemaVersion, requestId, runId, kind, requestValueSha256, package/source/proposal/prepared-plan pins, expectedReviewer, reviewWindowMs=120000, openedUtc и expiresUtc, gateNonce и ordinal. Фактическое значение reviewWindowMs не брать из CLI/env; запрос со значением вне120000 отвергается. Время UTC служит durable внешним ориентиром, но authority — локальная monotonic переменная runner. Не сравнивать monotonic значения разных процессов и не принимать mtime за начало окна.

До выдачи AWAIT_REVIEW request должен быть полностью сохранён штатным write-once способом; его фактические RAW/VALUE hashes входят в уведомление. Ошибка сохранения/неполное чтение закрывает gate без dependent action. У каждого gate есть отдельная durable append-only запись закрытия с request hash/nonce, kind, reason и elapsedMs, созданная только runner. CANCELLED/REJECTED/EXPIRED/terminal result имеют приоритет над любым opinion/accepted proof. Нельзя открыть такой gate повторно, сменить ordinal/nonce ради нового окна, удалить CLOSED или пересоздать request.

При timeout, cancellation, CHANGES_REQUIRED, source/schema/identity/hash/HMAC mismatch, drift или storage failure runner немедленно отказывает в dependent work. Он пытается сохранить CLOSED и общий FAIL/UNPROVEN штатным failure path; если storage не доказан, отсутствие CLOSED не означает OPEN. Его in-memory closed state и terminal failure остаются запретом. Сохраняются bounded exact-owned safety cleanup, original-after и terminal inventory; empty terminal не переписывает FAIL.

## R026-02: actual opinion и принятие runner — разные события

Независимый агент принимает решение только после InspectReview текущих фактов. Его source JSON остаётся closed, с точным фактическим identity, requestId/nonce/kind и всеми hash bindings; APPROVED допустим только при findings[]. Не создавать opinion автоматически по PASS checker, не подписывать за агента и не подставлять имя другого агента. Precompiled checker и независимый code review проверяют алгоритм, а не заранее одобряют будущие факты.

Предлагаемый actual reviewer pin — /root/q025_reviewer, пока именно этот агент назначен координатором и имеет эту фактическую identity. Если назначен иной actual reviewer, его точный pin и positive/negative fixtures должны быть закреплены и независимо проверены до нового package freeze; нельзя выпускать мнение от прежнего имени. Пустой/self/old/unknown identity, неверный request/value/package/run/kind и extra fields отвергаются. Мнение не превращается в admission от наличия файла или корректной подписи publisher.

Publisher проверяет отсутствие terminal result/CLOSED, current request bindings, допустимые status/identity/source, expiry и отсутствие уже опубликованного мнения до любых новых review artifacts; после чтения/валидации source повторяет свежие state/expiry checks непосредственно перед write-once publication. Если result/CLOSED/expiry уже наблюдаются, он отказывает без записи runtime source/opinion. Неизвестное состояние/ошибка чтения/clock drift означает отказ. Часы publisher — только консервативная предварительная проверка; его локальное время не заменяет deadline runner.

**У этого минимального контракта нет общей атомарной транзакции publisher↔runner.** Между проверкой и записью runner может закрыть gate. Нельзя обещать, что предварительная проверка исключает эту TOCTOU-гонку. Поэтому опубликованный файл имеет только статус OPINION, а не accepted admission. Если закрытие произошло в гонке, runner его отвергает и сохраняет как позднюю/непринятую историю; publisher post-check сообщает CLOSED/EXPIRED/UNPROVEN и не заявляет принятие. Никакого удаления истории или повторной публикации для обхода гонки. Если требуется атомарный запрет самого создания late file, это иной lock/IPC/CAS механизм и новое конкретное предложение до реализации; здесь он не подразумевается.

Runner после обнаружения opinion выполняет проверки в строгом порядке: актуальный in-memory gate OPEN → request/opinion/source RAW hashes → HMAC штатным закрытым кодом → strict source JSON/actual reviewer → exact request/value/run/package/source/kind/nonce/status bindings → актуальное отсутствие terminal/CLOSED/drift/cancel → **финальный monotonic now<deadline**. Проверка времени обязательна после ожидания и всего чтения/HMAC/валидации, а не только внутри polling. Ровно на deadline — отказ.

Только при всех успешных проверках runner формирует отдельный authenticated accepted proof: request/opinion/source hashes, run/kind/nonce, reviewer, acceptedElapsedMs, window120000, remainingMs и выполненные assertion IDs. Это историческое доказательство конкретного своевременного решения runner, а не переносимый permit. До его успешного сохранения dependent action закрыт. После сохранения/проверки результата записи runner ещё раз проверяет monotonic deadline/родительский deadline и OPEN/no-result/no-CLOSED непосредственно перед существующим dependent dispatch. Если запись/проверка заняла остаток окна, действия нет: CLOSED/FAIL имеет приоритет, даже если proof исторического решения уже существует. Такой proof не считать успешным completion gate/разрешением следующего действия. После рестарта прежний proof не возобновляет Run. Final guard не меняет120000, TTL или длительности фаз.

## Единственный выбранный маршрут доставки actual decision

После будущего утверждения и code review используется прямой маршрут **independent reviewer → собственный wx source output → bounded PublishReview → runner**. Координатор заранее подготавливает точные reviewed команды/пути и dispatch, затем наблюдает ход/ошибки; он не копирует JSON вручную и не повторяет анализ frozen baseline в timed window. Фоновый service, новый poller или subscription не добавляются; существующее ожидание runner остаётся в том же120с и закрывается его final clock guard.

После InspectReview независимый агент сам принимает actual verdict и ровно один раз записывает только свой complete source JSON в заранее закреплённый public ignored outbox нового root: real-host/run/reviewer-outbox/<requestId>-<kind>.json. Это candidate OPINION, не admission, не подпись от агента и не runtime accepted record. RequestId и kind берутся только из authenticated current request; closed basename/allowlist/canonical path/no-symlink/regular-file/size≤65536 обязательны. Произвольный output path, rewrite существующего source, output другого gate/root и чтение иных private файлов запрещены. Если агент не может завершить собственный source вовремя, timeout/NOT_RUN не обходится передачей подписи координатору.

Затем тот же фактический агент вызывает заранее reviewed bounded PublishReview(kind, requestId). Transport читает только этот fixed source file и конкретные current request/state/plan inputs, сверяет actual identity и все bindings, штатно проверяет HMAC/expiry/CLOSED/result и ограничения source, выполняет свежие pre/post checks из R026-02. Он не вызывает Docker/SQL/native mutation/Run/Prepare, не меняет настройки и не имеет произвольной команды/параметра пути. Host key остаётся только внутри прежнего закрытого штатного signer; инструмент не выдаёт ключ агенту. Подпись publisher удостоверяет transport record, а не заменяет independent decision.

Предварительные проверки publisher выполняются до его собственных archive/publication artifacts; уже созданный агентом outbox candidate сохраняется как мнение, даже если transport сразу отвергнет истёкший gate. Указанная TOCTOU-гонка остаётся явно неатомарной. Успешный ответ transport — **OPINION_RECORDED**, request/source/publication hashes и elapsed; это никогда не ADMISSION/ACCEPTED/PASS PG. Только runner может выдать свой accepted proof и разрешить dependent action после final monotonic checks. CLOSED/result/expiry/unknown/error возвращают REJECTED/UNPROVEN без новых publisher artifacts; сохранённый candidate не переиспользуется.

В80с rehearsal каждого gate включаются собственная запись source агентом, вызов этого transport, все очереди/инструменты и runner/rehearsal recorder acknowledgement. Никакая задержка координатора/доставки не вычитается. Rehearsal использует отдельный NOAUTHORITY transport/schema с теми же bounded path/validation/clock rules, без реального signer/keys и без runtime publisher endpoint; precompiled код не создаёт actual verdict автоматически.

## R026-04: offline и read-only rehearsal до native

После ответа Q026: согласованные AC до кода → новая COW/минимальная реализация → syntax/static → target AC и все existing offline без skip → независимое code review. Затем один **NOAUTHORITY read-only rehearsal** новой процедуры до Prepare/native dispatch, с независимым результатом/review. Он не трогает current Q025 package, не создаёт Docker resources и не запускает SQL.

Rehearsal использует закреплённый preserved START snapshot как исторический вход; его request RAW/VALUE pins различаются как в таблице. Только назначенное стандартное hash/metadata-read и заранее одобренная nonsecret sanitized projection; без ручного чтения keys/credentials/Env/raw logs. Для INIT/PAYLOAD-C/C/PAYLOAD-T/T — независимые synthetic typed fixtures с required fields/negative cases, не выдаваемые за реальные PG facts. Каждый artifact, opinion и summary имеет отдельный rehearsal schema и **authority=NOAUTHORITY**, sourceKind=HISTORICAL или SYNTHETIC и hypothetical decision WOULD_APPROVE/WOULD_REJECT. Не использовать actual admission statuses/подписи/keys, live run namespace, publisher runtime endpoint или истёкший Q025 APPROVED; runtime parser отвергает rehearsal schema.

Для всего rehearsal назначается **один конечный recorder process** с одним непрерывным monotonic clock. Его процесс/clock identity фиксируется в результате. До первой записи первого NOAUTHORITY request он задаёт общий absolute deadline=recorderStart+490000мс: максимум6×80000мс на gates и10000мс на завершающий report. Этот общий deadline действует на все ожидания и финальную проверку после записи/read-back report; за его пределами PASS не доказан. Нельзя перезапускать recorder, переносить начало, заменять clock owner или суммировать elapsed из разных процессов. Подготовка frozen baseline до recorderStart учитывается отдельно и не выдаётся за measured transport.

Для каждого из6 gates тот же recorder снимает свой t0 **до записи** соответствующего NOAUTHORITY request. Он же тем же monotonic clock снимает tAck только после наблюдения собственного complete output, read-back/валидации и acknowledgement. End-to-end elapsed=tAck−t0 включает запись request, bounded InspectReview, доставку независимому агенту, его фактическое рассмотрение historical/synthetic фактов и hypothetical decision, запись source, транспорт и read-back. Threshold **≤80000мс для каждого gate отдельно**; никаких средних/p95 вместо худшего gate. Request/source/output timestamps других процессов и mtime служат только наблюдениями, никогда не вычисляют authoritative elapsed. Все паузы/очереди/инструменты после t0 остаются в метрике.

Это конечный offline recorder, ожидающий только свои allowlisted NOAUTHORITY outputs этих6 gates и заканчивающийся не позже общего bound. Он не daemon/service, не подписывается на события и не опрашивает Docker/SQL; runtime poller/subscription не добавляется. Потеря процесса, его clock identity/непрерывности или proof конечного acknowledgement → UNPROVEN и native NOT_RUN. Уже failed gate и весь failed rehearsal не повторять; новый recorder не продолжает прежнюю попытку.

Unknown timing, clock change, missing acknowledgement, actual gate count≠6, truncation, role/schema mismatch, любой gate>80000мс, весь recorder/report>490000мс или неверный verdict → qualification FAIL/UNPROVEN и **native NOT_RUN**. Не увеличивать пороги/120с/бюджет и не переносить старт ради PASS; сначала остановка и конкретный разбор/новое решение. Наблюдаемые этапы отмечаются, но без доказательств не делается вывод о model/tool/transport cause. Это одна qualification процедуры, не обещание времени будущей модели. Rehearsal не утверждает actual START/INIT/C/T факты и не доказывает реальную HMAC/SQL/PG фазу.

До native дополнительно обязательны approved offline/rehearsal result, независимое code review, один новый Prepare, prepared-result review и отдельный dispatch review. Пройденный checker/rehearsal не заменяет шесть actual decisions внутри будущего Run. Если reviewers/transport не готовы либо proof freshness/headroom сомнительны — NOT_RUN, без запуска «попробовать успеть».

## R026-05: один nonnative transport-readiness check после Prepare

После одного approved Prepare и prepared-result review, **до dispatch actual Run**, обязателен отдельный ровно один bounded nonnative check нового transport. Он не actual gate и не rehearsal с реальными facts. Предлагаемый hard cap **10000мс на весь check**; никаких retries/renewal/повышения cap. Один конечный recorder parent начинает свой monotonic clock до записи readiness-attempt и запуска холодной reviewed команды, включает child command startup/import, все ACL/private I/O/HMAC проверки, сохранение и read-back результата, и тем же clock подтверждает завершение. Clock/recorder loss, unknown cost или >10000мс → NOT_RUN. Mtime/child timestamps не заменяют этот elapsed; parent restart не продолжает attempt.

Используется один заранее reviewed closed command/action и те же **shared reviewed auth/HMAC, ACL и private I/O primitives, что у PublishReview**, а не отдельный toy checker. Fixed NOAUTHORITY challenge/schema привязаны к prepared package/run identity только как контекст проверки; scope BOUND29-TRANSPORT-READINESS-NOAUTHORITY и authority=NOAUTHORITY запрещены runtime request/opinion/admission parsers. Challenge не содержит live gate facts/requestId/nonce/status APPROVED и не вызывает PublishReview runtime endpoint, InspectReview actual gate, Run/Prepare/Docker/SQL/network/native mutation. Не создавать actual request/opinion/admission/Run attempt; подпись NOAUTHORITY challenge не может использоваться как actual decision или replay.

Shared code внутри фиксированной операции проверяет prepared bindings и ACL/regular-file/path policy, штатно получает реальный host key и проверяет private-input hashes только в пределах прежнего reviewed кода. Ключи/credentials/Env/raw private I/O вручную не читаются, не выводятся и не передаются агенту. Через те же closed write-once/read-back/auth primitives проверяются два фиксированных typed NOAUTHORITY challenge cases: малый≤1024байт и максимальный payload65536байт. Оба включают полный bounded HMAC input/sign/verify/read-back cost; max input не заменяется маленькой заглушкой. Envelope size также ограничен до69632байт. Дополнительно обязательны bounded negative auth/schema rejection assertions, без обращения к live facts. Не измеренный верхний input/auth case → cost UNKNOWN → NOT_RUN.

Единственный attempt-marker сохраняется write-once в новом public real-host/run/readiness/transport-attempt.json (≤1024байт); результат NOAUTHORITY — real-host/run/readiness/transport-result.json (≤8192байт). Два challenge/read-back artifacts используют только новые fixed basenames transport-readiness-small.json и transport-readiness-max.json в private root этой же новой Prepare, не source/opinion paths actual gates; все output paths заранее allowlisted/canonical/no-symlink. Результат содержит attempt/package bindings, assertion IDs, sizes/hashes, recorder identity, authoritative elapsed/clock proof и PASS/FAIL/UNPROVEN, без raw/key/Env. Все public/private readiness artifacts вместе≤131072байт и входят в прежний new artifacts≤32MiB/полный retained budget; Prepare только подготавливает эти закрытые пути, не создаёт новую admission. В наличии attempt без доказанного своевременного результата — NOT_RUN, а не разрешение повторить check.

Эта отдельная readiness attempt не расходует и не создаёт Run attempt: её отрицательный результат оставляет единственный future Run **NOT_RUN**, сохраняя историю и уже использованный Prepare. Не выполнять новый Prepare/check/Run для обхода отказа в этом разрешении. Только после PASS≤10с и независимого readiness-result/dispatch review допускается один actual Run по Q026. До owner Q026 всё перечисленное остаётся предложением, никаких namespace/artifacts/keys/commands сейчас не создавать и не запускать.

Check измеряет один наблюдённый nonnative sample холодного запуска/shared local ACL/private I/O/auth bounded inputs. Он **не измеряет** Docker/PG/network/TLS/native gate facts, будущую модель/очередь/OS load или полный actual-review validation в будущих условиях; full phase qualification им не заявляется. Арифметика80с rehearsal+10с readiness оставляет30с до120с только как **наблюдённый sample headroom**, не guarantee и не сложение clocks разных процессов в proof одного actual gate.
