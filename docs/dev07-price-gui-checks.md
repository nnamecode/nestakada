Новых зависимостей, схемы БД, ресурсов или бизнес-правил нет. Это прайс PriceV1, не редактор HTML-таблиц D-051/057/069; последний остаётся следующим отдельным срезом.

## Ограниченная реализация

Владелец и сотрудник с отдельным разрешением price получают обычные подписанные поля прайса: название строки/колонки, вид ячейки «Пусто / Текст / Сумма», текст либо точную строку суммы и флаг «от». Сумма вводится текстовым input, не Number/parseFloat/toFixed: исходная десятичная строка отправляется прежнему серверному producer для принятой нормализации. Пустая ячейка хранится kind=text/text="", ноль — kind=amount/amount="0". Произвольный текст, включая HTML, показывается только как textContent/value.

Пустой price=null можно явно создать, существующий — редактировать; доступны добавление/удаление/перестановка строк и колонок. Удаление всего прайса — явное действие только в RAM с последующим обычным Check/Save, прежняя версия остаётся в истории. Новые строки/колонки получают UUID; переименование и перестановка сохраняют row/column/cell identity. Новая строка получает все имеющиеся колонки, новая колонка — пустую ячейку каждой строки. Ничего не заполняется числовым нулём и не обрезается. Структурные действия проверяют прежние500строк/32колонки/10000ячеек до изменения. Нулевая структура не превращается автоматически в null; допустимость проверяет действующий server profile, новый запрет не вводится.

Для ограниченного DOM показывать страницы по20строк с явной навигацией и общим счётчиком; весь PriceV1 остаётся в RAM и целиком участвует в Check/Save, скрытые строки не теряются. Это размер интерфейсной страницы, не лимит данных/новое бизнес-правило. Допустимые старые неполные строки не дополняются молча: отсутствующая ячейка отображается пустой, появляется в storage только по явной правке; untouched matrix сохраняется точно. Labels/input не используют maxlength с обрезкой; сервер проверяет500/1000codepoints. Ошибка не заменяет значение/не повышает ресурсы.

Доступность определяется наличием собственного ключа price в server initial_state.values, а не только owner. Без права GUI не монтируется и price не добавляется в changes. Прежние серверные grants/late revoke/Check proof/CSRF/current/draft/stage/unknown-result replay продолжают действовать. Все изменения RAM-only и инвалидируют proof/dirty; accepted normalization обновляет контролы только для соответствующего epoch. Новое редактирование во время ответа не затирается. Смена личности очищает прайс/DOM вместе с остальными полями; повторная авторизация не назначает права по старому UI. Никаких localStorage/внешней сети/автосохранения.
