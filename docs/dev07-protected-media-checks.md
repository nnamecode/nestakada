## Изученная фактическая граница

`page_editor.types.ProtectedBinding` уже frozen и содержит marker_id/parent_id/slot_before_id/slot_after_id/image_id/asset_id/alt/alignment/width_px/height_px/fingerprint. `ProtectedContext(nodes=tuple)` — доверенный контекст pure normalizer; field и canonical Page scope задаются отдельно. `PendingAsset(image_id,asset_id)` — существующий тип результата, а не доказательство READY/доступа. Сейчас html_policy отклоняет protected attrs/context как ControlledUnsupported после whole unsafe validation; наличие dataclass не делает интеграцию готовой.

DEV05 storage: embedded_images хранит closed ImageRef с постоянным image ID; layout.text.protected_nodes хранит id/reference_id/fingerprint, reference_id связывает изображение/защищённую зависимость. Asset slots выводятся из main_image/preview_image/embedded image IDs. Engine preflight вне транзакции читает настоящий READY Asset, actual storage SHA/bytes каждого file и descriptor digest; check_evidence повторяет READY/DB file descriptor evidence под locks. Последняя проверка descriptor digest сама по себе не является повторным физическим SHA-чтением. Точная защита FS/DB race должна быть доказана, не приписана существующему коду заранее.

Carrier — пустой span с закрытыми marker/image/Asset/alt/align/dims attrs, актуальный data-es-parent и упорядоченные data-es-slot. Raw src/srcset/filename/MIME/style и отдельные клиентские embedded_images/layout arrays не принимаются. Placement identity — field+parent+ordered markers+ordered slots/границы, не character offset текста. Сотрудник меняет разрешённый текст/оформление внутри прежних slots; владелец выбирает/заменяет разрешённый Asset штатным picker. Исторические файлы не перезаписываются.

## Fixture и независимый oracle

Локальные owner, назначенный employee, другой назначенный пользователь/foreign Page и visitor; две Page, отличающиеся actual current/Stable/owner draft/held stage по необходимости. Минимум два различных синтетических изображения загружаются через существующий upload и настоящий worker. SHA исходного corpus и фактические File SHA/bytes снимаются независимо; DB READY/AssetFile вручную не создаются. Источники/производные реально существуют в MEDIA_LIBRARY_ROOT. Допускается служебный seed trusted initial layout/context через готовый server builder, но tested edit/replace/check/save/restore выполняются actual API/UI, не подменяются seed.

Нужны положительные controls с ненулевыми protected map и actual media usages, а не пустой ProtectedContext или картинки, не связанные со snapshot. До/после читаются immutable payload/hash, current/Stable/draft/stage/basis/pins, все соответствующие AssetUsage, actual physical SHA/bytes. Browser img проверяется настоящим HTTP body/hash и фактическим loaded image, не одной строкой src/успешным HEAD. Shared Asset разрешается, если соответствующая Page/Revision реально на него ссылается; существование UUID само по себе не является ни правом, ни основанием нового запрета повторного использования файла.

## Ворота до application/test кода

1. Автор подтверждает закрытую grammar parent/slot/marker и trusted builder из actual selected schema; field/scope/fingerprint source binding, вывод embedded_images/layout/pending_assets, сравнение effective ancestor layout. Нельзя добавлять произвольные kwargs/payload arrays или считать присланный fingerprint авторитетным.
2. Root утверждает точные owner picker/ImageRef и employee protected-context APIs, server-approved preview map/контекст File membership, deterministic export и PM slot transaction handling. URL/DOM names не угадываются; owner page/media повторное использование следует существующим правам, не новой blanket Page-local политике.
3. Требуются реальные upload/worker/FS positive controls и документированная FS/DB race модель. Иммутабельность файлов и final descriptor checks не дают права заявить атомарную защиту от произвольного внешнего bit flip без доказательства. Actual resource measurements/metadata-only admission остаются отдельными gates.
4. Сначала независимое ревью технического контракта, затем разрешение точных pure/PG/HTTP/browser tests. Разделить native media-positive, source-map pure/whole-rejection tests, real PG/FS interleavings, real Nginx+JS browser/privacy/CSP. Fixture/observer только собственные synthetic run IDs, проверка foreign data перед cleanup, permanent identity/receipts/audit и system route сохраняются.
