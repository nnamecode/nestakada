Дата 2026-10-30. Этап 7 разрешён D-302, код сайта запрещён. Конкретные инструменты по AGENTS.md и implementation-plan.md §3 требуют отдельного согласования. Здесь подготовлен ограниченный вариант для приёмочных тестов; версии Django/Python/PostgreSQL, редактора и production-инфраструктура этим предложением не выбираются.

## TEST-Q001 — выбор инструментов приёмочных тестов

**Рекомендация:** Playwright Test **1.64.1**, отдельный тестовый пакет проекта, обычный JavaScript без отдельного TypeScript-компилятора; для запуска браузеров — официальный Linux-образ **mcr.microsoft.com/playwright:v1.64.1-noble** через уже установленный Docker Desktop/WSL2. Тестовый пакет и образ должны иметь одну версию. После разрешения скачать образ, проверить и сохранить его digest и полный lock зависимостей; плавающий latest не использовать. Перед запуском подтвердить ОС/Node внутри образа и фактическую совместимость, не выдавать её за уже проверенную.

Что это даёт: изолированный набор проверок UI/HTTP для будущего локального стенда. Он не создаёт Django-приложение, не запускает production и не меняет живой сайт. Сценарии прав/SQL/восстановления потребуют контролируемых синтетических данных и согласованного адаптера тестового стенда; фиктивный mock приложения не считается приёмкой настоящего сайта.

Альтернатива: Python/pytest с Playwright; потребуются согласование Python/плагинов и дополнительные зависимости. Нативный запуск новой версии Playwright на обнаруженной Windows 10 не рекомендуем: текущая официальная матрица начинается с Windows 11. Обновление Windows не предлагается; Linux-контейнер отделяет браузерный запуск от версии Windows-хоста. Возможность самого Docker Desktop/WSL2 на этой машине ещё проверяется при запуске, а не гарантируется документацией Playwright.

## Что изменится после согласования

- В T:\nestakada появятся только тестовый пакет/конфигурация/lock и тесты; на этапе 7 не создаются файлы приложения, его миграции, compose/Dockerfile production или серверные endpoints.
- Браузеры/системные библиотеки будут внутри скачанного образа в существующем хранилище Docker на T:, зависимости тестового пакета и временные отчёты — также на T:. Никаких глобальных npm-установок, смены PATH/WSL-настроек или учётных записей.
- Запускается уже установленный Docker Desktop, если он остановлен. Контейнеры — временные для тестов, без постоянного сервиса и без автоматизации Планировщика Windows. Не использовать privileged, монтирование Docker socket/профиля пользователя, произвольные внешние сайты или хостовые секреты.
- Объём образа/место измеряются до дальнейших загрузок и фиксируются после скачивания; расход диска сейчас не выдумывается. Браузерные тесты запускаются по требованию, не постоянно и не на сервере живого сайта.
- Первичная проверка включает сборку/перечисление тестов и изолированную самопроверку harness. При отсутствии приложения проверки сайта имеют статус «не выполнено: приложения нет» либо документированный ожидаемый отказ. Пропуски/заглушки не выдаются за 140 пройденных AC.
