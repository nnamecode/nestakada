# REF-4 — публикация черновика и прямое восстановление

Дата: 2026-11-05. Статус: завершено по D-613; независимое review `APPROVED`.
Связанные требования: REF-AC-004–006, D-030/D-031, D-042/D-043, D-044–D-046, D-608.

## Граница

- Переключить публикацию owner draft на простую транзакцию без нового `OperationReceipt`.
- Заменить создание нового `RestoreStage` прямым подтверждённым restore: предварительный просмотр остаётся, подтверждение одной транзакцией создаёт новую automatic revision и переключает current.
- Существующие legacy receipts и уже созданные stages остаются читаемыми/применимыми до REF-Q004.
- Manual, Stable, удаление версий и удаление старого кода не входят в инкремент.

## Приёмочные сценарии до кода

| ID | Сценарий | Обязательный результат |
|---|---|---|
| REF4-PR-001 | Владелец публикует проверенный owner draft | Создаётся ровно одна automatic revision, current переключается, draft/usages/legacy pin удаляются атомарно; новый receipt не создаётся |
| REF4-PR-002 | Draft/current/session/audit меняются или падают во время публикации | Нет частичной revision, current, удаления draft или media usages; stale запрос получает безопасный отказ |
| REF4-PR-003 | Повторить новую публикацию и replay старого receipt | Новый повтор не создаёт дубль; старый fingerprinted receipt возвращает прежний результат без записи |
| REF4-PR-004 | Владелец подтверждает restore исторической версии | Источник повторно проходит текущую isolated-нормализацию и media evidence; одной транзакцией создаётся новая automatic revision с `source_revision_id`, current переключается, stage/receipt/pin не создаются |
| REF4-PR-005 | Сотрудник восстанавливает назначенную страницу | В новую revision попадают только разрешённые поля; URL, защищённые поля, layout/protected media и Stable не меняются |
| REF4-PR-006 | Restore без подтверждения, с устаревшим current/source/правами/session или несовместимым содержимым | Безопасный 400/401/403/409; состояние, audit и media usages не меняются |
| REF4-PR-007 | Отказ audit/media/DB после подготовки restore | Текущий public остаётся прежним, новая revision и частичные usages отсутствуют |
| REF4-PR-008 | Существующий legacy held stage применяется после переключения нового UI | Старый stage остаётся переходно совместимым и корректно consume-ится; новые stages больше не создаются |

## Проверка

Сначала узкие command/HTTP-тесты, затем полный draft/restore набор, затронутые media/embedded/concurrency тесты, независимое code review, read-only сверка основной test-БД и login smoke. Production, VPS и старый сайт не затрагивать.
