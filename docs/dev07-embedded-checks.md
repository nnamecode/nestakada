## Исходная граница и независимый oracle

E1 действительно проверяет pure placement/context: independent canonical JSON SHA, immutable types, text/inline formatting inside slots, marker/reference/parent/slot/ancestor tamper и whole refusal до native cleaner. Дополнительный nested-parent positive прошёл в финальных335. Это не фактические HTTP-права, READY, renderer или PM-редактор встроенного изображения. `source_sha256` — trusted-process provenance, не подписанная capability; корректный hex сам по себе не даёт полномочий.

E2-first подтвердил main/preview: настоящие uploads/worker/files, 22 framework HTTP/PG/child tests, два MEDIA_8 browser PASS и полную регрессию335. Его [матрица](dev07-image-picker-coverage.md) сохраняет непроверенные race/resource/identity варианты. Existing contextual membership E2 относится к внешним main/preview; нельзя просто объявить его доказательством embedded slot membership. Embedded HTTP/UI и unknown `protected_ref` пока не считаются реализованными. Legacy214 и неоднозначная старая разметка остаются отдельной безопасной incompatibility, без эвристического восстановления map.

Для будущего E3 нужны две собственные Page, owner/назначенный employee/другой employee/visitor, реальные current/ordinary/Stable и при необходимости owner draft/held stage. Минимум два отличающихся Asset A/B получают существующим native upload → approved worker из прежнего synthetic PNG/JPEG/WebP corpus. Никаких ORM READY/AssetFile, новых фотографий, зависимостей, образов, CPU/RAM/портов или gallery originals. Seed может подготовить доверенное исходное содержимое через настоящие engine APIs после gate, но tested insert/replace/text edit/check/save/stage/replay выполняется реальным HTTP/UI.

Независимый oracle связывает исходные corpus SHA/bytes, actual AssetFile IDs/kinds/descriptors, физический manifest, HTTP body SHA/length и реально loaded browser image. Для map отдельно сверяются field/Page scope, постоянные identities, parent path/ancestors, порядок marker/slots, marker-to-slot boundaries и canonical fingerprint. Ожидаемые fingerprints строит QA, а не production builder. После check сверяются checked HTML и выведенные сервером `embedded_images`/`layout`; после commit — immutable snapshot, current/history/author, usages всех kinds/consumers/slots, draft/stage/pins/receipts/audit и физические файлы. Один `contenteditable=false`, UUID, status200, `src` или пустой ProtectedContext недостаточен.

## Точные вопросы к API-gate

Перед executable tests автор/root фиксируют следующие технические детали без нового бизнес-правила:

1. Закрытая операция выдачи identities для owner insert/replace, допустимые caller inputs, exact поля результата/check receipt/source binding и same-op поведение. Какие существующие identities сохраняются при замене и какие создаются заново; клиент не становится владельцем произвольных IDs.
2. Trusted derivation `embedded_images`/`layout` из checked markup+actual source, независимое canonical fingerprint представление, projected selected contexts current/draft/stage и взаимодействие retained main/preview evidence. Типы и названия не угадываются.
3. Поддержанная parent/slot grammar, paragraph split/join/linebreak и finite ancestor influence map, safe capability fallback. Список разрешённых текстовых операций требует положительных UI/HTTP controls, не только tamper negatives.
4. Exact embedded contextual-file/picker URL/DOM contract, server-approved derivative mapping и late identity/membership/descriptors. Существующий E2 endpoint нельзя молча расширить без нового reviewed membership oracle.
5. Schema/ledger/engine seams для atomic/replay/concurrency tests, реальная FS trust boundary, metadata-only admission и resource profile. Если потребуется новый инструмент/ресурс — отдельное решение; тест не повышает ресурсы автоматически.

После gate QA получает владение конкретными новыми test/tool файлами. Для реализации можно повторно использовать знания proven E2 host/observer/native-upload patterns, но старые E2 файлы не изменяются параллельно и не ослабляют guards: own run IDs, system Route, host-observed allowed file keys, validated consumers, stop own writers before close, content→auth locks, physical leaf check, permanent ledgers preserved. Реальные runtime, fixtures и cleanup запускает координатор только после freeze/review. Первая ошибка сообщается с новым основанием повтора; вторая эквивалентная без нового условия останавливает работу по AGENTS.
