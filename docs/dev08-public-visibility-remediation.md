# DEV-08E: исправление публичной видимости

Дата: 2026-11-09
Основание: D-052, D-238–D-240, D-244 и обнаруженное после D-704 расхождение DEV-08A/C.

## Причина

DEV-08A ошибочно связал доступность опубликованной страницы с публикацией всех предков, а DEV-08C вслед за ним исключил всё поддерево скрытого родителя. Это противоречит действующим решениям:

- D-052: известный неопубликованный URL отвечает пустым белым `200`, не `404`;
- D-239: опубликованный ребёнок скрытого родителя продолжает открываться;
- D-240: в автоматической навигации скрытый родитель пропускается, а опубликованный ребёнок поднимается к ближайшему опубликованному предку;
- D-238: `404` относится к неизвестному или полностью удалённому URL;
- D-244: redirect временно скрытой страницы сохраняется и ведёт на её текущий URL.

D-700/D-702 остаются историей реализации, но их hidden-subtree вывод исправляется этим более ранним утверждённым контрактом.

## Приёмочные сценарии

- `VIS-001`: exact PRIMARY и ALIAS существующей неопубликованной Page отвечают `200 text/html` с нулевым body; имя, payload, Header/Footer, menu и private данные не выдаются.
- `VIS-002`: пустой ответ не зависит от наличия/целостности current revision или shared blocks, не создаёт session/cookie и не пишет Page/Route/version/shared/audit.
- `VIS-003`: REDIRECT существующей неопубликованной Page остаётся прямым `301` на её exact PRIMARY; последующий PRIMARY даёт пустой `200`.
- `VIS-004`: опубликованная Page открывается независимо от флага публикации любого предка; её собственные current/schema/hash/XSS проверки сохраняются.
- `VIS-005`: navigation исключает саму неопубликованную Page, но включает опубликованных потомков в прежнем стабильном порядке и указывает ближайшего опубликованного предка либо root как их видимого родителя.
- `VIS-006`: неизвестный, удалённый, SYSTEM и синтаксически недопустимый target остаётся закрытым `404`; это не превращается в универсальный пустой `200`.
- `VIS-007`: missing/invalid PRIMARY опубликованной видимой Page, cycle/disconnected graph и DB failure по-прежнему дают закрытый `503`; скрытая Page без пункта меню не требует PRIMARY для navigation.
- `VIS-008`: GET/HEAD пустой страницы имеют пустой body, `no-cache`, CSP/nosniff и не запускают shared renderer/navigation; POST остаётся `405`.

## Минимальная реализация

- один frozen `PublicBlank` из существующего exact Route resolver;
- убрать проверку ancestor publication из выдачи Page, не меняя дерево или флаги;
- один bounded navigation traversal с переносом только видимого `parent_id`, без SQL-рекурсии, кэша или новой таблицы;
- существующая HTTP view возвращает пустой ответ до shared renderer.

## Не входит

Layout/price/media, новые error templates, SEO, формы, HTML fallback, миграция данных, изменение редактора или production deployment.

## Статус D-705

`VIS-001–008` записаны до кода. DEV-08E начат как исправление утверждённого контракта, а не расширение scope. Новые модели, schema, зависимости, cache и background process запрещены.

## Итог D-706

DEV-08E завершён. Exact known PRIMARY/ALIAS скрытой Page возвращают frozen `PublicBlank` и нулевой `200 text/html` до current revision, navigation и shared renderer. REDIRECT остаётся прямым к same-page PRIMARY. Опубликованная Page определяется собственным флагом независимо от предков. Navigation пропускает hidden node, не требует для него PRIMARY и передаёт потомкам ближайшего опубликованного родителя; cycle/disconnected и повреждение опубликованного пункта остаются закрытым `503`.
