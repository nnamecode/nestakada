2026-10-31. Код подготовлен для фактических root QA/независимого ревью, PASS браузера/HTTP не заявлен. Только `app/page_editor/assets/carrier-editor.mjs`, `editor.mjs`, `editor.css`; handler/политика/body/CSP/БД/worker/сервер не менялись этим исполнителем. ## Контракт адаптера

ESM export `createEditor(element,{approvedHtml,owner,field,styleSheet,onDirty,onError,onUntrustedInput})` из carrier-editor.mjs. Field только intro_text/main_text; styleSheet — загруженный same-origin LINK CSSStyleSheet, например editor.css. Без доступной stylesheet нет тихого fallback к style attribute.

Return methods: getCanonicalHtml(), getInput()→{mode,html}, validateApprovedHtml(html), setApprovedHtml(html,{emitDirty:false}), setRawHtml(raw), setMode('html'|'visual'), command(name,value), focus(), destroy(). Raw никогда не передаётся setContent/DOMParser/live DOM; только textarea.value в памяти. Название setApprovedHtml означает именно root/server-проверенный материал, не встроенную клиентскую санкцию. Возврат из HTML в visual требует explicit check/accept и этого метода. Нормализатор/проверки прав на сервере обязательны.

getCanonicalHtml сериализует закрытый PM document по типам/attrs/marks, не outerHTML/native editor.getHTML. Разрешённые semantic marks strong/em/u/s/sub/sup, собственный esFormat font/size/fg/bg, block align/margins, anchor/link carrier. Unknown schema/attrs/protected nodes не теряются silently. Вложенный обычный format объединяется по inherited map с приоритетом внутреннего span. Неподдержанные empty/nested anchor shapes дают понятный fixed error и остаются стыком, не объявлены поддержанными.

Адресный roundtrip fix после первого EH002: один actor/view-owned cache хранит exact SERVER-approved canonical и immutable PM base document только после успешного существующего closed import/render. Пока currentDoc.eq(baseDoc), включая undo обратно к основе, все visual exports возвращают этот approved source; реальное изменение model использует прежний закрытый serializer. Это сохраняет исходную группировку format-span/strong, которую плоские PM marks иначе дробили, и не является DOM.outerHTML/raw passthrough. Raw mode возвращает только raw для проверки, не создаёт base; HTML-only/destroy/different-user cleanup удаляют обе ссылки. View fault проверяется раньше cache: explicit check читает actual model serializer, обычный export блокируется. Cache не доказывает import fidelity; unknown/unprovable shapes по-прежнему требуют controlled HTML fallback, а computed semantic/edited/undo/native-recheck controls остаются обязательными.

Stock TextStyle/FontSize/TextAlign/TableView не используются. StarterKit лишние nodes/link/style cursor выключены; собственные node/mark views создают обычный DOM и назначают только generated CSSOM classes. injectCSS:false. Ни одного собственного style element/element.style/style attribute/CSS raw selector. Registry принадлежит view, переиспользует только текущие style facts, удаляет неиспользуемые rules после document transaction и все свои rules при destroy; предыдущие просмотренные цвета не являются вечным cache. Временный safety budget40000 rules/nodes на view — защита UI, не новая квота истории/содержимого; серверные DOM/field бюджеты остаются принятыми.

Адресный UI-EDITOR-REV001: dirty/proof invalidation предшествует CSS refresh; pinned Tiptap beforeTransaction hook также инвалидирует до EditorView.updateState/nodeviews. Rules faults latch viewBlocked, getCanonicalHtml/visual commands и Save не выдают прежнюю редакцию как успех; getInput оставляет реальный текущий PM source для отдельной явной проверки. Любой adapter onError инвалидирует accepted/review даже во время checked-response application, RAM не очищается. После style fault Save требует отдельный Check; только успешный server-check+explicit acceptance/reset возвращает доступ к сохранению.

Все approved таблицы в этой когорте — **opaque readonly atom**, без TableMap/colgroup/inline style и без обещания визуальных table commands. Exact approved canonical table substring (включая caption/sections/scope/nested) хранится в RAM atom и возвращается целиком serializer; private view показывает только escaped text/details и кнопку HTML-режима. Это не raw input и не table DOM.outerHTML. Protected integration явно не подключена, никакого выдуманного разрешения Asset через client attrs.

Visual plain paste — insertText. Rich paste/drop default остановлен до DOM; callback передаёт raw text/HTML только в RAM staging. Полный кандидат открывается отдельным явным действием в HTML textarea, затем whole-field server check и принятие. Для rich paste staging явно сообщает добавление в конец поля, не выдаёт это за незаметную вставку в курсор. Link command также готовит полный RAM candidate без dispatch небезопасного href в live DOM. Клиентский редактор не санитайзер.

Адресный UI-EDITOR-REV004: обработчики установлены именно в editorProps.handleDOMEvents.paste/drop, вызывают preventDefault+true **до** ProseMirror parseFromClipboard/readHTML. Поздние handlePaste/handleDrop и одно enablePasteRules:false этого не обеспечивают и больше не используются для этой границы. Plain text вставляется своим insertText; raw rich clipboard/drop не передаётся innerHTML/DOMParser/live DOM. Instrumentation actual events/network/CSP должен подтвердить этот путь.

## Root template/controller contract

`mountEditorPage({root,initialState,styleSheet,check,save,draft,reauth})` export из editor.mjs, без автоматического bootstrap/fetch/путей/секретов. Точные root state:

```text
{owner,pageId,generation,baseRevisionId,editingFrom,draftBasis,stageId,
 values:{all allowed changes},
 fields:[{name:'intro_text'|'main_text',rawHtml,approvedHtml:string|null}],
 checkReceipt:null}
```

Для approvedHtml=null используется только внутренняя безопасная пустая visual-пустышка и setRawHtml(rawHtml); неизвестный raw остаётся в textarea, не парсится как HTML. Root selector: `[data-editor-field="intro_text|main_text"]`, необязательный `[data-editor-mount]` внутри; статус `[data-editor-status]`, dirty `[data-editor-dirty]`. Если placeholders отсутствуют, controller создаёт только свои UI containers. Actions data-editor-action=check/save/draft/retry-intent. Native contenteditable surface внутри mount имеет `.es-editor-surface`; HTML textarea `.es-html-source`. Кнопки/политика сохранения черновика не подменяют серверный owner check.

Callbacks:

- check(changes) → `{normalisedChanges,normalisationChanged,fieldWarnings,checkReceipt,baseRevisionId}`. Values берутся из actual root state и собственного текущего ввода полей; источником body остаётся callback root. После изменившегося ввода во время ожидания ответ не затирает поле.
- save/draft({changes,checkReceipt,operationId,context}) → настоящий DEV05 `{result_id,result_code,replay,gone,operation_id}`. Context — **замороженный на момент отправки** snapshot pageId/generation/baseRevisionId/editingFrom/draftBasis/stageId. Root transport bridge должен использовать этот snapshot при повторе, а не более новый mutable state, иначе нельзя обещать exact body retry. URL/auth/cookie/CSRF/current-right checks остаются root handler.
- reauth() → `{sameUser:boolean}`. Это root настоящий отдельный вход в том же контексте; controller не отправляет текст автоматически. Для сменившегося пользователя собственные editor/RAM fields уничтожаются; для того же прежний ввод сохраняется, proof инвалидируется. Обновление актуальной идентичности/basis/прав — root bridge, не доверие client owner flag.

Адресное уточнение reauth contract: сообщение об успешном входе возможно только при response object с exact boolean sameUser после фактической проверки root bridge. Undefined/malformed/неполный ответ → fixed EDITOR_REAUTH_INCOMPLETE, без очистки прежнего unknown-save intent. Proven different identity — sameUser=false либо специальный EDITOR_IDENTITY_CHANGED от root сравнения actual server identity с исходной — очищает собственные редакторы/intent/review и блокирует UI до нового открытия страницы. Обычный session-expired/preflight failure не считается доказательством смены пользователя и не освобождает unknown intent. Новых запросов/auto retry при reauth нет.

Адресное privacy уточнение: EDITOR_IDENTITY_CHANGED обрабатывается для любого guarded check/save/retry callback, не только reauth. При доказанной смене удаляются собственные clones accepted/pending/proof/intent/context, shared initialState.values и fields raw/approved contents; input/textarea/pre очищаются до отсоединения review/DOM. Adapter destroy очищает source/opaque table registry, исходный approvedHtml binding, DOM text и ссылки на Editor/Rules/callbacks, а controller очищает map и terminal-lock. In-flight local check/intent body также очищается на этом identity code. Обычный session-expired/incomplete response не запускает такую очистку. Root bridge отдельно очищает свои pending/CSRF/bootstrap JSON copies. Это удаление доступных собственных ссылок/значений с последующим GC, **не обещание физической zeroization JS памяти**.

Нормализация отображается безопасными pre.textContent, принятие отдельно подставляет approved text и не публикует автоматически. Save без изменённой normalization проверяет ввод и выполняет только уже явное действие пользователя; после изменившейся normalization надо принять и нажать Save отдельно. При ошибке адаптации одного из полей предыдущий ввод всех полей возвращается в RAM HTML mode, публикации нет.

Адресный UI-EDITOR-REV002: validateApprovedHtml возвращает visual capability, а известная визуально неподдержанная форма не блокирует server-valid HTML. Exact SERVER-checked canonical (например пустой anchor) остаётся в RAM HTML-mode с accepted proof и может быть сохранён через тот же проверенный source; GUI не заявлен. Старый visual state уничтожается, getCanonicalHtml не выдаёт его вместо HTML-only поля. Unsafe/badprofile (style/class/id/active tags/неразрешённые attrs) не классифицируется так, не подставляется в DOM и не получает GUI claim. Controller по-прежнему не создаёт server proof самостоятельно.

Success UI допускается только по структурно валидной DEV05 receipt с тем же operation UUID. Неопределённый ответ сохраняет immutable exact intent/action/body/UUID в RAM, блокирует новое сохранение до разбора и показывает отдельную кнопку **ручного** повтора прежнего намерения. Edit не переписывает старый body или UUID. Повтор не является автоматическим retry; callback не должен приписывать этому UUID новое содержание. Новые правки после старой отправки не затираются подтверждением старого результата. Для известного отказа именно save POST root bridge передаёт outcomeKnown=true+status400/401/403/404/408/409/411/413/415: pending/proof сбрасывается, RAM сохраняется, новый check/op допустим. Preflight state/check/reauth отказ не доказывает rollback прежней неизвестной отправки и обязан иметь outcomeKnown=false; старый intent остаётся для same-user manual retry. 5xx/network/malformed receipt также unknown. Reload/local storage/session storage/IndexedDB/URL-передачи текста нет.

Операционные UUID и scope IDs строятся WebCrypto getRandomValues с UUIDv4 variant/version bits, без Math.random; это работает и на согласованном HTTP test origin, где secure-context-only randomUUID может отсутствовать. Root bridge обязан использовать замороженный context из callback при exact retry; чтение mutable нового basis вместо него нарушило бы контракт. Дополнительные root формы должны менять values и инвалидировать proof: controller отслеживает внешние input events, также возвращает invalidate()/getChanges() для явной стыковки. Client owner/styleSheet/state — удобство UI, не источник серверных полномочий.
