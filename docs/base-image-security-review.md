# Независимое ревью исправлений базовых образов

2026-10-30. Рецензент: `base_image_security_review`, отдельный от авторов сборок и разбора применимости. Основания: D-314, D-315 / TEST-Q009; область — ENV-07 и ограниченная локальная основа до DEV-02/DEV-28.

## Вердикт

**Существенных замечаний, препятствующих использованию проверенных артефактов для ограниченной локальной основы, не обнаружено.** Целевые исправления BASESEC-001–004 подтверждаются составом, происхождением и сохранёнными runtime-свидетельствами. Пакет пригоден как результат подготовки локальных базовых образов при сохранении описанных ниже ограничений.

Это технический результат ревью, а не разрешение писать сайт, принятие владельцем оставшихся эксплуатационных рисков или допуск production. Переход к этапу 8 отдельно разрешает владелец. Полные AC приложения, внешний ARC-10 и выпускные проверки остаются своими воротами.

Ревью включало чтение рецептов, исходных решений, отчётов и первичных сохранённых свидетельств; независимый пересчёт файловых хэшей, сверку JSON/CSV и проверку синтаксиса приёмочного файла. Runtime-прогоны выполняли авторы подготовки; рецензент проверял их реальные сохранённые результаты и identity-связи, без собственного повторного запуска контейнеров.

## Проверенная цепочка происхождения

- Сверены `runtime-images.lock.json`, upstream `images.lock.json`, `source-archives.lock.json`, три input-lock и три build receipt. Пересчитаны 12 указателей требований/рецептов/input-lock/receipt/архивов; значения совпали.
- Независимо пересчитаны 83 хэша Debian/wheel входов Python и 82 хэша Debian-входов PostgreSQL. Официальные source archives PostgreSQL 18.6 и psycopg-c 3.3.6 совпали с закреплёнными SHA256. Рецепты проверяют эти входы до компиляции; `dpkg --audit` используется без `force-depends`.
- Receipt каждого финального артефакта содержит соответствующие закреплённые upstream materials и build network `none`. Для Python/PG фактически выбран внешний канонический рецепт через `--file`; исторические `Dockerfile` внутри work-контекстов не приняты за определение последних сборок.
- Три конечных Docker-reported image IDs сопоставлены с фактическими final-identity JSON и exported digest из receipts. Для PostgreSQL принят только конечный hardened ID `sha256:de3d5ee43e308309e10730caead7dd880539d53f0275d977cd2f8c3f62b6eef7`. Первичный артефакт `1171d32a…` не используется как свидетельство конечного результата.
- Docker-reported image ID, OCI manifest/export digest и config digest не объявляются взаимозаменяемыми. Их совпадение в текущем containerd store не превращает Docker ID в отдельный config digest. Обновлённые FOUNDATION-001/009 сохраняют это разделение, источники архивов и build receipts.
- `runtime-components.cdx.json`: 135 уникальных component refs; ссылки трёх образов согласованы с runtime-lock. Метаданные, рецепты и lock-файлы содержат публичные артефакты/версии/хэши. В 17 новых файлах области `environment/foundation` не обнаружены private-key material или DSN с паролем; содержимое также просмотрено на передачу секретов через build args/контекст. Локальные fixture-секреты и дампы в этот пакет не включены.

## Ненулевой остаток и границы допуска

Реестр сохраняет 118 исходных постоянных ID. Итоговые группы независимо сверены: **34 source-package-removed; 38 vendor-unimportant; 44 vendor-deferred; 1 PAM с незадействованным проверенным auth-путём; 1 zlib с отсутствующим конкретным описанным source-путём**. Во всех 34 строках удалённые source packages действительно отсутствуют в конечных Python/PG инвентарях. Они не названы пропатченными пакетами.

**156 image/advisory совпадений по 84 исходным ID остаются видимыми.** Это vendor-tracked остаток, не 156 исправлений и не нулевой результат аудита. Новые сопоставления вне исходного реестра не заявлены как найденные; source-version scan и его snapshot не заменяют аудит неизвестных уязвимостей.

- PAM `undetermined` не переименован в resolved. Отсутствие PAM в PG auth-пути и серверной сборке ограничивает текущую применимость, но не закрывает все сценарии локального входа/новых процессов ОС.
- zlib не объявлена универсально исправленной: разбор exact source ограничен CVE-описанным retry/gz_vacate механизмом, с привязкой к текущему Debian package/runtime identity. Статус поставщика остаётся open. Расширение путей использования требует пересмотра.
- Setuptools83.0.0 остаётся только в builder по upstream pin psycopg-c. Его конкретный GHSA-xmj3-9gf7-h52w оценён для Linux/offline/pip с проверенными wheels и отсутствующим legacy install_as_egg путём. Это адресная неприменимость, не wildcard-подавление advisory и не утверждение об установленном исправленном setuptools84.
- Собственные PG/C-сборки требуют повторяемого обновления с сохранением новых input-lock/receipts и применимых регрессий. Однодневный тестовый CA не используется как production-материал. Отчёты выключения относятся к fixture; старые данные/образы сохраняются отдельно.

До недоверенной нагрузки и выпуска остаются повторный разбор актуальных vendor advisory, реальные настройки и интеграции приложения, приёмочные сценарии и production TLS/архитектура/резервирование. **11 FOUNDATION-сценариев самого приложения не исполнялись; 140 полных AC не объявляются пройденными.**

## Завершение

Новых открытых замечаний `BASE-REV-xxx` к проверенному пакету не выявлено. Замечания исходного реестра и перечисленные release-gates сохраняются со своими постоянными ID; они не заменены формальным «всё безопасно».

Текущий этап — **7, подготовка и проверка локальной основы**. Следующий — **8, ограниченная DEV-02/DEV-28**, только после отдельного решения владельца. Ревью не разрешает изменения старого сайта, VPS или публикацию.
