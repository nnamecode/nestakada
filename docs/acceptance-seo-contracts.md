## Начальные синтетические данные

Ниже внутренние имена и новые тестовые маршруты; они не выбирают URL/ORM/endpoints продукта. Reset готовит собственную изолированную БД, не затрагивает действующий сайт. Oracle не читается из результата SEO-функции приложения.

- `seo-index-state-matrix`: в минимальной fixture ровно три индексируемых опубликованных canonical-представителя: `/`, `/acceptance/seo/published/`, `/acceptance/seo/second/`. Все три реально доступны по200. Первый P-LIVE содержит SEO-PUBLISHED-CANARY и непустые разные title/H1/description; известный момент изменения `2026-10-01T08:30:00Z`. У P-SECOND достоверная lastmod отсутствует. Время не берётся из запроса/момента reset.
- В той же fixture P-HIDDEN/P-NOINDEX/P-DELETED/P-REDIRECT/P-PRIVATE/P-ALIAS/P-QUERY-DUP/P-NEW-DRAFT имеют соответственно `/acceptance/seo/hidden/`, `noindex/`, `deleted/`, `old/`, `private/`, `alias/`, `published/?tracking=one`, `draft/`. Это заданные тестом собственные страницы/планируемые публичные пути, не неизвестные production-маршруты. Redirect указывает на P-LIVE, alias имеет того же представителя. P-PRIVATE — существующий владельческий черновик с зарезервированным будущим публичным путём; **реальный закрытый маршрут его чтения** определяется reviewed binding и используется owner/visitor одинаково. Отсутствие будущего публичного пути в XML не является полной проверкой всех административных URL.
- Raw canary hidden/noindex/deleted равны SEO-HIDDEN-CANARY/SEO-NOINDEX-CANARY/SEO-DELETED-CANARY, черновика — SEO-PRIVATE-DRAFT-CANARY. Синтетические секреты robots: `/SEO-SECRET-DOCUMENT-CANARY/`, SEO-SYNTHETIC-SESSION-CANARY, `/local/private/backup-seo-fixture/`. Они существуют в исходных приватных fixture-полях и не должны появляться в robots; не задавать их только в expected. Контентные canary не являются credentials/cookies/secretRefs адаптера, не маскируются вместо серверного отказа.
- `seo-page-independent-fields`: P-EDIT назначена владельцу, публична, сохранённые название/title/H1/description непусты и различаются; description не совпадает с новым тестовым значением. Редакция/URL известны. Настоящий rename и отдельный submit-page-direct проверяются по фактическому имени/публичному тексту, а SEO остаётся прежним.
- `seo-confirmed-synthetic-business`: опубликованные индексируемые P-HOME/P-CONTACTS, подтверждённое название «Синтетический автосервис SEO», телефон +70000000000, адрес «Тестовая улица, 1». Это заведомо тестовые данные без обращения к реальному телефону/картам/Метрике/validator-service. Geo/sameAs/рейтинги/отзывы/цены/Offer отсутствуют и не считаются подтверждёнными. Одна организация использует доверенный origin локального стенда и `/#auto-repair`, не текущий Host посетителя.

В том же независимом fixture-профиле необходимы публичные `/assets/seo-fixture.css`, `/assets/seo-fixture.js`, `/img/seo-fixture-image.jpg`; их адреса заданы тестом до чтения robots, а не выбираются из разрешённых самим сервером. Это тестовые представители нужных CSS/JS/медиа, не новая система путей продукта и не полный перечень его ресурсов. ## Действия и фактические наблюдения

`seo-sitemap-response` и `seo-robots-response` возвращают **сырые настоящие HTTP status/contentType/body** из изолированной цели, без подстановки XML/правильных директив/очистки ответа observer-ом. Sitemap разбирается тестом самостоятельно через DOMParser XML с проверкой namespace/parsererror/loc/duplicates. Отдельная parser page никогда не открывает приложение, имеет JS=false/serviceWorkers block, HTTP/WebSocket abort; app-адаптер использует собственные настоящие контексты независимо. XML50МБ/50000 и условные HTTP этого набора не исполняются.

`seo-public-response(material)` читает реальное публичное HTTP-тело и заголовок X-Robots-Tag, из фактического HTML извлекает canonicalUrls, все разобранные JSON-LD-документы, descriptionValues/title/H1, видимые телефон/адрес. Не брать эти значения из expected или из БД вместо ответа. Некорректный JSON-LD должен вызывать отказ наблюдения, не исчезать из списка. Тест извлекает AutoRepair из документов/их @graph с наследованием @context, не запрещая постороннюю безопасную разметку одним счётчиком script. Полная семантическая Schema-валидация и дубли других Organization остаются отдельно.

`seo-page-state` читает настоящие revision/name/title/H1/description. set-page-indexing-direct/save-page-seo-direct/rename-page/submit-page-direct выполняют реальные допустимые UI/HTTP-операции, с действительным основанием/правами/CSRF. Состояние страницы не меняется прямой БД-записью вместо проверяемого действия.

`seo-business-state` даёт фактическое основание общего бизнес-блока. save-confirmed-business-name сначала принимает обычное новое имя, которое видно в публичной AutoRepair; затем получает вредную строку. Допустим серверный отказ с сохранением правильного имени либо корректное сохранение буквального текста внутри по-прежнему разобранного AutoRepair. Нельзя ошибку транспорта выдавать за бизнес-отказ. Тест **не доказывает реальное неисполнение script/CSP/состав DOM действующей вкладки**: текущий stdio observe не умеет читать window/DOM actor page. Эта runtime-ветвь честно неподготовлена до отдельного reviewed read-only browser observer; seo-browser-execution-evidence/view-seo-page-in-real-browser не используются.

`read-private-seo-material-direct` использует один и тот же реальный закрытый обработчик/ID/метод: меняется только авторизация/связанные токены. Owner-positive сначала доказывает наличие черновика, visitor не получает его тело. Нельзя заменить отказом неизвестного URL или отсутствием кнопки. Privacy-проверка не означает готовность production TLS/Host/proxy/CSRF/check-deploy.

## Честный остаток

Не покрыты все URL/публикационные переходы/удаление и rename в XML, XMLэкранирование/границы50000/50МБ/разбиение/условные запросы/lastmod общих блоков/инвалидация кэша; полная robots-политика произвольных ресурсов/UA и query; Host/forwarded poisoning; превью-картинки/новые страницы поумолчанию; полный alt/Schema/cookies/CSP/EXIF/внешняя валидация и runtime-неисполнение после вредного имени.

Для независимого малого ASCII-набора robots helper применяет prefix matching к path+query, `*` как ноль/более символов, терминальный `$`, наибольшую длину совпавшего rule path и allow при равенстве. Конечный `*` без `$` не повышает специфичность. Поэтому Disallow:/* и более специфический запрет публичного пути/необходимого ресурса не проходят; наличие двух Allow-строк само по себе уже недостаточно. UTF-8/percent-encoding дают явный unsupported-readiness отказ, не предполагаемое разрешение; выбор UA вне wildcard-профиля и полный crawler engine остаются неподготовленными. Семантика для этого поднабора сверена с [официальной спецификацией Google](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) 2026-10-30; это проверка принятого SEO-профиля, не новая production-policy.

Аварийные AT-606/SEO-006 требуют независимого настоящего control/gate/head/актуального XML и физического ARC-10; этот файл их не исполняет и не заявляет готовыми. Часть canonical/viewport уже в public-contracts, оставшиеся metadata/реальные восемь браузеров и Safari/iPhone не заменяются этими assertions. Приложения/bindings/fixture bridge пока нет, независимое ревью/сборка записываются координатором; набор против приложения не запускался. Полное TEST-04/TEST-07 остаётся открытым.
