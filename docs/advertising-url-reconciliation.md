Статус D-1066, 2026-11-14. Это завершённая локальная инженерная сверка для `READY-04 / MIG-01`, `AC-051` и `AC-MIG-006`. Рекламные проекты, кабинеты, кампании и выгрузки не входят в область разработки/системного администрирования; исторический `LAUNCH-IN-007` retired/not applicable.

Обновление D-1065/D-1066: владелец подтвердил, что больше половины страниц участвуют в рекламной сети и все перенесённые старые URL должны сохраниться буквально 1:1, но отдельная работа с рекламными проектами не требуется. Host-only read-only сверка без сети: `site-inventory.csv` rows114/unique requested114, `analytics-route-map.csv` rows115/unique paths115, известных requested URL вне map0, duplicate0. Единственный map-only адрес — утверждённый `/services/avtomojka`; exact query paths `/gallery-of-works/?page=1` и `?page=2` присутствуют в обоих реестрах.

## Уже известная локальная база

`docs/site-inventory.csv` содержит 114 строк и 114 уникальных `requested_url` одного host `estakada-service.ru`. На момент сохранённого обхода все 114 ответили HTTP 200 без записанных ошибок; уникальных `effective_url` — 113.

- Единственное различие requested/effective: `/gallery-of-works/?page=1` → `/gallery-of-works/`.
- Query присутствует ровно у двух известных адресов: gallery `?page=1` и `?page=2`.
- Старый вложенный адрес автомойки `/services/drugie-uslugi/avtomojka` присутствует в обходе как HTTP 200.
- Новый согласованный адрес `/services/avtomojka` есть в route map как MAP-115, но отсутствовал в публичном обходе; он не отменяет старый адрес.

Эти утверждённые реестры являются технической границей миграции URL проекта. Проверка состава рекламных кампаний находится вне scope.

## Граница ответственности

Дополнительный файл или доступ от владельца не требуется. Разработчик не запрашивает рекламную статистику, настройки кампаний, идентификаторы аккаунта, cookies, API-токены, логины или пароли. Если владелец позже сам изменит согласованный список URL, это оформляется как обычное изменение требований к route map.

## Правила сравнения

1. Сравнивать полные URL, сохраняя регистр, завершающий слеш, percent-encoding и query. Не добавлять слеш и не убирать параметры автоматически.
2. Не следовать редиректу вместо проверки исходного рекламируемого адреса: D-023 требует идентичный URL.
   Literal identity включает регистр, завершающий слеш, percent-encoding и полный query; рекламируемый URL не заменяется canonical или новым удобным адресом.
3. Для каждой строки inventory должен существовать ровно один literal path+query в route map.
4. Дубликаты exact URL сообщать отдельно, но не считать новым адресом.
5. `route_map_only` допустим только как отдельно утверждённый новый адрес и не служит основанием удалить старый.
6. Любой будущий новый URL сначала добавляется в утверждённый migration inventory; сетевые запросы по неизвестному адресу автоматически не выполнять.
