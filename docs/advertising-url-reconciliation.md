# Сверка рекламируемых URL

Статус D-1010, 2026-11-14. Это минимальный протокол для `LAUNCH-IN-007`, `READY-04 / MIG-01`, `AC-051` и `AC-MIG-006`. Он не заменяет фактическую выгрузку рекламных адресов, не подключается к рекламному кабинету и не изменяет кампании.

## Уже известная локальная база

`docs/site-inventory.csv` содержит 114 строк и 114 уникальных `requested_url` одного host `estakada-service.ru`. На момент сохранённого обхода все 114 ответили HTTP 200 без записанных ошибок; уникальных `effective_url` — 113.

- Единственное различие requested/effective: `/gallery-of-works/?page=1` → `/gallery-of-works/`.
- Query присутствует ровно у двух известных адресов: gallery `?page=1` и `?page=2`.
- Старый вложенный адрес автомойки `/services/drugie-uslugi/avtomojka` присутствует в обходе как HTTP 200.
- Новый согласованный адрес `/services/avtomojka` есть в route map как MAP-115, но отсутствовал в публичном обходе; он не отменяет старый адрес и не считается рекламируемым без внешнего доказательства.

Эти факты описывают только публично найденные URL. Они не доказывают отсутствие несвязанных или параметризованных рекламных посадочных адресов.

## Минимальный вход от владельца

Безопасный локальный путь будущего файла:

`work/launch-inputs/advertising-urls.csv`

Каталог `work/` уже исключён из Git. Файл не коммитить и не прикладывать к публичной документации.

Достаточный формат:

```csv
advertised_url
https://estakada-service.ru/example/path
```

Допускается вместо CSV обычный текст: один полный destination URL на строку. Обязателен только сам конечный адрес объявления. Названия кампаний/групп можно добавить для удобства, но они не нужны для технической сверки.

Не передавать статистику, бюджеты, поисковые запросы пользователей, телефоны/почту клиентов, идентификаторы аккаунта, cookies, API-токены, логины или пароли.

## Правила сравнения

1. Сравнивать полные URL, сохраняя регистр, завершающий слеш, percent-encoding и query. Не добавлять слеш и не убирать параметры автоматически.
2. Не следовать редиректу вместо проверки исходного рекламируемого адреса: D-023 требует идентичный URL.
3. Для каждой уникальной строки назначить ровно один результат: `inventory_exact`, `route_map_only`, `advertising_only`, `foreign_or_invalid`.
4. Дубликаты exact URL сообщать отдельно, но не считать новым адресом.
5. `advertising_only` не удалять и не перенаправлять автоматически: сначала добавить в migration inventory и определить требуемое содержимое.
6. `route_map_only` и отсутствие URL в рекламной выгрузке не доказывают, что адрес можно удалить.
7. Любой неизвестный host или схема остаётся на ручную проверку; сетевые запросы по нему не выполнять автоматически.

## Результат сверки

Итоговый read-only отчёт должен содержать только счётчики и сами destination URL по четырём категориям, без секретов и рекламной статистики. До получения входного файла `LAUNCH-IN-007`, `AC-051` и `AC-MIG-006` остаются открытыми; локальные 114 URL не повышаются до полного evidence.

Следующее действие владельца, когда будет удобно: сохранить экспорт или простой список destination URL в указанном ignored-пути. После этого можно выполнить локальное сравнение без доступа к рекламному кабинету, VPS и старому сайту.
