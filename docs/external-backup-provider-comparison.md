# Внешнее хранилище резервных копий — краткое сравнение

Дата последней проверки: 2026-11-22. Статус: Selectel S3 выбран владельцем как направление B002 по D-1848; аккаунт, услуга и bucket не подключены.

## Текущая граница

- Нужен один независимый от FirstVDS провайдер объектного хранилища, а не второй сервер.
- На VPS остаются два локальных поколения. Внешнее хранилище держит два поколения и временно третье во время безопасной ротации.
- Расчётный внешний пик — до 12 ГиБ: три поколения максимум по 4 ГиБ.
- Передача выполняется только после клиентского шифрования; ключ не хранится на VPS, в Git, базе приложения или самом хранилище.
- Подключение, выбор программы передачи и учебное восстановление — отдельные этапы после решения владельца.
- S3 не является POSIX-файловой системой: он не предоставляет directory fd, `O_NOFOLLOW`, `fsync` каталога или проверяемый `st_dev`. Поэтому внешний bucket не может молча заменить вторую POSIX-копию в текущем `RB3-LEDGER-AUTHORITY-001`.

## Кандидаты

### 1. Selectel S3 — рекомендуется

- Провайдер: АО «Селектел», отдельное юридическое лицо от АО «ИОТ», от имени которого работает FirstVDS.
- При создании бакета можно выбрать российскую локацию; официально перечислены Москва и Санкт-Петербург.
- S3 API позволяет загружать, просматривать, скачивать и удалять объекты; поддерживаются отдельные ключи доступа, версии объектов и клиентское шифрование.
- Холодный класс предназначен для резервных копий и стоит от 1,25 ₽ за ГБ в месяц. При расчётном пике 12 ГиБ хранение составляет ориентировочно от 15 ₽ в месяц без учёта запросов и исходящего трафика.
- Поддерживаются versioning и Object Lock. Обычный bucket private по умолчанию; для автоматизации рекомендуется отдельный service user и S3 key с узкой bucket policy.
- Наличие cold-класса зависит от региона/pool и может временно меняться; точная российская локация и класс подтверждаются в панели непосредственно перед заказом.
- Selectel S3 не поддерживает bucket encryption через S3 API, но официально заявляет client-side encryption через AWS SDK. Это соответствует требованию проекта шифровать до передачи и не добавляет KMS-зависимость.
- Для первой версии достаточно обычного холодного S3. S3 Vault, аттестованный S3, выделенное хранилище и собственная backup-платформа не требуются.

### 2. Yandex Object Storage — допустимая альтернатива

- Данные российского региона хранятся в нескольких географически распределённых дата-центрах на территории России.
- Поддерживаются S3-совместимый доступ, статические ключи, размер и метаданные объекта, `Content-MD5` и `ETag`.
- Холодный класс стоит 1,267 ₽ за ГБ в месяц; первые 100 ГБ исходящего трафика Object Storage в месяц не тарифицируются по опубликованным правилам.
- Поддерживаются versioning, Object Lock, strong consistency и server-side encryption через KMS; для проекта всё равно предпочтительно client-side encryption, чтобы provider не был владельцем единственного encryption boundary.
- Функционально подходит, но для текущей задачи Selectel проще зафиксировать по конкретной российской локации и остаётся независимым от FirstVDS без дополнительной KMS-службы.

## Рекомендация владельцу

Владелец выбрал Selectel S3, российскую локацию и холодный класс как направление B002. Перед любым заказом отдельно проверяются актуальная цена/доступность cold-класса в панели, квота и service user, затем согласуется минимальный инструмент потокового client-side encryption без временной полной ciphertext-копии на VPS.

Отдельно требуется один архитектурный выбор для B002 zero-ledger:

1. **Выбрано D-1848:** primary genesis остаётся в одном trusted POSIX root, а независимая plaintext-equivalent authority хранится как client-side-encrypted exact-version S3 object с read-back/decrypt/digest proof; текущий two-POSIX-root код меняется только после отдельного security/architecture review.
2. **Без изменения кода:** materialization ждёт production-среду с двумя реально независимыми POSIX filesystems; S3 используется позже только для backup. Это сохраняет код, но не разблокирует real import сейчас.

Не допускаются S3 mount/FUSE как притворная POSIX-authority, второй каталог на том же device, VHD/WSL workaround или хранение ключа рядом с объектом.
