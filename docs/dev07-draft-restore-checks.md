## Область и фактическая опора

Существующий DEV05 фасад `page_versions.services` экспортирует save_owner_draft/cancel_owner_draft, prepare_restore/stage_restore/get_stage/cancel_stage и commit_owner/commit_employee. Изучены реальные engine/restoration и PG/HTTP tests, включая приватность draft, current-based employee commit, stage cancel/terminal replay и current-change invalidation. Эти прежние доказательства не заменяют проверку нового editor bridge/normalizer/proof/session пути.

OwnerDraft — один отдельный текущий draft на Page: UUID, draft revision, immutable public base, payload и refs. Save draft не создаёт ordinary content revision и не меняет current. Основа draft остаётся pinned после employee/current change до явного save/rebase/cancel. RestoreStage хранит actor/generation/Page/source/base/permission binding, а candidate вычисляется из pinned source/current; собственной копии произвольного пользовательского HTML в stage/ledger нет. Stage/view/compare сами не публикуют; только отдельное Save может создать automatic revision.

Новые editor HTTP DTO/URL bindings, checkReceipt для draft/stage, explicit rebase и UX-переходы ещё проходят backend-анализ и root gate. Ниже нет новых маршрутов, TTL, квот, права владельца снимать чужие удержания или правила слияния текстов. Пока unsupported dependency (protected/media/component integration) не готова, она остаётся явной capability-границей, а не fake positive.

## Fixture и доказательство результата

Локальные синтетические owner, назначенный text employee, назначенный price employee, чужой employee и visitor. Две Page, current A/B, различающаяся историческая ordinary/Stable, приватный owner draft-canary, реальные source/base pins. История/Stable/grants создаются существующими trusted APIs; проверяемые действия — реальными HTTP/UI handler, с настоящим producer/PG. Синтетические media — только через фактический upload/worker/READY при отдельной готовности интеграции, без manufactured READY.

До/после читаются actual current/payload hash, ordinary/Stable IDs, draft UUID/revision/base/hash, stage status/source/base/fields, pins, usages, permanent operation receipt и bounded audit. UI/RAM наблюдаются из настоящей исходной вкладки. Опубликованная композиция проверяется только при наличии фактического DEV08 renderer; без него current pointer не выдаётся за браузерную публичную приёмку. Уборка строго по собственным verified IDs, permanent identity/receipt/audit сохраняются.

## Ворота перед test code и уточнения автору

1. Frozen backend DTO/route bindings для owner draft read/check/save/cancel/rebase/apply, stage read/check/save/cancel/result; action-specific receipt bindings/replay/gone и mapping ошибок. Имя proposed endpoint не считается фактическим API до подтверждения root.
2. Уточнение reviewer gate2: checked editor path вправе атомарно применить проверенный отредактированный final snapshot, не требуя равенства final payload и исходного draft payload. Он обязан связать и повторно проверить actual draft id/revision/base/hash; неожиданное изменение этих server данных конфликтует. Legacy commit path остаётся strict, его прежний payload equality не ослабляется. Не вводить скрытый промежуточный draft-save с последующей отдельной публикацией. Rebase proof уже при check связан с отдельным mode и конкретным targetCurrentId; обычный draft proof плюс последний rebase boolean недостаточны. Изменение target current после показанного сравнения даёт409 без auto merge/rebase. Автор ещё должен подтвердить фактические names/DTO/API этого закрытого пути до тестового кода; здесь не угадываются новые параметры существующего engine.
3. Check должен отличать current/owner-draft/restore-stage и проверять реальную основу/допустимую проекцию. Подмена editingFrom только в JSON не должна выбирать чужой draft/stage или неподтверждённый source. При актуализации generation held stage может стать incompatible; собственный RAM сохраняется, а автоматическое новое подтверждение не возникает.
4. Actual editor adapters/entry callbacks и подтверждённые UX состояния подтверждения замены/отмены/сравнения/rebase/terminal/unknown. При неподключённом protected/media integration позитивы ограничены реально поддержанным safe corpus; scoped refusal не закрывает полную функцию.
