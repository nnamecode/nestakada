## Начальные данные и действия

shared-blocks-independent-history содержит настоящие опубликованные header/footer, отдельные draft/draftRevision и минимум по одному совместимому историческому снимку. В нём буквальный синтетический телефон+70000000001 отличается от текущего, в истории есть BLOCK-HISTORY-PRIVATE-{kind}; текущий текст отличается от всех новых canary теста. P-ONE — реальная опубликованная Page с непустым text/историей, её публичный ответ детерминирован для сравнения содержимого блоков и валидатора. S-EDIT назначен на Page, не на общие блоки. Исторический просмотр и сравнение не меняют сайт.

OWNER и OWNER-SECOND — **два собственных браузерных сеанса одного nesadmin**, не введённый второй администратор/новая роль. Оба получают реальную авторизацию одного владельца; аудит отражает фактического пользователя, не имя тестового контекста. Два POST реально отправляются одновременно; драйвер не сериализует их и не вычисляет победителя.

publish-shared-block-direct/save-shared-block-draft/read-shared-block-history-direct/compare-shared-block-version/prepare-shared-block-restore/apply-shared-block-version — внутренние имена тестов. Конкретные URL/ORM/selectors не выбраны. Все проверяемые операции идут через настоящий UI/HTTP с действительным основанием/CSRF/правами; fixture bridge не выполняет бизнес-apply записью БД. apply-shared-block-version может воспроизвести реальную последовательность выбора старого содержимого/подтверждения/явного применения, но не скрыто подменить её серверной записью. Промежуточное состояние block-editor здесь не объявлено проверенным.

В BLOCK-page-restore используется прежний настоящий profile page-history-restore с уже открытым S-EDIT редактором и несохранённым вводом; его двухфазная подготовка/защита от autosave описаны в local-test-adapter.md. Перед restore владелец действительно меняет оба общих блока; проверяется их сохранность после применения старого текста Page. История Page не должна содержать команду отката глобального Header/Footer.

## Наблюдения

После prepare-shared-block-restore и до explicit apply опубликованные revision/currentVersionId/currentHtml/versions обязаны совпасть с before. Другой общий блок сохраняется до и после применения. Поэтому ошибочная публикация на этапе подготовки с последующим accepted-noop не проходит; промежуточные draft/UI стадии здесь не ограничиваются вместо полного отдельного сценария.

shared-block(kind) читает фактические id/revision/draftRevision/currentVersionId/currentHtml/draftHtml/versions[{id,html,...}]. Значимые поля и непустые IDs проверяются до сравнения; текущая версия реально входит в историю. Бизнес-текст/версии не генерируются по expected. Снимок старого блока при восстановлении остаётся неизменным, новый current получает новый ID.

public-with-shared-blocks(P-ONE,ifNoneMatch?) делает настоящий HTTP GET/условный GET, возвращает status/body/etag и фактически извлечённые headerHtml/footerHtml/pageText. Это не копия текущих БД-полей вместо публичной страницы. Локаторы извлечения подтверждаются независимым ревью bindings; текущий canary обязан быть в настоящем публичном представлении. Семантическое сравнение блоков не требует совпадения всего HTML с одноразовыми токенами формы.

Новый безопасный HTML не сравнивается побайтно со строкой POST: инертный DOMParser ищет фактический абзац с независимым canary/text oracle, допуская нормализацию атрибутов/регистра/сериализации. Before/after неизменность и копирование уже канонического совместимого исторического снимка сравниваются по реальным сохранённым значениям. Parser page отдельная, JS=false/SWblock/HTTP+WS abort; она не исполняет содержимое и не заменяет реальное наблюдение UI/CSP. Реальные app contexts сохраняют своё назначение и изоляцию.

shared-block-public-classification читает реальные две общие записи и их публичную классификацию isPage/publicUrl/hasPageSeo/indexedAsPage. Это логические свойства доступа/выдачи, не требование конкретной таблицы Django. Один флаг не заменяет полной проверки всех публичных путей; конкретные observer-источники ещё проходят отдельное ревью.

Имена/значения не являются новым API сайта. Ни один полный AC/TEST-03/TEST-07 не закрывается; конкретных bindings/приложения пока нет и этот файл против них не запускался.
