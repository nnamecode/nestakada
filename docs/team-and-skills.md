## Команда: роли, а не постоянно работающие агенты

| Роль | Задачи | Когда включать |
|---|---|---|
| Координатор — основной агент | План, решения, общение с владельцем, сборка результатов и контроль циклов | Постоянно во время активной работы |
| Аналитик | BRD, требования, состояния, поля и критерии приёмки | BRD и аналитика |
| Дизайнер интерфейса | Варианты десктопа/мобильной версии, компоненты | Этап дизайна |
| Архитектор / разработчик | Архитектура, Django, данные, интерфейс и окружение | Архитектура и реализация |
| QA-инженер | Приёмочные сценарии, e2e, браузеры и содержательные тесты | Аналитика, тесты и приёмка |
| Независимый рецензент | Архитектура, аналитика, безопасность и код | Отдельные ограниченные ревью, не собственные изменения |

Не запускать все роли одновременно. Предложение: обычно координатор + один исполнитель; независимый рецензент по готовому результату. Параллелизм только для независимых задач, максимум три субагента с учётом доступного лимита. Имена ролей не означают, что отдельные постоянные агенты уже созданы. Модель и настройки наследуются от основной сессии, без самовольной смены.

Инструкции ролей созданы в docs/agent-roles.md и привязаны к этапам. Каждый запуск получает ID задачи, границы файлов, ожидаемый результат и правило остановки из AGENTS.md. Отчёт: результат, проверка, нерешённые вопросы; без пересказа всего проекта.
