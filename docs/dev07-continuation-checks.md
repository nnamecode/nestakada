## Общие условия и доказательства

Синтетическая собственная Page с небольшим исходным current, настоящие PostgreSQL/AuthSession/CSRF/права и настоящий child protocol. В framework HTTP допустим известный seam чтения тела, явно обозначенный в отчёте: он не доказывает Nginx/socket admission. Для fault-программы допускается только статический доверенный test-only seam, вызывающий настоящий editor_runtime.processing._exchange. Пользователь не выбирает команду/путь; окружение и секреты child не расширяются. Здоровый положительный контроль использует настоящий продуктовый normalize_input и Check.

Перед и после отказа сравниваются current/history/draft/stage/pins/media usage и content-operation receipts. Не должно быть CheckReceipt, частичной версии, скрытой публикации или удаления файлов. Допустимые bounded denial audit/session counters учитываются отдельно, без ложного требования неизменности всей БД. RAM-ввод сохраняется, автоматических повторов нет.

После каждого process fault: фиксируются только собственный PID/parent relationship, exit/reap и отсутствие живого собственного child, освобождение EditorSlot и успешный отдельный ручной здоровый запрос. Kill/reap не затрагивает чужие процессы. FD/process evidence ограничивается собственным процессом; пароли, cookies, CSRF, proof, raw input/stdout/stderr не попадают в отчёт. Лимиты и исходники до/после неизменны. Ошибка означает FAIL/неподтверждённую готовность, а не разрешение увеличить лимит.

## Согласование с native F1/F2

Визуальные сценарии остаются F07 из технического предложения, без новой нумерации. Для F07-001/002 необходим положительный native nonempty range reset внутри одного slot: полный Unicode и соседние marks/links/anchors/IDs сохраняются, результат проходит настоящий Check/Save/reload. Обычные no-protected caret stored marks и multi-block reset также остаются положительными контролями. Новый отказ empty caret внутри protected slot не превращается в запрет прежнего ordinary caret.

F07-004/005 проверяют root-level p после последнего protected parent либо ordinary p без protected: native split/join, exact text/marks, одна transaction, undo/redo, затем Check/Save/reload. Anchor после split только слева; join несовместимых attrs/anchor даёт целый отказ. Slots сохраняют ранее поддержанный hardBreak. Rapid keys идут без QA sleeps, DOM/PM selection setters или вставленных наблюдений между критическими клавишами. Положительное interior Unicode deletion и отказ protected boundary проверяются отдельно. Это не полная структурная обработка списков/таблиц, slot paragraph split или reparenting.

## FR07-008 — дополнительный entity профиль перед оптимизацией

2026-10-31, отдельное диагностическое разрешение root после нового отказа ENTITY_EXACT. Это дополнение сценариев до исправления parser path, не результат и не замена исторических FR07-001–007. Первый диагностический инструмент — ignored work/dev07-f-20261031/entity-diagnostic.py: настоящий framework Check/PG/child на `<p>` + `&amp;` ×200000 + `</p>` (1000007 raw UTF-8 bytes, 200000 decoded codepoints). Он фиксирует только status/fixed code, реальный child PID/exit/reaped, wall, child user+sys CPU delta и cgroup OOM events. Метка результата DIAGNOSTIC_OBSERVATION; HTTP503 не превращается в acceptance PASS. Никаких изменений лимита, fixture, production endpoint или raw stdout/HTML в отчёте. Запуск только root после ревью/заморозки.

Приёмочные векторы после отдельного parser/test code gate: exact200000 `&amp;` — настоящий HTTP200, exact canonical и verified proof/no mutation; 200001 `&amp;` (1000012B, всё ещё менее1MiB) — 400 INPUT_REJECTED/no proof; escaped `&lt;script&gt;alert(1)&lt;/script&gt;` остаётся безопасным escaped text; `<table> \n<tbody><tr><td>A&amp;B</td></tr></tbody></table>` сохраняет точные whitespace и entity semantics. Векторы проходят owner/assigned employee. Потоковое объединение text tokens не может отбрасывать table whitespace, превращать escaped markup в реальные узлы либо обходить decoded text/source byte caps. Диагностический одноразовый профиль сам эти acceptance-векторы не закрывает.

### Предварительный differential oracle PERF-001–005

До реализации helper, по dev07-parser-performance.md: до30 небольших фиксированных fixtures сравнивают новый parser с отдельным STOCK html5lib.HTMLParser(etree, namespaceHTMLElements=True). Expected tree не получается через optimized helper. Сравнение полное: namespace/tag, sorted attrs, text/tail, порядок детей, затем точные parser.errors (позиция, code, datavars). Никаких HTML/attrs/error datavars в публичном диагностическом отчёте; при расхождении — только fixture ID, часть oracle и фиксированный failure code. Продуктовый отказ unsafe source проверяется отдельно от эквивалентности parser, который сам не является sanitizer.

Закрытые классы небольшого корпуса: empty/plain; entity runs8191/8192/8193/16385; mixed literal/entity; отдельные ASCII SpaceCharacters; space entities/NBSP; CRLF/CR/NFD; numeric decimal/hex/astral/multi-codepoint named entity; escaped script; escaped img/event; double escaping; unknown/missing-semicolon entity; NUL/control replacement; текст до/после inline child и tail; active formatting/adoption; duplicate attrs; malformed EOF attribute; table whitespace; table foster parenting; caption/thead/nested table; SVG/MathML; rawtext/rcdata switching; select/pre; comment/doctype errors; entity attributes; два error-position случая сразу после batch boundary. Максимум30 concrete fixtures фиксируется после фактического API freeze; список не означает уже написанные/исполненные тесты.

Особые критерии: Characters и SpaceCharacters не смешиваются; barrier выдаётся до чтения последующего token; неизвестные phase/foreign/table/rawtext/select/pre идут stock; NUL/errors/EOF не исчезают. Escaped `<script>` остаётся text, а не повторно разобранным markup. Табличные пробелы и error positions не могут быть упрощены ради одинакового plain text. Большой200k performance профиль остаётся отдельным FR07-008/HTTP oracle: маленький differential корпус не доказывает его время/ресурсы и не заменяет caps. Для phase scan/parse/full разрешён отдельный ignored entity-phase-probe.py под прежними384MiB/CPU10/wall20; его phase timings исключают последующий подсчёт/hash oracle и не складываются с inclusive whole-normalize.
