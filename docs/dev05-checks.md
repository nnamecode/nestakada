# DEV-05 — сценарии до реализации

2026-10-31, D-327. Основание: REQ-018–023/059/063, AC-018–023/059/063, AC-MAN-001–003, D-259–262, UI-S007–013, PR-08. Результаты заранее не объявлены пройденными.

Последующее исполнение: ограниченная DEV-05 завершена после 150 общих PG тестов (36 новых), 11 FOUNDATION и 15 Chromium/HTTP групп PASS и независимого ревью. Протоколы, точная граница и неисполненные зависимости — dev05-implementation.md; полный AC этим автоматически не закрывается.

| ID | Независимое ожидание |
|---|---|
| V05-001 | До первой правки есть исходный снимок; успешное сохранение атомарно создаёт новый immutable ID/серверное время/автора и текущую редакцию. Неудача не создаёт частичную историю |
| V05-002 | Лимит:10 ordinary manual+automatic вместе, включая ordinary current, плюс все Stable. Удаляется старейшая допустимая по server savedAt; manualDate1960/2099 не меняет очередь. Current/Stable/используемые основы защищены |
| V05-003 | Контрольная версия владельца копирует показанную currentRevision, не отдельный draft/не body запроса. Ни current/draft/публикация,ни URL/дерево не меняются. Новый снимок ordinary,Stable не наследуется |
| V05-004 | Название≤200/комментарий≤1000/manualDate с явной зоной отдельно; real createdAt/author/sourceRevision серверные. Изменение ручных метаданных не переписывает payload/реальное время/автора |
| V05-005 | Владелец после просмотра назначает Stable только конкретной версии; это не публикация. Employee/visitor/direct forged fields не ставят/не снимают метку. Следующее сохранение ordinary |
| V05-006 | Снятие Stable:актуальное точное подтверждение последствий+повторный текущий пароль. Неверный пароль/устаревшее подтверждение/другая роль отклонены. Исходная дата сохраняется,ordinary-лимит применяется,current не удаляется |
| V05-007 | Удаляется только одна подтверждённая допустимая ordinary-версия. Current/Stable/используемая draft/operation основа защищены. Пропавший ID не означает следующую запись; физических media unlink нет |
| V05-008 | Два одинаковых operationID/параметра дают один результат/аудит. Тот же ID с другими параметрами/действием отклонён. После prune сохраняется consumed/gone,а не повторное исполнение. Replay проверяет текущие права |
| V05-009 | Просмотр/сравнение/prepare/stage восстановления не меняют current. Разрешённые данные подготавливаются для редактора; публикация не происходит одним restore-POST. Применяет отдельное явное сохранение через проверяемый engine API |
| V05-010 | Неизвестная схема/недоступный Asset/несовместимый защищённый компонент дают полный отказ prepare/apply. Исходник/собственный ввод не переписываются; текст можно читать безопасно в пределах доступа |
| V05-011 | Employee видит всю историю назначенной Page,включая manual/Stable; чужая Page/visitor закрыты. Restore использует только текущие права intro/main/price,не распространяет старые права или owner draft |
| V05-012 | Restore владельца возвращает допустимые тексты/прайс/H1/SEO/layout/media. URL/parent/позиция/публикация/HeaderFooter/права/Stable не откатываются ни у какой роли |
| V05-013 | Настоящие ordinary/Stable/current/draft ссылки engine удерживают реальные media-файлы. Prune/delete снимают только свои refs; чужие current/shared/HTML refs остаются; байты не копируются/не переписываются |
| V05-014 | PostgreSQL concurrency:Stable-vs-prune,двойной save/manual receipt,restore-vs-revoke. Есть одна определённая граница; нет двойной версии/потерянной защиты/мёртвых ссылок |
| V05-015 | Техническая схема закрыта/версионирована. Веб-формы не дают произвольного payload writer; история отображается как экранированные данные,не Django/Python/JS. GET не создаёт контентную историю |
| V05-016 | Историческое изображение доступно назначенному сотруднику только через Page+Revision+связанный Asset. Чужой fileID/private source не выдаётся. Физические SHA/nosniff/private-no-store проверяются |
| V05-017 | Отдельный owner draft закрыт от employee/history-копирования; employee save берёт публичную current,а не draft. Устаревшая база не объединяется автоматически |
| V05-018 | Ошибки записи revision/AssetUsage/ledger/audit откатывают весь content commit,не теряя прежнюю current/защищённые снимки. Сбой не считается успехом |
| V05-019 | Серверные UTC instant и автор отделены от manualDate; показ времени в Europe/Moscow проверен по обе стороны полуночи. Часы Windows/VPS не меняются |

Engine/PG/FS проверки вызывают настоящие команды и модели; синтетический исходный контент/аккаунты допустимы как fixture. HTTP/UI тесты проверяют реальные manual/Stable/delete/history/prepare/stage,а не SQL вместо этих действий. Полный rich-редактор,несохранённый пользовательский ввод вкладки,публичный renderer,Header/Footer и Page/tree/URL публикация относятся DEV-07/08/29 и этим модулем не имитируются. Полные исторические e2e из version-time/storage/editor-* не объявляются пройденными наличием новых частичных проверок.
