# Локальная подготовка основы: результат и остаток

**Актуальная поправка D-315:** локальные runtime заменены проверенными сборками из [итога исправлений](base-image-security-remediation.md). В текущем наборе psycopg[c]3.3.6/system libpq17.11, PostgreSQL18.6 без SQL XML/XSLT и минимальный Nginx1.30.6. Ниже сохранена историческая версия соответствующего этапа; источники исходных образов не являются текущим runtime-lock. Код сайта по-прежнему запрещён.

**Продолжение D-313: HTTP-проблема исправлена отдельным согласованным Nginx. Ниже сохранён результат первоначальной подготовки D-312.** [Реальные результаты](local-foundation-proxy-check.md). Остаток безопасности не закрыт.

2026-10-30. Основания: D-310 — поэтапный порядок; D-311 — версии и проект схемы; D-312 — разрешение получить артефакты и выполнить локальный preflight. Код сайта, DEV-02/DEV-28, старый сайт и VPS этим не разрешались и не изменялись.

**Артефакты подготовлены, но полный локальный допуск ещё не получен.** Проверки импортов и БД прошли. Предложенная публикация HTTP из единственной internal-сети не работает в текущем Docker. Системные advisory требуют отдельного разбора применимости. Нельзя считать приложение безопасным или готовым к реализации по одним успешным импортам.

## Что подготовлено

- `environment/foundation/images.lock.json`: официальные index и выбранные linux/amd64 manifest digest. Скачаны именно выбранные manifests Python и PostgreSQL; фактические config image IDs записаны отдельно в локальные свидетельства. Производный образ приложения не создавался.
- `environment/foundation/requirements.lock`: 7 точных Python-зависимостей с SHA256 конкретных Linux-совместимых wheels. Прямые версии совпадают D-311; транзитивные — asgiref 3.13.0, packaging 26.3, sqlparse 0.6.0. Hash каждого артефакта сверялся с metadata PyPI; установка выполнена offline с `--require-hashes` из скачанных wheels.
- `scripts/foundation-artifacts.py`: инструмент получения/проверки артефактов и библиотечного smoke. Не создаёт приложение, Django-проект или его настройки. Фиксированные временные Django settings существуют только в памяти процесса smoke.
- Локально в `work/foundation-preflight-20261030/`: wheels, установленный набор runtime, сведения о лицензиях, Python CycloneDX 1.6, инвентари ОС, raw manifest/inspect и результаты проб. Всё вне Git.
- Две независимые preflight-области dev/test: свои internal-сети, тома PostgreSQL и три разных секрета bootstrap/migrator/runtime. Это испытательные области, не полноценное готовое окружение приложения. Файлы секретов имеют отдельные Windows ACL для владельца и SYSTEM; значения не выводились и не добавлялись в Git.

Загрузка выполнялась отдельно от runtime-проверок и без секретов БД. Вспомогательные smoke-процессы работали без повышенных capabilities. Runtime-проба получала только свой readonly пароль, не bootstrap/migrator или секреты соседнего окружения. На подготовительном шаге pip работал внутри одноразового контейнера; системные Python/PATH/службы Windows не менялись.

## Проверка advisory и её ограничения

1. Для семи точных Python-distributions PyPI metadata вернул пустой список vulnerabilities; yanked-артефактов нет. Это узкая проверка известных PyPI advisory на момент подготовки, не обещание отсутствия уязвимостей.
2. Сняты инвентари 87 binary-пакетов Python-образа и 145 — PostgreSQL-образа. Публичный Debian Security Tracker скачан без отправки нашего инвентаря. Сопоставлены Debian source package versions для trixie; исправленные версии сравнивались `dpkg --compare-versions`.
3. Получено **190 совпадений по 118 идентификаторам Debian advisory: 114 CVE и 4 TEMP**. По состояниям совпадений: 188 open и 2 undetermined. По полю urgency: 81 unimportant и 109 not yet assigned; у 95 совпадений Debian есть комментарий об отложенном исправлении/незначительности. **Это не 190 подтверждённых эксплуатируемых уязвимостей и не 190 безопасно закрытых записей.** Требуется разбор применимости; общая оценка «чисто» не выставлена.
4. Например, PAM CVE-2025-8941 отмечена Debian как undetermined; это не разрешено молча считать исправленным. Для zlib и libxml2 также остались записи без оценки urgency/отложения; диапазоны upstream и backports требуют проверки. Не выполнялись произвольные exploit-проверки и обновления базовых образов.
5. Сравнение Debian не заменяет аудит CPython из /usr/local, PGDG PostgreSQL и libpq/OpenSSL внутри psycopg-binary. Python CycloneDX содержит только Python-библиотеки; он не является полным SBOM ОС/нативных библиотек. Их inventory и проверка нужны отдельно до допуска основы/выпуска. Лицензии wheels сохранены, но полный аудит лицензий нативных компонентов не объявлен завершённым.

Первичный разбор по поставщику записан в `debian-triage.json`: 52 уникальные записи поставщик относит к unimportant, у 54 есть отложенное исправление/пояснение, 12 оставлены на явную проверку применимости. Это классификация, не автоматическое разрешение рисков. Для текущих синтетических проб нет пользовательского ввода и бизнес-данных; такой вывод не переносится на будущий сайт.

Дополнительно фактически прочитаны OpenSSL 3.5.8 и libpq 18.6 внутри psycopg-binary; имена 15 поставляемых native-файлов сохранены в `evidence/bundled-native-versions.json`. Версии всех остальных библиотек и полный upstream-аудит ещё не закрыты. В реальном pg_hba.conf собственного dev-стенда host-аутентификация — SCRAM, PAM не используется; это уменьшает применимость PAM-проблемы к проверенному пути, но не превращает vendor undetermined в resolved. PostgreSQL-образ содержит libxml2: будущий доступ к XML-функциям и применимость его advisory нельзя оценить как отсутствующие только из-за отсутствия страницы XML в сайте.

Источники: [Debian Tracker](https://security-tracker.debian.org/tracker/), [PAM CVE-2025-8941](https://security-tracker.debian.org/tracker/CVE-2025-8941), [PyPI JSON API](https://docs.pypi.org/api/json/). Локальные детали: `artifacts.json`, `python-components.cdx.json`, `*-os-packages.tsv`, `debian-audit.json` внутри work. Raw tracker около 87 MB остаётся вне Git.

## Независимое ревью

`foundation_preflight_review` независимо пересчитал SHA256 всех 7 wheels, сверил manifests/locks и фактические свидетельства импортов, pip check, runtime-проверок, persistence и выключения. Существенных замечаний к инструменту и границам TEST-Q008 нет. TEST-R066: статистика Debian первоначально называла все advisory CVE, хотя четыре идентификатора имеют тип TEMP; формулировка исправлена. Безопасность приложения и новый вариант сети этим ревью не объявляются проверенными.

## Ошибки подготовки и исправления

- Первая попытка импорта была запущена до завершения процесса установки: pip уже вывел installed, но ещё перемещал файлы в bind-каталог. Получен ModuleNotFoundError. Повтор выполнен только после exit 0 процесса и появления отсутствовавшего файла django/conf/__init__.py; прошёл. Успешный результат не скрывает первую ошибку.
- Проверка принадлежности тома перед пересозданием сначала ошибочно зависела от порядка Mounts. Guard остановил действие до удаления. После чтения inspect проверка исправлена на поиск точных type/name/destination и label; выполнено успешно. Тома не удалялись.
- HTTP-публикация не работает в исходной схеме. Повтор эквивалентного host-запроса не делался; Docker inspect и внутренний GET подтвердили причину. Предлагаемое изменение вынесено отдельно в TEST-Q008, не применено.

Новые obразы Nginx не скачивались, конфигурация прокси не создавалась. Коммита/push не было; прежние изменения рабочей копии сохранены.
