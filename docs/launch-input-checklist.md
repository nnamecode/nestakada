# Чек-лист внешних входов запуска

Статус D-1009, 2026-11-14. Этот список преобразует восемь внешних входов D-1008 в короткие owner-facing gates. Он не разрешает deployment, не включает формы/аналитику и не требует выбирать необязательные сервисы заранее.

Базовый профиль первого публичного запуска: заявки и сбор ПД выключены, SMTP/Telegram/аналитика/внешние виджеты не подключены, DEV-26/27 остаются отложенными. Поэтому условные пункты не блокируют этот профиль сами по себе.

## Что не нужно выбирать сейчас

- MAX и Telegram URL: отсутствующие ссылки не публикуются.
- SMTP: не нужен, пока intake выключен.
- Аналитика, consent manager, YouTube и виджеты: остаются выключенными.
- DEV-26/27 runtime fallback: остаётся отложенным по D-923.
- Новая CRM, личный кабинет, API, чат, очередь или monitoring platform: не входят в этот чек-лист.

## Порядок закрытия без раздувания

1. Сначала `LAUNCH-IN-007`, потому что точные рекламируемые URL ограничивают migration/publication, но не требуют доступа к серверу.
2. Затем read-only `LAUNCH-IN-002`, чтобы зафиксировать фактическую production-среду до конфигурационного плана.
3. Вместе выбрать минимальные `LAUNCH-IN-005` и `LAUNCH-IN-006`; не строить собственные backup/monitoring платформы.
4. `LAUNCH-IN-003/004` закрывать только перед включением заявок и ПД.
5. `LAUNCH-IN-008` остаётся последним явным разрешением; оно не выводится автоматически из готовности остальных строк.

Текущий результат: базовый профиль не блокируется отсутствием необязательных контактов, SMTP или аналитики, но production release всё ещё закрыт обязательными `LAUNCH-IN-002`, `005`, `006`, `007`, `008`.
