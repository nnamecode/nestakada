# DEV07-SID — смена пользователя в выбранном черновике/восстановлении

2026-11-01. Продолжение после DEV07-RUI по поручению владельца «давай дальше». Ограниченные браузерные проверки существующих D07-022/023/024, V07-008, REQ-015/017 и DEV07 contract §4. Новые правила, инструменты, DTO, права, TTL и действия не вводятся. Код сайта меняется только при подтверждённом дефекте с отдельным техническим ревью исправления.

| ID | Действие и ожидаемый исход до кода |
|---|---|
| SID-001 | Owner сохраняет отдельный приватный draft, открывает именно selected owner-draft и проверяет новый собственный текст. В другом окне того же BrowserContext выполняет настоящий logout/login employee. В исходной вкладке явный Check обнаруживает другого actor до отправки editor payload: terminal identity lock, доступные DOM/initial JSON/активные intent/proof очищены, контролы выключены. Ни Check, ни Save/draft не отправляют прежний текст. Server draft/current/history/pins/receipts неизменны |
| SID-002 | Employee явно готовит и открывает собственный stage, правит текст и получает proof. После настоящего logout/login owner в том же BrowserContext нажатие Save в старой вкладке обнаруживает смену actor до POST. Нет использования owner-прав для чужого stage, payload не отправлен, локальные доступные копии очищены. Stage остаётся held с прежними pins/current |
| SID-003 | В выбранном owner draft выполняется настоящий Draft update: route.fetch доводит его до реального commit200, затем ответ обрывается. Исходная вкладка показывает неизвестный исход и manual retry. После logout/login другого actor явный retry обнаруживает смену пользователя, не отправляет второй editor write, очищает неизвестное локальное намерение/proof/доступные копии. Исходная одна server revision draft и её durable receipt сохраняются; смена пользователя не откатывает commit |
| SID-004 | В выбранном owner draft есть свой несохранённый текст. После настоящего logout собственная сессия недоступна, текст остаётся в исходной вкладке. Настоящий login того же owner с прежней generation создаёт новую сессию/CSRF; явное «Войти снова» перепроверяет identity/права и ничего не сохраняет. Только отдельные новый Check и Save применяют retained RAM к прежнему разрешённому draft basis. Проверить новый Check/proof и текущий CSRF, отсутствие autosend/hidden retry и один явный commit |

До/после сравниваются реальные current/history/draft revision/base/hash, stages/pins, receipt-inclusive domainHash и VERSION audit. Все editor POST-пути наблюдаются, включая check/save/draft/cancel/embedded issue; auth POST разрешены только как явно подготовленный logout/login. Нельзя подменять настоящий actor ответом route.fulfill. Старый приватный canary не пишется в отчёты/скриншоты/логи; при необходимости диагностические значения остаются в RAM тестового runner. Только фиксированные коды/булевы результаты/безопасные ID.

Проверяются очистка DOM/initial JSON/доступных активных handles и прекращение отправки payload, не физическая zeroization heap. Наблюдение не должно удерживать исторические копии, которыми приложение уже не владело, и выдавать их за активную утечку. Не добавлять setter/reset endpoint для прохождения теста. Same actor SID-004 — новое session/CSRF при прежней generation; полная новая generation, current/grant changes, late-body/preflight/FS races, медиа/MAX и другие браузеры остаются отдельно.

Техническая опора: существующий editor-bridge.session сначала читает настоящий /manage/session/, затем metadata state с текущими правами, и только после проверки actor делает editor POST. Старые current-only EH005/EH010/EH012 не подменяют новые selected-source доказательства. Использовать неизменную RST fixture713b… и прежний approved Chromium/Nginx/Docker профиль; новые только probe и host. Product source предыдущего RUI не меняется до actual finding. Старый сайт/VPS не трогать; DEV-07 около 98%, этап 8 около 20%.
