Существующие 29 media e2e не объявляются пройденными. Docker и зависимости исполнитель не запускает; миграции/интеграция/фактические результаты и независимое ревью остаются координатору.

## Границы реализации

Служебные Python API — доверенная внутренняя граница, не публичный ввод и не система прав редактора. Общий CONTENT_LOCK предшествует auth lock и row locks. Модельные bulk-изменения запрещены; внутренние SQL/служебные обходы ORM не объявляются защитой от администратора БД.

Рабочий корень по умолчанию `/var/lib/estakada/media`; `MEDIA_LIBRARY_ROOT` служит доверенной настройкой интеграции и временным корнем тестов. Разрешённые пространства — `img/` и `private/sources/`. Файловые операции обходят каталоги через dir_fd/O_NOFOLLOW, запрещают symlink и hardlink файлов, создают только O_EXCL; существующие ключи не перезаписываются. Конфигурацию корня, резервные копии и исходный архив cleanup не меняет. Защита рассчитана на сервис и непривилегированные внешние входы; администратор ОС, одновременно переставляющий сам корень, не объявляется изолированным противником.

Подтверждение подписано Django, связано с владельцем/поколением/ID и точными фактическими файловыми manifest. После повторной проверки refs и байтов DELETING фиксируется отдельной транзакцией до unlink. Новые refs к DELETING/DELETE_FAILED запрещены. Метаданные оставшихся/уже удалённых файлов сохраняются до полного завершения; retry не выдаёт отсутствие файла за вновь освобождённые байты. Ошибка не превращается в нулевой pending. Автоочистки по возрасту нет.

После финального удаления Asset/AssetFile остаются минимальные резервации UUID и server key: старый публичный адрес не получает новые байты после очистки. В них нет исходников/учётных данных; они занимают служебное место и не очищаются этим cleanup. Одновременные physical retry разделяет PostgreSQL session advisory try-lock конкретного Asset; CONTENT_LOCK/auth/row locks не удерживаются на время unlink.

Адресные REV001/REV002: после каждого mkdir выполняется fsync содержащего каталога до перехода в новый каталог. Ошибка producer сохраняется первичной, даже если частичный leaf исчез; иной inode не удаляется. Отсутствие корня/промежуточного каталога — MediaParentUnavailable и pending с сохранением DB-описания; только ENOENT leaf после успешного открытия родителя означает already_absent. Добавлены реальные FS syscall-sequence, missing/replaced partial-write leaf, rename родителя после DELETING с retry после возврата, а также отдельный missing-leaf case. Эти проверки исполнитель не запускал; миграция 0001 не изменялась.

Дополнительно Events фиксируют одновременный второй physical retry: try-lock отвергает его, unlink вызывается один раз и released_bytes учитываются единожды. Отдельный реальный rename всего рабочего корня также проверяет отличие недоступного storage от отсутствующего leaf. Всего подготовлено 22 проверки, фактическое исполнение остаётся координатору.

Результаты исполнения пока не получены. Сбой процесса во время первоначальной записи может оставить неучтённый файловый остаток; автоматического сканирования/удаления таких остатков этот ограниченный пакет не вводит. READY требует повторной проверки всех зарегистрированных файлов; upload/worker должен завершать запись и валидацию до вызова READY.
