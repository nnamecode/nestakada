## Исполнение и границы артефактов

Подтверждённый контракт подготовки: work/dev07-package-cache/js/project/{package.json,pnpm-lock.yaml,pnpm-workspace.yaml,node_modules/}; Python wheels в work/dev07-package-cache/python/wheels, lock в python/requirements.lock и environment/editor-package/requirements.lock; candidate recipe environment/editor-package/App.candidate.Dockerfile. Идентификатор производного image задаёт root после сборки, не выбирает QA.

Для JS root предоставляет readonly /deps (js/project с package.json и node_modules), /qa (tools/editor_package) и прежние approved Playwright modules отдельно; /output — writable work/dev07-package-cache/qa, заранее созданная root. QA-only entry компилируется из строки esbuild stdin в фактический файл /output, который затем действительно читает браузер. Новые каталоги QA не создаёт. Результаты bundle/HTML/screenshots/JSON синтетические, не production assets.

Python probe использует стандартные unittest/JSON, subprocess и Linux wait4/resource для фактического RSS/elapsed. Координатор подтвердил QA-only10секунд на child и512МиБ RLIMIT_AS; outer Python/JS runner1ГиБ/2CPU/network-none без секретов. Это контроль оснастки, не новый серверный лимит/новое бизнес-правило. Для допустимых положительных corpora timeout/error означает проблему кандидата; controlled refusal/pathological timeout фиксируется отдельно и не выдаётся за доказанную производительность. Первое падение останавливает набор, retries нет.

Ни download/install/network/Docker, ни реальные импорты кандидатов/браузерные запуски этот QA-исполнитель не выполняет. Root запускает только после frozen hashes/артефактов и независимого ревью. Source-когорта — tools/editor_package/probe.py и probe.mjs; prepare.mjs/recipes/locks принадлежат исполнителю и не меняются QA.

До подключения ещё обязательны: реальный product parser с ранними бюджетами/политикой/целиковыми отказами, явная Word normalization confirmation, pin/rights/receipts DEV05, безопасный client paste/HTML-mode handoff, доверенные Asset/component nodes, CSP/body отдельно, полноценные Header/Footer и фактическая product HTTP/PG/FS/e2e приёмка.

## Адресные security-регрессии до первого запуска

Root/reviewer установили actual ammonia4.1.4 в wheel nh3; локальные первичные advisory JSON — work/dev07-20261031/RUSTSEC-2021-0157.json, RUSTSEC-2021-0158.json, RUSTSEC-2026-0373.json. Их upstream PoC используются как исходные данные, не подменяются безопасным упрощением. Исследуемая конфигурация clean явно исключает style и SVG; filter_style_properties не вызывается. Отсутствие dangerous output при таком профиле не исправляет upstream и не разрешает использовать потенциально затронутый CSS/SVG путь. Будущий producer обязан отказать исходной опасной строке до дополнительного cleaner.

Прототипная регрессия вызывает настоящую экспортируемую mergeAttributes выбранного core в браузере, записывает SHA фактического function source и проверяет обычный positive результат. Advisory range неоднозначен; вывод о пригодности не делается до actual результата и независимого ревью. Markdown-пакета в выбранном графе нет и ради этой пробы он не добавляется.

Первый фактический JS-прогон: PKG-JS-001/002/009 прошли, CSP-violations0, затем PKG-JS-010 FAIL. Причина — избыточное ожидание QA удалить собственный __proto__ key. Root и независимый рецензент прочитали actual core/src/utilities/mergeAttributes.ts: upstream фикс использует Object.defineProperty для безопасной data property вместо prototype setter. Согласованная адресная коррекция oracle требует собственного value без get/set, обычного prototype результата, отсутствия наследуемого canary/глобальной мутации и сохранения обычных атрибутов. Небезопасное прежнее result[key]=value по-прежнему провалит эту проверку. Код/версия пакета не менялись; первый FAIL сохраняется отдельным артефактом до одного повторного запуска root с новым oracle. Report использует safeOwnDataProperty и фактический function source SHA, а не ошибочное jsonOwnProtoIgnored. Python12PASS относится к отдельному первому прогону, Python-программа этой коррекцией не менялась. Это не проверка допустимости произвольных атрибутов в будущем product producer/DOM.
