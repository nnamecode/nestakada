## 2. Редактор, история и структура

### UI-S002–UI-S006: редактор и конфликт

```text
Страница: {название}                     Адрес: {точный URL}
Состояние: Опубликовано / Есть неопубликованные изменения

Ваш ввод                               Актуальная редакция
{введённый текст}                       {текущий разрешённый текст}

Страница уже изменена.
Сравните правки с актуальной редакцией.

[Сравнить]  [Открыть актуальную редакцию]  [Отмена]
```

На конфликте сайт и история не меняются. Ввод остаётся только в памяти открытой вкладки. «Открыть актуальную редакцию» не выбрасывает прежний ввод молча: сравнение/выбор остаются доступными, перенос делает пользователь. Сохранение после переноса — явное.

Истечение сессии меняет сообщение на «Сессия завершена. Войдите снова, чтобы продолжить» с отдельным входом; нового сохранения после входа автоматически нет. При отозванном праве — «Нет доступа к этому действию», без подгрузки закрытых данных. Вход другим пользователем не даёт права сохранить прежний ввод. Пароли не возвращаются в поле/журнал. Кнопки сотрудника и владельца различаются по уже принятой матрице.

Успех именует фактическое действие: черновик сохранён либо разрешённое содержимое опубликовано. Ошибка версии/Asset/публикации не получает сообщение успеха. Неопределённый результат выясняется по исходной операции, а не повторяется как новое действие без проверки.

### UI-S007–UI-S013: версии, ручной снимок, Stable

```text
Сохранённые версии                  Обычные: {n}/10  Stable: {n}
{ID} {тип} {реальная дата} {автор} [Текущая] [Stable: текст+цвет]
{пользовательское имя/дата — отдельно, если заданы}

[Просмотреть] [Сравнить] [Восстановить]
Только владельцу: [Создать контрольную версию]
                 [Назначить Stable] / [Снять Stable]
                 [Удалить выбранную версию — когда допустимо]
```

Ручная версия:

```text
Создать контрольную версию
Источник: {страница, URL, ID опубликованной редакции, дата}
Будет сохранена копия опубликованной редакции.
Черновик и несохранённый ввод не сохраняются.

Название          {обычный текст}
Дата для подписи  {пользовательская дата, не серверное время}
Комментарий       {обычный текст}

[Отмена] [Создать контрольную версию]
```

Источник показывается до действия; смена currentRevision требует нового просмотра. Копия обычная, Stable не наследуется. Снимок не публикует draft/ввод и входит в общий обычный лимит. Успех связан с ID реально созданной версии, не с номером строки списка.

Восстановление сначала показывает сравнение, затем отдельно подтверждает замену несохранённого ввода и подставляет разрешённые поля в редактор. Сайт меняет лишь последующее явное сохранение. Защищённые URL/родитель/позиция/публикация/права/Stable/общие блоки не откатываются вместе со страницей. Несовместимость — целый отказ с безопасным списком причин; нет кнопки «восстановить всё равно частично».

Удаление обычной версии показывает её ID, тип, автора, реальные и пользовательские даты, зависимости. Stable/current/используемая основа недоступны удалению. Изменившееся состояние даёт актуальную причину, не удаляет соседнюю строку.

Назначение Stable не публикует версию. Снятие — отдельное окно только nesadmin:

```text
Снять Stable с {точный ID / дата / автор}?
Версия станет обычной с прежней датой и может выбыть по лимиту.
Текущая публикация не удаляется.
Повторный пароль владельца: {скрытый ввод}

[Отмена] [Снять Stable]
```

### UI-S014–UI-S019: адреса, скрытие, удаление

Новый адрес предлагается до первого сохранения. Коллизия показывается у поля; молчаливый суффикс не добавляется. Переименование/перенос не меняют сохранённый URL. Для разрешённой поздней смены показываются A → B и актуальные прямые редиректы на тот же ID. Защищённые старые рекламные адреса не предлагаются к замене.

Скрытие родителя предупреждает, что опубликованные дети сохранят свои адреса/флаги и останутся доступны; это не удаление и не скрытие поддерева. Родитель с любым ребёнком не может перейти к подтверждению удаления.

```text
Удаление страницы
Название / точный URL / ID: {показанный объект}
История: {обычные} обычных, {Stable} Stable
Редиректы: {актуальный список}
Общие файлы других объектов сохранятся.

Будут удалены эта страница и вся её история, включая Stable.
Настроенная главная автоматически изменяться не будет.
Повторный пароль владельца: {скрытый ввод}

[Отмена] [Удалить показанную страницу]
```

При изменении ребёнка/истории/защиты/редиректов после подготовки требуется новое подтверждение. Неопределённый/незавершённый протокол не выдаётся за завершённое удаление. Предупреждение «Источник удалён. Проверьте главную отдельно» показывается только владельцу; ни состав главной, ни её ночная публичная копия из-за этого автоматически не переписываются.

## 3. Медиа и общие блоки

UI-S020–UI-S023 / UI-S057 дополняют прежний выбор серверных файлов/папок. Замена показывает конкретный материал и место, старое/новое изображение и кнопку «Заменить здесь». Нет действия «заменить везде», записи поверх исторических байтов или автоматического переноса папки из-за нового заголовка.

Очистка показывает список/объём/актуальную проверку использования. Перед удалением ссылки пересчитываются; новая ссылка/Stable/HTML-резерв защищают файл. Пропавшая последняя ссылка делает файл кандидатом ручной очистки, а не немедленно удаляет его. Отказы загрузки/формата/размера видны у файла; прежнее состояние цело.

Header/Footer имеют отдельные текущую редакцию, draft и историю; в сравнении виден буквальный старый телефон/ссылка. Применение страницы не публикует другой общий блок. Нельзя заменять проектный предел истории общих блоков правилом «10 версий Page», очищать защиту или исполнять произвольный код.

## 4. Обе формы: главное для посетителя

Ниже подписи/компоновка для главной и contacts одинаковы по смыслу, сохраняют принятый публичный вид. Реальные правовые тексты/реквизиты и контактный номер **не выдуманы**: до LEGAL-01/CONTACT-01 только синтетическая локальная демонстрация, реального приёма нет.

### UI-S024–UI-S027: исходная форма, ошибки, принято

```text
Заявка на запись

Имя *                      {ввод}
Телефон *                  {ввод +7 / 8}
Автомобиль — необязательно  {ввод}
Комментарий — необязательно {ввод}

[ ] {отдельное согласие с утверждённым текстом и ссылкой}
[Отправить заявку]

Ошибка, если есть:
Проверьте отмеченные поля.
{конкретная подпись возле каждого ошибочного поля}
```

Поле согласия не предвыбрано. Пределы/нормализация берутся из принятого TECH-01, не из нового макета. Во время отправки — «Проверяем отправку…». Блокировка кнопки только UX; серверная защита от дублей обязательна.

Только после согласованной записи заявки и доказательства: «Заявка принята», без полей обращения/внутреннего ID, без обещания времени ответа. Новое обращение начинается отдельным явным действием; повтор старого результата не создаёт новую заявку.

### UI-S028–UI-S032: потерянный ответ, конфликт, срок и защита

```text
Не удалось подтвердить отправку.
Данные остаются в форме. Повторите попытку или позвоните нам.

[Повторить попытку] [Позвонить]
```

Повтор использует **прежнее намерение**, не создаёт новый ключ автоматически. Сообщение не утверждает, что ранее ничего не было записано.

- Иной payload принятого intent: «Эта отправка уже обработана с другими данными. Новая заявка не создана». Исходник не выводится/не переписывается.
- Истёкшая защита: «Срок защиты отправки истёк. Обновите форму и проверьте данные перед повторной отправкой». Ввод в исходной вкладке, новый POST только явно.
- Смена CSRF: «Защита формы обновилась. Проверьте данные и повторите отправку». Актуальная защита и явный повтор того же намерения, не обход CSRF ради receipt.
- Исчерпание приёма: «Сейчас отправить новую заявку не удалось. Попробуйте позже или позвоните нам». Действующие receipt не удаляются ради новых; новая отправка не получает ложный успех.

Окна 30 минут/24 часа — параметры защиты/распознавания повтора, **не срок реакции владельца**. Не создаются новые endpoint-адреса или альтернативные приёмники форм. Значения/токены не уходят в URL, ТГ/почту/Метрику/localStorage.

### UI-S033: форма в ночном HTML

Страница выглядит как принятая обычная копия сайта. **Баннера «сайт сломался/резерв» нет.** После отправки:

```text
Для записи позвоните нам: {проверенный номер из снимка}
[Позвонить] [Вернуться к странице]
```

Не показывать «Заявка принята» и не утверждать, что предыдущая неопределённая отправка не принята. Не сохранять данные постоянно в браузере/новом приёмнике и не повторять POST автоматически после возврата движка. Без JS предусмотрен такой же нейтральный исход на серверном пути резерва.

## 5. Заявки и сотрудники

UI-S034–UI-S039: список со статусом/датой/ответственным; владелец видит все, сотрудник только назначенные. Открытие карточки статус не меняет. Исходные данные read-only; заметки/автор/дата отдельно, исправление новой заметкой.

```text
Заявка {внутренний ID, только закрытый интерфейс}
Статус: Новая                 Ответственный: {текущий}
Исходная заявка: {неизменяемые данные}
Рабочие заметки: {отдельные записи с автором/временем}

[Взять в работу] [Завершить] [Отменить]
Владелец: [Назначить ответственного] [Удалить заявку]
```

Доступные кнопки следуют принятой таблице статусов; Новую можно сразу завершить/отменить. Закрытая возвращается только в работу после актуального «Вернуть эту заявку в работу?». Дата поступления/ID/история не сбрасываются.

Отключение сотрудника показывает затронутые открытые заявки: они перейдут nesadmin с прежними статусами/историей; закрытые сохранят историческое назначение. Включение не возвращает назначения автоматически.

Удаление — одна конкретная заявка/рабочая история/заметки, без корзины, с актуальным составом/повторным паролем. Нет окончательного успеха без долговечной защиты от возврата из бэкапа. Правовое обращение/доказательства согласия и retention закрываются LEGAL-01, а не кнопкой обычного удаления.

## 6. Логи: прочтение и частичное удаление

UI-S040–UI-S043: точное число событий внутри категории, 999+ только сокращение значка; группировка не уменьшает количество. Открытие не отмечает. «Отметить просмотренными до {граница}» не захватывает новые события и не означает техническое восстановление.

```text
Удалить логи категории {одна из девяти}
Период / верхняя граница: {подтверждённый срез}
События: {точное число}        Группы: {число}
БД: {состав}                  Файлы: {байты / отметка оценки}
Новые события после границы останутся.

[Отмена] [Удалить подтверждённый набор]
```

После неполной физической стадии:

```text
Записи удалены, очистка файлов не завершена
БД: {фактический результат}    Файлы: {остаток, не ложный ноль}
Операция / граница: {тот же ID / состав}

[Повторить очистку этой операции] [Открыть сведения]
```

При неизвестном коммите — «Результат операции ещё не подтверждён» и проверка той же операции. Нет нового удаления «всего на сейчас». Ни очистка/просмотр, ни пустая категория не закрывают critical/recovery; обычная отметка просмотра остаётся отдельной. Аудит операции находится вне удаляемого набора, общая квота не обходится временным файлом.

## 7. Резервирование и восстановление

UI-S044–UI-S048 показывают раздельно **полные точки 7 внешних/2 локальных** и **2 исправных ночных HTML-набора**. «Файл загружен» не равен «копия проверена». Неизвестное состояние — «Не проверена»/«Источник недоступен», а не успех или нулевой размер.

В этом дополнении не вводится новая ручная команда создания полных копий: список/сведения/подготовка восстановления дополняют принятую автоматическую схему. Если нужная ручная кнопка уже предусмотрена окончательной архитектурой, она показывается по её контракту; предлагаемая компоновка не расширяет бизнес-объём.

```text
Восстановление выбранной полной точки
Точка / дата / источник / состав: {конкретные данные}
Проверка комплекта: {результат}
Защитная копия перед восстановлением: {подтверждённое состояние}
Защита удалённых данных и старых сессий: {состояние}
Повторный пароль владельца: {скрытый ввод}

[Отмена] [Подтвердить восстановление выбранной точки]
```

Safety/break-glass при отсутствии protective-копии следует принятой внешней процедуре, без нового «восстановить всё равно» по одному клику. Во время выполнения показываются этапы/подтверждённый результат; timeout не даёт успех.

Если админка не работает, её экран не изображается доступным: владелец использует заранее сохранённую **внешнюю инструкцию**, не зависящую от Django/БД. Конкретные команды/способ доступа определяются ARC-09/10 отдельно; публичный backdoor/восстановление по email не добавляются. Сроков обязательной реакции владельцу нет.

### UI-S049–UI-S051: публичные ответы

Обычный допустимый ночной HTML выглядит как идентичный принятый публичный сайт, без признака аварии. Его старые публичные цены/ссылки сами по себе допустимы D-300. Удалённый собственный адрес при этом 404; скрытый существующий — пустой белый 200 без обвязки/черновика. При отсутствии пригодного резерва — лёгкая контактная страница **503**, а не фальшивый обычный 200; нейтральный контактный текст/реальный номер без технических подробностей.
