# Дата ручной версии и серверное время: частичные AT-059/703

2026-10-30. Только приёмочные утверждения этапа7 по D-301/D-302/D-308. Основания: REQ-059/AC-059, TECH-01, analytics-manual-operations.md/AC-MAN-003. Приложение/системные часы Windows/старый сайт/VPS не меняются.

`acceptance/version-time.spec.js`:4экземпляра. Два серверных момента по обе стороны московской полуночи (20:59:30Z/21:00:30Z) и две пользовательские даты —1960/2099. Ручная дата сохраняется отдельно; реальный автор берётся из авторизованного владельца, savedAt — из серверного момента операции. Десять обычных версий/две Stable проверяются до действия; создание одиннадцатой обычной вытесняет старейшую допустимую по savedAt, сохраняя current и все Stable, включая новый ручной снимок с пользовательской датой в прошлом. Текущие опубликованные данные и черновик не изменяются.

## Контракт будущей fixture и наблюдений

`manual-version-clock-boundary({nowUtc})` создаёт собственную синтетическую страницу с10обычными/2Stable версиями, уникальными реальными savedAt обычных до nowUtc, current среди самых новых. Владелец имеет отдельный draft. Время фиксируется только в инъецируемом источнике часов изолированного тестового процесса. Подмена Windows/VPS/global timezone запрещена. Fixture задаёт начальные условия, не вычисляет ожидаемый результат очистки/создания версии. Сейчас этого профиля/приложения ещё нет.

`fixture-identifiers.ownerUserId` — фактический ID синтетического nesadmin. `page.versions` дополнительно возвращает actual-db authorId/savedAt/manualDate; savedAt — реальный момент сохранения, manualDate — отдельное пользовательское значение с явной зоной. `create-named-version` выполняет настоящий UI/HTTP-запрос владельца, передаёт currentRevision/manualDate неизменёнными; не пишет SQL вместо продукта. Названия тестовые, не схема ORM/endpoint сайта.

`manual-version-creation-audit` (actual-db) читает фактическую запись аудита создания именно новой версии: eventId/versionId/authorId/occurredAt. Связь берётся из реальной операции, не назначается наблюдателем по ожидаемому ID. Время и автор аудита проверяются отдельно от пользовательской даты версии.

`audit-time-presentation` читает реальные закрытые HTML/экспорт аудита владельца (actual-http), связывает eventId/authorId с фактическим событием. `zoneLabel` — показанная московская зона, нормализованная в Europe/Moscow из фактической понятной подписи, без требования буквального текста этой IANA-строки. `wallTime` — year/month/day/hour/minute и необязательный second, извлечённые из видимой подписи; нельзя подставить результат Intl или невидимый datetime вместо видимого текста. Секунды проверяются только при их реальном отображении. Точный формат разделителей UI не задаётся. `exportOccurredAtUtc` — фактическое время этого события в принятом экспорте аудита с UTC-зоной (Z либо +00:00 в нормализованном тестовом представлении); проверяется тот же instant. Пользовательская дата проверяется в записи версии, отдельный экспорт ручной версии/поля manualDate в экспорте аудита не вводится.

## Пределы

Проверяются ручные версии/очистка/представление их времени, не все сохранения/назначения/restore/логи из полного AC-059. Не проверены подмена автора прямым payload, разрешение/точность реального источника времени, равные savedAt/конкурентная очистка, весь формат выгрузки и отрицательные права на него. Вся пользовательская дата задаётся с явной зоной; неизвестные правила для неверного/неоднозначного ввода не придумываются.

Нет приложения/bindings/bridge;4сценария не исполнялись. Сборка/самопроверки оснастки не означают прохождение AC. Независимое ревью закрыло TEST-R036–038: UTC-формат не ограничен Z, экспорт относится к аудиту, секунды UI необязательны. [Отчёт](acceptance-editor-time-review.md). Полные AC/TEST-07 не закрыты.
