## Исходные ограничения и два предусловия

Фактический app/editor_runtime/guards.py: owner/price-grant JSON64MiB, employee без price5MiB, shared4MiB; один EditorSlot через flock EX|NB собственного `/tmp/estakada-editor.slot` (inode сохраняется), Busy503 EDITOR_BUSY. Body абсолютный120s с настоящим threading.Timer и shutdown(SHUT_RD) дубликата kernel socket. Deadline начинается внутри read_json_bytes после framing/type/size checks, а не при TCP connect. Read до65536bytes, ожидание полного chunk может блокироваться; ограничитель завершает timer, join и duplicate FD в __exit__. EOF до объявленной длины —400 EDITOR_BODY_INVALID, timer expiration —408 EDITOR_BODY_TIMEOUT. Check/Save берут slot до full source/read/child; SQL content/auth транзакция не должна удерживаться во время ожидания тела.

Child AS384MiB/CPU10s/wall20s, context/output64MiB и stderr16384bytes; app768MiB/1CPU/pids128/read-only/non-root/tmpfs прежние. Child не запускается до полного body. На ровно трёх больших edit/check|save|draft путях current F Nginx overlay устанавливает64m и proxy_request_buffering off; малые cancel/issue не расширяются.

**Первое предусловие:** environment/foundation/compose.yaml запускает Django runserver --noreload --nothreading. F overlay его command не меняет. Этот сервер обслуживает один request и не может доказать конкурирующий503, пока первый заблокирован на body. Предложение отдельного test-only overlay: тот же pinned Django runserver, но без --nothreading; ни новый сервер/пакет/порт, ни production-профиль этим не выбирается. Перед тестом проверить actual command и способность двух независимых соединений войти в handler. File flock должен оставаться общей защитой threads/processes, а не тестовой заглушкой.

**Второе предусловие:** F probe-nginx.conf не задаёт proxy_read_timeout/client_body_timeout. Default inactivity timers могут завершить соединение раньше app120; прежний ingress504 не доказывает app deadline. Нужен отдельно проверенный test-only exact editor location с upstream read timeout, допускающим app120 (предложение150s), при прежнем buffering off. Headers отправляются сразу, небольшие body bytes периодически поддерживают inactivity timeout. Product body120 не сокращается/не увеличивается. Точный тестовый timeout и внешний safety watchdog (предложение180s) фиксируются root до запуска; watchdog не называется поведением продукта. Полный nginx -T/compose command/source/profile hashes входят в свидетельство.

## Детерминированная конкуренция без fake work

Первый A — настоящий аутентифицированный owner POST check с валидным CSRF/Content-Length и синтетическим допустимым PageInput. Отправить headers и только начало body, оставив ненулевой остаток. Это реальный барьер ожидания read, без sleep child/паузы security/production test endpoint. До второго запроса необходимо наблюдаемое подтверждение slot-held и reader-enter: одного факта отправки TCP bytes недостаточно.

Допустимый дополнительный witness — отдельный trusted fixture process с тем же UID пытается NB flock того же verified inode и немедленно закрывает FD; конфликт доказывает занятость, успешный lock немедленно освобождается и тест ещё не переходит к B. Внешний независимый PG connection в одной короткой transaction проверяет pg_try_advisory_xact_lock(CONTENT_LOCK7342810401), затем AUTH_LOCK7342810301; обе операции должны вернуть true, затем rollback. Это проверка отсутствия удерживаемых domain locks в точке stable body barrier, не разрешение удерживать их на всё испытание.

Второй B по другому TCP connection получает собственную реальную session/CSRF и допустимые headers, но тело ещё не посылается. Варианты до кода: A Check/B Check и A Check/B Save; Save DTO/proof/operationId предварительно подготовлены реальным Check, operationId уникален. B обязан получить503 EDITOR_BUSY до передачи body/child, без очереди/retry. Получение503 при сознательно неотправленном body подтверждает отсутствие блокирующего чтения этого body; точное отсутствие entry в read/normalize лучше подтвердить пассивным test-only observer ниже. Отсутствие sampled PID не считается доказательством отсутствия короткого child.

После завершённого Busy response дослать остаток A: настоящий child и Check завершаются200 с verified proof, без current/version mutation. Затем только отдельный явный повтор B с тем же безопасным намерением: Check200 либо Save200 и ровно одна automatic/receipt/actual refs. Пока B был Busy, receipt/current/history/refs не меняются. Slot после A реально свободен, следующий запрос не попадает в старую очередь. Новый вызов после Busy — отдельный согласованный шаг сценария, не blind retry ошибки теста.

## FR07-005: abort и настоящий deadline

1. **Abort до полного тела.** A hold body barrier как выше, доказать slot-held/reader-enter/child-not-entered. Закрыть клиентский socket до Content-Length. Не требовать JSON после peer abort. Наблюдать фактическое завершение reader/request, освобождение flock, cancel+join настоящего timer, закрытие duplicate socket FD, отсутствие child и domain mutation. Новый здоровый Check с новой connection должен пройти. Half-close/FIN и при необходимости reset — разные явно обозначенные transport варианты, не взаимозаменяемая гарантия.
2. **Absolute120 при живом slowly-fed socket.** Отправить headers и небольшой prefix, затем фиксированный byte каждые5s, суммарно существенно меньше заявленного body. Никакого патча seconds/clock, искусственного worker timeout или ускорения120s. Нужен reader-start witness; мерить monotonic от него. При доступном ответе получить app408 EDITOR_BODY_TIMEOUT, а не ingress504; зафиксировать guard duration около120s с заранее заданной технической погрешностью планировщика/доставки. Периодические bytes не продлевают абсолютный timer. При оборванном transport app outcome доказывается пассивным observer/cleanup, но сам такой прогон не закрывает положительный socket408 oracle.
3. После deadline — child-not-entered, slot/FD/timer cleanup, прежние current/history/refs/receipts, healthy request success и отсутствие старого timeout воздействия на новый FD. Timer.join/is_alive и закрытый duplicate — прямой witness; один поздний успешный запрос сам по себе не доказывает отсутствие FD/timer leak. Периодическая активность/проверка harness не увеличивает body budget и не допускает автоматическое возобновление запроса.

**Граница Save:** abort гарантированно до конца reader не мог начать child/commit и должен сохранить domain. При полностью полученном Save body и потерянном response результат UNKNOWN: сервер мог успеть commit. Нельзя обещать rollback из-за разрыва TCP. Это отдельный сценарий durable receipt/same operationId replay с актуальной session/правами, не часть read-abort oracle и не новый operationId.

## Наблюдаемость и manageable scope

Рекомендуются два новых ограниченных тестовых файла/harness и собственный ignored network overlay после gate; frozen старые инструменты не переписываются. Для thread-safe пассивных свидетельств test-only загружаемый observer может оборачивать настоящие EditorSlot.__enter__/__exit__, read_json_bytes и normalize_input/_ReadDeadline exit: вызывает original ровно один раз и пишет только fixed event IDs, monotonic timestamps, собственный correlation ID, PID/TID, byte counts и закрытые error codes. Нельзя возвращать fake reader bytes/Busy/timeout, держать slot самому вместо A, менять timer/childcommand или добавлять product HTTP endpoint. Таймер/FD निरीктируются после original __exit__; наблюдение без воздействия на app control flow. Точный seam, bounded канал/очередь и отсутствие секретов root/reviewer утверждают до реализации.

Cookies/CSRF/credentials/raw body не попадают в Git/logs/report. Native TCP harness использует существующие Node net/http либо stdlib, только loopback8767 approved ingress; DB/process observer — existing host fixture controller с fixed capabilities, не Docker socket в браузерном runner. Не направлять arbitrary hosts/commands/paths. Thread/FD/process/cgroup/OOM evidence снимается до, в stable barrier и после cleanup; request-thread/keepalive FD закрываются перед сравнением. Body temp dir Nginx не получает request-файл; polling/FD counts одни не доказывают отсутствие кратковременного файла — нужен bounded directory event observer либо честная граница доказательства.

Первый cohort: concurrency Check/Check + Check/Save, быстрый incomplete-body abort и один реальный slowly-fed120s. Пока длится120s root даёт регулярные краткие статусы и держит внешний safety watchdog; не блокировать коммуникацию одним непрозрачным sleep. Одна ошибка фиксируется с фактами/фазой, следующий эквивалентный запуск только при новом source/состоянии/наблюдаемости; третьих одинаковых попыток нет. Неподтверждённые transport assumptions остаются pending, не обходятся снижением oracle/caps.

Сейчас ничего из FR07-004/005 не объявляется пройденным. Нужны QA precode scenarios, reviewer gate overlay/observer и реальный root runtime; при отсутствии concurrent сервера или различимого app120 сохранить блокер явно. Production-server selection, deployment и остальные DEV-07 gates этим документом не закрываются.
