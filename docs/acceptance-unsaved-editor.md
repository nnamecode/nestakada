# Несохранённый текст и повторный вход: частичные AT-015/017/118

2026-10-30. Основания D-258/D-294, REQ-015/017, TECH-01, принятые UI-S003–005 и D-301/D-307/D-308. Только тесты и чтение браузера. Старый сайт/VPS/код приложения не меняются.

`acceptance/unsaved-editor.spec.js`:10экземпляров. Два сценария — отказ валидации и конфликт с новой редакцией; восемь — истечение idle/absolute сессии и четыре варианта повторного входа: тот же пользователь, отозванное право, устаревшая редакция, другой пользователь.

После отказа/конфликта допустимый собственный ввод остаётся в фактическом поле открытой вкладки; опубликованные данные, черновик, история и права не меняются. Для валидационной ошибки используется запрещённый шаблонный синтаксис TECH-01, затем исправление и явное успешное сохранение через тот же редактор. Перед запросом ошибка не должна уже появиться как автоматическое серверное сохранение. Конфликт не объединяет тексты.

Истекшая сессия не читает закрытую страницу. Повторный вход не сохраняет текст автоматически, текущие права и редакция перепроверяются. Для другого пользователя не обещается удержание старого ввода: проверяются отсутствие прежнего доступа и отказ прямому сохранению старой страницы. После этих отказов отдельное явное назначение права владельцем позволяет тому же реальному пользователю принять тот же допустимый payload — положительный контроль отличает запрет доступа от неработающего обработчика/CSRF. Это новое явное действие владельца в синтетическом тесте, не автоматическая выдача прав после входа.

## Наблюдение собственной вкладки

`editor-memory-state` имеет только fixed kind `ui-memory`. Подмена его на fixture-read, произвольный script или другое имя для такого kind отвергается. Драйвер читает действительную actor.page: URL, ключи и значения localStorage/sessionStorage. Возвращаются только boolean наличия собственного canary и метка источника, без URL/содержимого хранилищ/секретов. Ошибка чтения не считается пустым хранилищем; чужой origin/about:blank отвергается. Проверяется буквальный canary и до двух уровней URI-кодирования; собственное поле ввода читается отдельно существующим ui-input.

Это снимок текущего top-level документа в нескольких точках сценария. Пока не проверены transient-записи между наблюдениями, IndexedDB, CacheStorage, cookies, worker/frame storage, произвольное кодирование/сжатие или выгрузка по сети. Отрицательные boolean этих снимков не доказывают полное отсутствие постоянного хранения. Reload/закрытие вкладки может потерять ввод по D-258; восстановления после этого тест не требует.

Самопроверки DRIVER-MEMORY-001/002 проверяют fixed binding/отказ подмене/ограничения и реальный Chromium на инертной локальной странице: ввод в поле не считается записью storage; загрязнение ключа/значения и encoded URL обнаруживается без возврата содержимого. Эта страница — только оснастка наблюдателя, не модель редактора/сайта.

## Контракт будущего подключения

Используются действующие `page-history-restore` и `controlled-session-boundary`: реальный редактор открывается и получает ввод до финализации истечения часов; guard проверяет отсутствие мутаций/автосохранения. Windows/VPS/global clock не меняются. Начальный текст controlled-session — «Несохранённый допустимый ввод»; age1801/43201 по обе стороны принятых лимитов, не новое правило точной границы.

`page` читает фактическую SQL-проекцию, включая grants; `open-editor-input` читает поле конкретной вкладки S-EDIT. `type-unsaved-text` только UI-наблюдение, не accepted сервера. `save-open-editor` действительно отправляет открытый ввод и основание, не заменяет их параметрами теста и не обновляет base скрыто. `save-text` — настоящий прямой запрос сохранения с текущей сессией и действительным CSRF. После login обновлённый CSRF берётся из настоящего контекста; устаревший токен не должен выдавать ложный отказ правам. Конкретных bindings ещё нет, их способность корректно обновлять сессионный/CSRF-контекст требует независимой проверки.

`reauthenticate-open-editor({credentialActor})` выполняет настоящий вход с синтетическими секретами указанного пользователя **в том же браузерном контексте**, сохраняя исходную вкладку/её память для того же пользователя. Нельзя заменить actor на отдельно заранее авторизованный context или подменить serveruser в fixture. Название актёра S-EDIT после входа S-OTHER означает исходную вкладку, не прежнюю серверную идентичность. `read-current-identity-direct` читает фактического текущего пользователя через реальный UI/HTTP этой сессии. fixture-identifiers содержит разные editUserId/otherUserId. Секреты в тесты/отчёты не попадают.

`revoke-page-grant`/`grant-page-grant` — настоящие явные действия владельца; права не восстанавливаются reset/наблюдателем внутри сценария. Чтение и запись после login должны использовать обновлённую сессию исходного контекста; прежние cookie/CSRF из reset не считаются доказательством. Названия — контракт тестового интерфейса, не новые endpoints/ORM-поля продукта.
