## Независимый локальный источник

При выполнении тест читает только `acceptance/local-migration-source/<basename>`; имя basename берётся из закреплённого `source_snapshot` соответствующего MAP, регулярное выражение допускает только20hex`.html`. Для каждой строки MAP дополнительно проверяется согласованная RTE-запись: MAP-ID/requested_path/source_snapshot/SHA.

**Не генерировать source из результата импорта.** Staging заранее копирует неизменённые байты соответствующих публичных HTML из `work/site-audit/crawl/`; конкретный SHA-256 в CSV проверяется до парсинга. Список MAP:003/009/033/039/044/045/049/078/090/097/013/038/073/015/032/088. MAP-115 использует тот же исходник/SHA, что088; не является новым наблюдением старого сайта. Эти точные paths/SHA уже находятся в analytics-route-map.csv/analytics-route-evidence.csv и не дублируются расходящимся вторым реестром.

Runner копирует только16выбранных публичных HTML в отдельную GUID-папку work/acceptance-migration-source, проверяет SHA до/после копирования и предоставляет её read-only только тестовому контейнеру. Install container исходники не получает. Широкий mount work/media, Docker socket или весь пользовательский каталог не нужен. ВGit исходные HTML/staging не включаются. Чтение происходит внутри тела теста, поэтому collection не требует наличия файлов; отсутствие/неверныйSHA вызывает явный MIGRATION_SOURCE_UNAVAILABLE/HASH_MISMATCH, а не skip/pass/подмену ожидаемых данных. Симлинк/выход из фиксированной папки и файлы свыше256КиБ отвергаются как ограничения тестового инструмента, не бизнес-лимит HTML. Source body в сообщениях об ошибке не выводится.

HTML разбирается собственным DOMParser в странице с JavaScript disabled, service workers block, HTTP/WS abort. Скрипты/стили не исполняются. Источник — единственный `div.col-lg-9`; для individually inspected MAP-013/015/032/038/073/088 тело берётся только из прямого `.c-content`, H1 — изпрямого `.pagetitle`. Поэтому нижний `.services-list-extended`/«Все услуги» и breadcrumb `.pagetitle.subservice` не попадают вматериал. Для10legacy используются собственные прямые материалы основной колонки сисключением всей `.pagetitle`. Попадание меню/крошек внутрь выбранного тела вызывает явный отказ. Это неуниверсальный extractor для всех115маршрутов; самостоятельный каталог этим способом неразбирается. H1 отделяется от тела, пробелы/NBSP нормализуются; слова, числа и пунктуация не переписываются. Полный source SHA закрепляет вход независимо от будущего импорта/наблюдений.

## Контракт будущего изолированного стенда

`reset(migration-imported-local-source-bundle)` обязан выполнить настоящий импорт этих локальных исходников в собственную тестовую БД/хранилище. Он не подставляет заранее ожидаемые projection и не выдаёт zip/v3 за корректный импорт. Работа импортера/санитаризации/ограничений реальной схемы ещё требует реализации и независимого ревью после разрешения этапа8. Нельзя запускать этот профиль на старом сайте/VPS.

Наблюдения используют существующий транспорт actual-db/actual-http:

- `migration-imported-material({mapId,requestedPath})`, actual-db: фактические mapId/requestedPath/sourceSnapshotSha256/materialId/revision/publicationState/headings/bodyText; для автомойки дополнительно proseText (реальное тело без таблиц). Источник provenance связывает реальную запись с импортным журналом; SHA-метка не заменяет проверку содержимого. bodyText — инертно извлечённые слова **реально сохранённого тела**, без H1/общей навигации, не заранее ожидаемый текст.
- `migration-imported-price-grids({materialId})`, actual-db: materialId/tables — все фактические таблицы прайса в порядке источника. Логическая таблица содержит строки/ячейки `{text,rowSpan,colSpan}` с реальными заголовками/объединёнными осями/оговорками. Mapping из будущей схемы только читает данные; не возвращает исходный HTML вместо результата импорта.
- `migration-public-material-text({requestedPath})`, actual-http: status/materialId/headings/bodyText (и proseText для автомойки), извлечённые из настоящего ответа того же точного пути. Основная область определяется будущим принятым шаблоном; исключаются общая шапка, хлебные крошки, меню и Footer, но не потерянные абзацы/списки. Связь materialId должна быть доказана реальным маршрутизатором/данными, не fixture echo.
- `migration-public-price-grids({requestedPath})`, actual-http: status/materialId/tables — логические таблицы по реально выданному содержимому. Совпадение логических ячеек не требует идентичного HTML/CSS или сохранения старой CMS. Связи заголовков/объединённых осей должны сохраняться; bridge не достраивает отсутствующие ячейки из source.
- `act(VISITOR,read-migration-route-direct,{requestedPath})` выполняет настоящий GET с redirects disabled. Возвращает явный фактический accepted/status/contentType/requestedPath/finalPath/location;200с отличным путём/Location не считается переносом точного адреса.

Для автомойки проверяется общий фактический materialId, а не два независимых редактируемых экземпляра. Канонический URL/полнота рекламной выгрузки не выбираются этим файлом. Названия наблюдений — контракт тестового интерфейса, не публичные endpoints и не утверждение будущей схемыБД.

## Ограничения и проверки

Нужны реальное приложение/миграция/локальные bindings/bridge и отдельно проверенные source staging/парсинг целевых полей. Наличие меток source/provenance/materialId само по себе ничего не доказывает до ревью конкретного подключения. Assertion-проверки против приложения пока не запускались.

Не покрыты все60service/catalog, галерейный состав/порядок/page=1/page=2, MED-placement и16архивных файлов, полная реклама ANA-Q041, sanitation/overflow/error-пути импорта, даты/авторы/откаты импортера, безопасность/законность внешних ресурсов, пиксельные макеты/всеустройства, все ветви AC. Для сохранения принятых исключений главной D-232/D-300 она не сравнивается со старой главной; прайсы главной не восстанавливаются из источника автоматически.
