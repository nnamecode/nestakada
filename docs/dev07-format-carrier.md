## 1. Факт и необходимая граница

Root получил Python12PASS+3 restricted RustSec PoC и native evidence, JS marks/table/style prototype/CSSOM classes PASS. **PKG006 default style roundtrip FAIL:5 inline-CSP violations.** Это не исправляется разрешением unsafe-inline/eval.

Read-only изучен фактически установленный Tiptap3.32.2: TextStyle parseHTML принимает span только при наличии style, mergeNestedSpanStyles по умолчанию создаёт style; FontFamily/FontSize/Color/BackgroundColor/TextAlign renderHTML возвращают style. Table.renderHTML создаёт colgroup и width/min-width даже при resizable=false; TableView меняет inline style. TableCell/Header alignment helper также возвращает style. Subscript допускает style parse rule. Эти defaults не являются approved carrier и не должны автоматически включаться в продукт.

Предлагается **один canonical fragment HTML** для snapshot/HTML-mode/normalised API output, с обычными безопасными tags и закрытыми `data-es-*` значениями. Внутреннее ProseMirror JSON/DOM — представление UI, не принимаемый сервером Snapshot/независимый HTML-профиль. Canonical serializer не вызывает raw `editor.getHTML()` неподконтрольного набора extensions и не копирует runtime DOM.

## 2. Точная матрица canonical carrier

Неуказанное свойство отсутствует и наследует принятый общий стиль. Отсутствие не означает автоматическую запись default в снимок. Нормализованные значения экранируются как HTML attributes; порядок атрибутов фиксирован именем. Клиент может прислать только точные допустимые поля carrier, но ни один attr не является полномочием: роль/Asset/protected map проверяются по серверу.

Один span может объединять font/size/fg/bg. Пустой формат без свойств canonical serializer не создаёт, кроме самостоятельного зарегистрированного anchor/protected/slot marker. Вложенные форматирующие span не сливаются с потерей свойств: normalization вычисляет итоговый inherited map по каждому текстовому run, затем создаёт минимальные совместимые spans с сохранёнными semantic marks и текстом. Если чистка меняет представление, нормализованный результат показывается до save.

Font map — фиксированные CSS families: inter→`Inter,Arial,sans-serif`; oswald→`Oswald,Arial,sans-serif`; arial→`Arial,sans-serif`; georgia→`Georgia,serif`; times-new-roman→`"Times New Roman",serif`; courier-new→`"Courier New",monospace`. Это mapping принятого TECH01 списка, не установка/скачивание шрифтов. Недоступный локальный font использует указанный fallback; внешние font URLs не загружаются. Verdana из старого demo не добавляется поверх принятого D301 перечня.

Size canonical grammar: decimal без leading zeros (кроме0), без знака/единицы/NaN/Infinity, trailing fractional zeros удалены, затем exact Decimal range8..72. Входный CSS `12.50px` после проверки становится `data-es-size="12.5"` с видимой normalization. TECH01 не называет font-size только целым — этот контракт не сужает его молча до65integer значений. Ресурсный reader отдельно ограничивает весь вход; произвольная точность не создаёт вечный CSSOM cache.

Цвет #RGB разворачивается в #rrggbb при показанной normalization; #RRGGBB приводится lower. Иные input syntaxes допускаются лишь при отдельно описанной exact безопасной нормализации, не через browser computed style/произвольный CSS fallback. Canonical output всегда только указанный формат; неявные rgb/var/currentColor/URL не проходят carrier как готовое полномочие.

## 3. Input CSS/HTML → carrier → nh3

На input отдельно разрешён TECH01 безопасный style для проверки/normalization; он никогда не попадает в live preview или nh3. tinycss2 разбирает декларации; duplicates/unknown dangerous declarations, functions/url/var/expression/import/position/z-index/line-height и активный HTML вызывают whole refusal. Только конечные font-family/size/color/background-color/text-align/margin-*/cell-padding profile values отображаются в матрицу. Если input style и data-es attr заявляют разные значения одного свойства — отказ, не выбор по порядку. Padding у таблицы нельзя спутать с cellpad: UI отступ ячейки — отдельный data-es-cellpad; Word td-padding принимается только после доказанного единого значения всех4сторон всех затронутых ячеек и явной normalization либо объяснённого отказа, без усреднения.

Дополнительные semantic CSS aliases для исходного formatting задаются конечной map: font-weight normal/400→отсутствие strong, bold/700→strong; font-style normal/italic→отсутствие/em; text-decoration-line none/underline/line-through либо их точная комбинация→u/s; vertical-align baseline/sub/super→обычный/sub/sup. Обработка только literal tokens, не CSS parser fallback по arbitrary computed styles. Встреча неподдержанного значения объясняется как неподдерживаемое оформление; не округлять другой вес до700. Canonical output для этих функций — tags, не data-es-weight/style. Семантически противоречивые source marks/styles требуют явно показанной normalization, а не случайного порядка атрибутов.

Обычные benign aliases b→strong/i→em допускаются только как явно показанная normalization входа, не расширяют canonical tag set. Дополнительные неизвестные attrs/data-*/classes/ids не исчезают молча ради успешного save: ошибка либо заранее перечисленная безопасная Word-normalization с явным принятием. Произвольный class из клиента запрещён даже если похож на runtime `.esf-*`; произвольный `data-es-foo`, `data-es-node` от другого документа и marker без actual protected reference также запрещены.

После полного HTML5 tree/permissions/URL/style validation серверный canonical serializer строит output без style/SVG. Единственный restricted nh3 call получает точные tag→attribute allowlists этого документа, а не wildcard data-*; URL schemes ограничены профилем. Ни `style`, ни SVG/animation, ни `filter_style_properties` не разрешены в этом call. Rowspan/colspan/scope/carrier значения уже проверены, nh3 не используется как валидатор чисел/прав.

Сервер инертно разбирает clean output снова и сравнивает semantic DOM/attrs/text/grid/protected references; неожиданная потеря хотя бы одного carrier или безопасного caption/scope — отказ, не незаметное обнуление форматирования. Canonical serialize(clean(serialize(DOM))) должен быть идемпотентен. Native advisory affected paths не объявляются исправленными; ограниченная конфигурация и upstream PoC проверяются дополнительно, но опасный оригинал отклоняется до cleaner.

## 4. Точные Tiptap hooks, которые заменяют defaults

Прямой `TextStyleKit` не подключается: lineHeight выключен, stock TextStyle/FontFamily/FontSize/Color/BackgroundColor/TextAlign не дублируются рядом с carrier extensions. Один собственный mark `esFormat` с attrs font,size,fg,bg, defaults=null:

- parseHTML принимает только span с зарегистрированным data-es-font/size/fg/bg, читает getAttribute, проверяет exact grammar; **не читает element.style/computedStyle**, mergeNestedSpanStyles отсутствует.
- renderHTML возвращает только `['span', {точные непустые data-es-*},0]`; не merge arbitrary HTMLAttributes из input/options. remove-empty проверяет четыре собственных attrs, не truthy вместо допустимого0 другого профиля.
- UI команды setFont/setSize/setForeground/setBackground меняют только attrs esFormat с закрытой валидацией; ни одна команда не получает raw CSS declaration/selector. Clear-format удаляет разрешённые marks/attrs, не protected atoms/slots.
- Private node/mark view назначает собственный runtime class из безопасной stylesheet compilation §8; он не является PM attr и не попадает в canonical serializer. Для inline mark возможен trusted markView/span update class, но не `.style`.

Фактически установленный core3.32.2 имеет Mark.addMarkView и ExtensionManager.markViews: для esFormat используется именно этот поддерживаемый hook; кастомный mark view получает только проверенные typed attrs и выставляет свой class. Canonical renderHTML остаётся отдельно без runtime classes.

Собственный `EsBlockFormat` addGlobalAttributes задаёт esAlign и nullable integer margins на точном перечне node types из матрицы; parse/render снова data-es attrs, без style. Хранение0 не теряется из-за `value || default`. Отключить stock TextAlign полностью, а не только изменить его options. Самые обычные semantic marks strong/em/u/s/sub/sup используют exact tags; inherited style parse rules для sub/sup/strong/italic и arbitrary HTMLAttributes не используются.

StarterKit отключает code/codeBlock/horizontalRule/dropcursor/trailingNode и stock link. Dropcursor/style code может нарушать CSP даже без исходного HTML; drag/drop изображений всё равно handled trusted media path. Базовые paragraph/heading/listItem extensions расширяются там, где нужны только carrier attrs. Link заменяется EsLink. Неподдерживаемые markdown/paste input rules не должны создавать запрещённые nodes; auto-paste/drop проходит pre-DOM validation, а не default transformPastedHTML после live вставки.

Canonical exporter работает по PM document и закрытой map типов/attrs, а не `DOM.outerHTML`; неизвестный PM attr/type — ошибка, не silent drop. Настоящие tags/marks сериализуются с контекстным escaping, UTF8/codepoints сохраняются. `editor.getHTML()` можно использовать только как диагностическую сравниваемую величину полностью переопределённой схемы, не как отдельный доверенный источник raw HTML. Надо проверить Tiptap editor view, transactions и export, не только static renderHTML hooks.

## 5. Таблицы без скрытых style/colgroup и потери metadata

Stock Table.extend получает `resizable:false`, `renderWrapper:false`, `View:null` и собственный renderHTML без createColGroup/style. Это важно: одного resizable=false недостаточно по установленному source. Stock colwidth/align helpers TableCell/Header отключены/заменены, parsing legacy style/align не исполняется в браузере; input normalization делает сервер. Rowspan/colspan остаются typed attrs. Столбцовый drag-resize/colwidth/colgroup не создаются как новая функция. Точность строк/колонок/объединений сохраняется без ширин.

Чтобы штатные pm/tables команды/TableMap продолжали видеть table с прямыми tableRow children, caption не вставляется в row-only PM table. Предлагается технический `esTableBlock` с content `esCaption? table`; `esCaption` содержит разрешённый inline content/marks, имеет отдельное доступное поле/selection. TableRow хранит esSection=head|body, TableHeader — esScope. При загрузке server-approved canonical table преобразуется детерминированным adapter в эту PM форму; default setContent с теряющим caption DOMParser не применяется.

Canonical exporter разворачивает esTableBlock обратно ровно в `<table attrs><caption>…</caption><thead>…</thead><tbody>…</tbody></table>`. Технического div, PM classes, selection decorations или editable attrs в snapshot нет. Визуальный private wrapper может иметь trusted class, но wire serializer его не копирует. Для нового table `insertTable` создаёт отдельную первую header row и body rows, esCellPad=4. Вставка/удаление строк/колонок/merge/split оборачивает штатные commands: сохраняет scope/section/padding и проверяет результат до canonical export.

thead используется для явной head-группы; tbody для body. Не изобретать заголовок вместо отсутствующего у существующей таблицы, не превращать td в th молча. В сохранённой истории caption/thead/tbody/tr/th/td/rowspan/colspan/scope+format carrier удерживаются; обёртка UI не меняет источник. Неконтинуальные/противоречивые секции, span выходящий за границу группы, перекрытие занятых клеток и прочие invalid grids вызывают объяснимый отказ, не fixTables с потерей данных после тихой вставки. Price500/32/10000 не назначается обычной таблице автоматически.

**Finite UI capability fallback допущен reviewer для реализации/проб, не как закрытие FMT004/V07.** Прежде любого PM TableMap/stock table command выполняется sparse-grid proof: row-group boundaries и количество реальных row/cell nodes известны из bounded DOM; для occupied column intervals хранятся начало/конец и row-expiry, а не dense virtual matrix. При переходе строки истёкшие intervals снимаются; новые spans сопоставляются со свободными интервалами, проверяются overlaps/выход за реальную row-group boundary. Работа зависит от реальных nodes/interval events, не от declared billion slots: ни заполнение массива, ни поячеечный цикл по giant rowspan/colspan не допускаются. Для rich-widget admission не используется опасное умножение: checked safe integers либо `width<=floor(remainingBudget/rowCount)` после проверок положительности, иначе opaque fallback; source sparse geometry может считать arbitrary-precision extent без allocation virtual slots. Child/resource profile ограничивает время проверки; resource failure показывается честно, не превращается в «таблица недопустима по новому лимиту».

**20000 virtual slots — aggregate UI budget всего открытого editor document, не каждой таблицы.** При детерминированном проходе canonical document non-nested tables получают rich capability только если sparse proof подтверждает, что их work cost помещается в оставшийся aggregate budget; после admission cost вычитается. Сумма всех tables, передаваемых stock TableMap/visual commands,≤20000; каждая дальнейшая transaction/insert/merge проверяет новый aggregate до stock command. Это UI work bound, не content/save limit и не price cap.

Большая суммарная виртуальная сетка, недостаточный remaining budget, arithmetic uncertainty либо nested table помещается в opaque readonly editor atom с **полным exact APPROVED canonical HTML** из той же области — не raw input, не arbitrary outerHTML, не обрезанная сериализация. Такой atom не экспортируется в TableMap и не создаёт гигантский live table DOM. Private widget показывает escaped/collapsed представление и видимое объяснение «Эта таблица редактируется в HTML-режиме» с действием «Редактировать HTML»; HTML-mode остаётся редактируемым через ту же server policy/permissions и explicit normalization. Все разрешённые caption/sections/attrs/вложенное содержимое сохраняются в approved opaque source; canonical serializer возвращает source целиком, не placeholder. Сохранение/история/restore не отказывают только из-за превышения widget bound. Opaque widget не обходит общие HTML/права/Asset/security проверки.

Для rich widget эта возможность не обещает идентичный GUI в oversized/nested случае. Полная public table rendering/capability остаётся DEV08 gate; private collapsed widget не выдаётся за доказательство публичного renderer. Nested shape не объявляется ошибкой только потому, что stock TableMap её не умеет. Если sparse proof/fallback не принят независимым ревью либо не подтверждён resource tests, соответствующая UI capability остаётся pending, а не молча получает новый бизнес-лимит.

D057 zebra — trusted stylesheet, не persisted arbitrary colors/classes. Header transparent, далее счётчик по порядку отображаемых строк всей таблицы: первая header row=1, вторая общаяrow затемнена, третья прозрачна. Canonical semantic row order однозначен, renderer назначает trusted parity class каждому tr; это избегает неверного restart tbody:nth-child. Оттенок берётся из принятого CSS, не новое оформление из этого документа. Cellpad rule адресует только th/td текущей таблицы, не вложенные чужие таблицы. Допустимость nested table/schema — тот же отдельный profile gate, не parser fallback.

## 6. Ссылки и scoped anchors

Обычный a хранит href/title/target/rel согласно TECH01; `_blank` canonical rel включает noopener, без новых SEO-rel. Idempotence не требует принудительно добавлять nofollow/noreferrer. URL не fetch-ится сервером или preview-браузером при проверке. Listener не открывает ссылку при редактировании.

Точный предлагаемый anchor algorithm: carrier `data-es-anchor` хранит plain Unicode label после NFC, без NUL/C0/DEL/CR/LF/TAB, без молчаливой смены букв; размер входит в общий source byte budget. Label не становится CSS/DOM selector. Server вычисляет labelToken=SHA256(UTF8(label)).hex, а actual id=`esc-<PageUUIDhex>-<fieldToken>-<renderScopeHex>-<labelToken>`; fieldToken только intro/main, scope стабилен для текущего public field и отдельный для private view. Никакая пользовательская часть напрямую в selector не интерполируется. Anchor на span разрешает пустую метку-узел, но не пустой label; duplicate normalized label в одном field отклоняется как неоднозначная разметка.

`href="#fragment"` декодируется строго один раз как UTF8 percent-encoded fragment, нормализуется NFC. Canonical a сохраняет **explicit binding**: `data-es-target-field="intro_text|main_text"` и `data-es-target-anchor="NFC label"` вместе с проверенным href. Для обычной собственной anchor ссылки field выбирается исходным field в check, cross-field выбирается явно человеком; это записывается в canonical attrs после принятой normalization, а не угадывается после reload. Оба binding attrs либо присутствуют вместе, либо отсутствуют; несовпадение href с encoded label/неверный field вызывает отказ. Cross-page path не принимает эти attrs. EsLink attrs, PM JSON, canonical serializer, nh3 allowlist, DB snapshot и reload должны roundtrip оба значения. Renderer использует сохранённый field+anchor, не повторный поиск «где сегодня встретилась метка».

Для неизвестной same-Page метки binding хранится всё равно с явным field; renderer использует детерминированный scoped#id этого field без совпадающего target, check показывает предупреждение. Это не новый запрет сохранения обычной ссылки и не доступ к toolbar/system DOM. При последующем создании этой метки binding становится разрешимым без переселения на другой field. Изменить target field можно только явным редактированием/normalization с обычными правами, а не появлением одноимённого anchor после reload.

**Cross-page path#fragment — literal safe URL**, например `/other-page/#fragment`: сохраняется без переписывания и без data-es-target-field/anchor, проверяется обычным URL profile. Автоresolver по PageID, общий anchor registry, поиск target во всех Page и обещание новой схемы deep links сейчас не реализуются. Уже известный автору namespaced literal может работать; неизвестный target не «исправляется» и не связывается с новым объектом. Existing old public anchors/migration mapping не меняются автоматически; стык публичной схемы/deep links принадлежит DEV08/MIG/29. Это техническая граница, не обещание успешности неинвентаризированных старых ссылок.

Нет неограниченного IDN/URL rewriting или повторного percent decoding до другого смысла. Отказ опасным/неоднозначным схемам сохраняет полное содержимое прежней версии; anchor normalization до save показывается. Source arbitrary id/class не обходят namespace через data-es-anchor.

## 7. Protected Asset marker и положение

Carrier marker — пустой span с точными attributes: `data-es-protected=markerUUID`, `data-es-image=EmbeddedImageRef.id`, `data-es-asset=AssetUUID`, `data-es-alt=plainText≤300codepoints`, `data-es-image-align=left|center|right`, необязательные `data-es-width/data-es-height=positiveInteger` (отсутствие означает null). Другие attrs, raw src/srcset/MIME/filename/style исключены. Actual embedded_image/Asset не определяется одним присланным UUID: проверяются real READY Asset/files/права и точное соответствие metadata актуальному разрешённому изображению. MarkerUUID сопоставляется с existing `layout.text.protected_nodes{id,reference_id,fingerprint}`, reference_id — постоянный EmbeddedImageRef.id. Parent/layout/marker stamp сервер проверяет по актуальному current base и разрешённой ownership, включая FS preflight и повторную проверку в commit.

**HTML budget включает всё metadata изображения.** Полный marker с UUID/alt/dims/align/parent/slot/format attrs входит в исходный richHTML1MiB соответствующего intro/main field. Отдельный client `embedded_images` array либо arbitrary layout/Snapshot writer не допускается сверх HTML: producer выводит embedded_images/layout из проверенного canonical markup и current basis, сохраняя постоянные image IDs. Только два внешних main_image/preview_image ImageRef остаются отдельными малыми полями. Это не новый cap числа фото, а закрытие той же source-size границы; слишком большое представление не усекается. dev07-editor-contract.md исправлен в этой же адресной документной когорте до code.

Для родителя, содержащего защищённый marker, canonical fragment дополнительно использует `data-es-parent="UUID"`; редактируемые текстовые участки вокруг marker получают `span data-es-slot="UUID"`. Эти identity attrs имеют только server-assigned актуальные значения; отдельной пользовательской функции/бизнес-сущности они не создают. Protected placement identity = enclosing field+parentUUID+ordered protected marker sequence+ordered slot identities/marker-to-slot boundaries. Fingerprint включает kind/reference descriptor/placement; actual Asset SHA/File IDs проверяются существующим FS/ledger путём, не просто клиентским hash.

Employee может менять разрешённый текст/форматирование внутри прежних slots, но не переносить/удалять/дублировать marker, менять parent/slot identities/последовательность/Asset/alt/alignment/dimensions или effective ancestor layout защищённого изображения. Сервер сравнивает полный актуальный protected map, не доверяет contenteditable=false или тому, что кнопка скрыта. Прямой HTML POST с новым parent/похожим UUID отклоняется whole. Если на историческом rich HTML нет однозначного protected map, несовместимость не исправляется угадыванием; владелец/импорт формирует проверенное представление отдельно.

В PM esProtected — atom/selectable, editable content отсутствует; node view создаёт img только с server-approved preview URL и alt/plain dims из доступного ImageRef. Не принимает arbitrary src/srcset/style/event и не сохраняет real URL обратно в fragment. UI запрещает employee cut/delete/drop/reparent atom, но это только удобство поверх серверной проверки. Owner replace/insert меняет actual media reference через разрешённый picker и создаёт новый snapshot, исходные байты не перезаписываются.

Текст до/после marker технически отделён slots, поэтому «перемещение» не маскируется потерей marker во время normalizing join/split. Обычный текстовый shift не проверяется по неизменному character offset: добавление текста перед картинкой само по себе не означает запрещённый перенос. Точная PM transaction handling для paragraph splits/joins/slot-boundaries требует тестов сохранения разрешённого текста без ослабления marker map; при невозможности безопасного отображения функция не объявляется готовой. Такие constraints реализуют D072, не выдают сотруднику новые media права.

## 8. Trusted CSSOM/private renderer без растущего cache

Canonical snapshot хранит data attrs/semantic tags, **не runtime classes**. Renderer проверяет carrier вновь и строит style facts, выбирая значения только из матрицы. Class name generated как `esf-<server/viewScopeHex>-<nodeSlotInteger>`; клиентский class/selector в него не интерполируется. Один style rule на текущий formatted element объединяет его разрешённые свойства; общие tags/zebra/подписи используют фиксированный same-origin stylesheet.

Private editor/preview получает свой same-origin stylesheet (предлагаемый закрытый `/manage/editor/format-shell.css`, без payload/секретов, header text/css,nosniff); JS изменяет именно CSSStyleSheet/CSSStyleRule через insertRule/setProperty с проверенными literal values, а не element.style/style attribute/style element/cssText от пользователя. Это использует успешно проверенный root CSSOM механизм, но полный product путь ещё предстоит проверить. Ни nonce-обхода, ни unsafe-inline/eval не добавляется.

Rule registry принадлежит только одному открытому view/document. При загрузке другой версии/закрытии editor он уничтожается целиком; при редактировании удалённый node теряет rule, existing node заменяет прежний rule, а не накапливает новый на каждый color/keystroke. Верхняя граница количества rules≤числу formatted elements текущих разрешённых деревьев, плюс конечный static stylesheet; для одного field действует его node budget20000, для двух — сумма их бюджетов, а не вечный общий cache. Map не переживает документ и не хранит все встречавшиеся colors. Это производная граница DOM, не новая квота истории/контента и не per-table virtual-slot budget. Для больших таблиц/частых input нужна фактическая memory/time проверка, не только счётчик rules.

Canonical renderer для private history может получить те же classes и отдельный закрытый stylesheet по Page/Revision контексту с реальной проверкой доступа; public renderer DEV08 должен компилировать safe facts в отдельный same-origin CSS response для текущего опубликованного контента, чтобы форматирование не зависело исключительно от JS. Публичного historical CSS/Asset endpoint не возникает. Unknown historical policy/schema показывается как безопасный текст, не помечается verified только по имени поля.
