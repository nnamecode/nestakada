## Область первой когорты

Предложенный save принимает закрытый PageInput с operationId/checkReceipt, только editingFrom=current. После реальной child revalidation отправленные changes должны точно совпадать с одобренными normalisedChanges; normalization не принимается скрыто во время записи. Проверяется подпись и актуальный контекст, затем существующий DEV05 commit_owner/commit_employee создаёт настоящую automatic revision. Draft/stage restore в этой когорте явно неподдержаны. Произвольный Snapshot/author/policy/renderer/layout/media/URL/права не становятся клиентскими полями.

Фактические URL name, response keys/error codes и replay admission уточняет root после freeze; сценарии не выдумывают DOM/технический API. Успех доказывают PG current+immutable revision+refs+operation receipt+audit, а не HTTP200 само по себе. Публичная выдача DEV08, editor UX и весь DEV07 остаются отдельными gates.

Fixture: настоящие owner, назначенные text-only и price employees, чужой employee/visitor; Page с primary Route и current, отдельный owner draft-canary, ordinary history и Stable, синтетический текст/прайс. Начальные снимки/grants/Stable создаются штатными trusted APIs; проверяемое сохранение выполняется через настоящий handler, не seed SQL. Для медиа используются только фактические доступные Asset/ref APIs после готовности интеграции; fake READY запрещён. Уборка только собственных live fixture IDs, с сохранением permanent identity/operation/audit семантики.

Пока API visual adapter не получен; selectors, exports, bundle paths и URL не выдумываются. До готовности используются только план и реальные ранее утверждённые Playwright/package artifacts. QA-only synthetic shell проверяет сам adapter, а будущая product page — реальную интеграцию; shell не называется публичным renderer или готовым editor save.

## Подготовленный product browser subset после API freeze

`tools/editor_http_probe.mjs` подготовлен для16 групп; наличие полного PASS заранее не утверждается. EH008 проверяет фактическую ProseMirror transaction после check, новый проверенный текст и CSSStyleSheet.insertRule fault с блокировкой прежнего proof/save до явного повторного check. EH009 проверяет server-valid пустой anchor: принятие canonical source, HTML-only fallback и actual save без потери anchor/text. EH010 выполняет настоящий logout владельца, login назначенного сотрудника в том же browser context и reauth исходной вкладки; ожидает очистку editable DOM и initial JSON, блокировку controls и отсутствие POST прежнего owner input. Эта проверка не заменяет отдельный EH005 lost-response/same-user reauth exact replay. EH011 меняет generation того же сотрудника настоящим password-reset, сохраняет RAM при попытке Check со старым контекстом и требует явного reauth/check/save. EH012 меняет пользователя и нажимает Save напрямую, без предварительного reauth: ожидается terminal identity lock с очисткой прежнего editable DOM/JSON/canary, а не UNKNOWN или отправка owner input. Scope очистки — известные ссылки/DOM и GC, не физическое обнуление памяти.

Усиленный EH002 сохраняет точное сравнение server-approved→adapter export→server recheck. Кэш исходника сам по себе не доказывает точность parser: реальная keyboard transaction добавляет EDITED, export обязан отличаться и содержать правку, а повторный server check остаётся стабильным. Undo до сброса основы возвращает точный прежний approved HTML; загрузка отредактированного server-approved HTML сохраняет canonical export, opaque source и форматирование. TreeWalker находит настоящий текстовый узел emoji: computed font-size12.5px/color rgb(17,34,51) проверяются у его parentElement, наличие closest strong — отдельно, при первой и повторной загрузке. Oracle не навязывает порядок вложения strong/span. Диагностический adapter-roundtrip.json при исходном mismatch содержит только фиксированную синтетику EH002, без proof/секретов. Probe SHA256 текущего freeze:736c4245f92f99578d00fcf899dd983c92054f0b532d5bf42a06e15ff49c9bf1.

Существующий raw paste/drop testcase инструментирует только String-canary проход в innerHTML/DOMParser и сеть, не запрещает harmless approved parsing. Safe text paste является самостоятельным положительным контролем. Opaque tables проверяются как точный approved-source fallback, без обещания rich TableMap GUI.

## Readiness и ожидаемый закрытый контракт

От root после frozen save source: exact route/name/JSON result/errors; различие new commit и exact replay admission; проверка нормализованного proof без молчаливого изменения входа; engine typed Snapshot/TextPricePatch construction и origin/current-policy/grant checks; error mapping/receipt read/gone; безопасные fault seams и fixture APIs. У DEV05 engine owner fingerprint включает полный Snapshot digest, employee — typed changes; replay выполняется до base assertion. Следовательно HTTP replay не должен преждевременно отказывать только из-за продвинувшегося base и не должен пересобирать прежний owner snapshot из новой current так, что exact operation меняет fingerprint. Этот нюанс проверяется S07-007/008/009, реализацию определяет автор.

От исполнителя adapter: фактические approved artifact paths/exports, load/export/commands/ready/error contract, closed carrier/schema mapping, stylesheet/CSSOM ownership, table/protected readiness и реальный test entrypoint. До этих данных browser probe/API/DOM не создаются.

После отдельного разрешения: `test_save_http.py` с реальными PG/login/CSRF/child/DEV05 positives и ограниченным framework reader seam; затем реальные socket/parallel/fault и browser evidence. Client не объявляется Nginx; seeded snapshot не объявляется browser save; mocked child не заменяет реальный positive; прежние H07/V05 результаты связываются только с фактически повторно проверенными границами.
