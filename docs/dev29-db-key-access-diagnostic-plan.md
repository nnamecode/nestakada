# DEV-29 — диагностика доступа DB к TLS key

После единственного Q026: cp внутри PID1-supervisor получил Permission denied при чтении /run/secrets/database-server-key. Санитизированный savedstream изучен исполнителем без вывода raw logs, Env или ключей. Это не разрешает повтор Run и не меняет frozen package42.

Предлагаемый следующий шаг — только metadata/code review:

1. Сопоставить согласованные UID/GID DB999, readonly TLS bind и последовательность supervisor до INITDB.
2. У известного исходного TLS-файла проверить лишь тип regular/reparse, размер, metadata доступа и код штатного создания; содержимое/ключ не читать и не выводить, ACL не менять. Не делать широкого поиска.
3. Подготовить минимальный способ обеспечить чтение UID999 только в новой изолированной копии, сохранив исходный ключ, ACL, readonly mount, caps и runner. Способ пока не выбран и не утверждён.
4. Независимое ревью конкретного предложения до кода и любых новых native-действий. Новый Run не входит в этот диагностический план.

Лимиты: один известный файл за чтение, вывод до1700символов; первая ошибка требует причины повтора/нового условия, вторая эквивалентная — остановка по AGENTS. Docker/SQL/старый сайт/VPS не затрагивать. Никакие секреты, private proofs и raw logs не добавлять в Git.
