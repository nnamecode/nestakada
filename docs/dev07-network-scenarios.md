## Граница и обязательная подготовка

Только собственный локальный test stand, существующие pinned images/packages/caps. Публичный сайт/VPS, новые зависимости, расширение ресурсов или production deploy не используются. App остаётся768MiB/1CPU/pids128, child AS384MiB/CPU10/wall20, один heavy slot и настоящий body120s. Не подменять child, таймер, reader, очередь либо результат нормализации ради сетевого PASS. Конкретный технический проект готовится отдельно в dev07-network-checks.md; отсутствие его утверждённых условий означает readiness pending.

Точный источник изменений среды проверяется до исполнения: environment/foundation/compose.yaml запускает runserver с --noreload --nothreading; прежний F overlay эту команду не меняет. Однопоточный сервер не доказывает одновременное обслуживание двух HTTP запросов. Нужен отдельно проверенный TEST-ONLY concurrent режим того же Django без новой server dependency и без повышения caps. Текущее streaming location для трёх POST не задаёт явный upstream timeout; его прежний/default timeout может оборвать соединение раньше120s. Значения test overlay должны быть заранее зафиксированы техническим ревью так, чтобы измерять app deadline, а не подменять его ingress timeout. Этот документ сам их не устанавливает.

Неполный A становится barrier только после двух наблюдаемых фактов: actual application heavy-slot inode занят чужим fd при неблокирующем пробном flock и пассивный observer подтвердил настоящий reader-enter. Клиентский write/sleep сам по себе не доказывает, что Nginx уже передал запрос в приложение. Наблюдатель открывает именно собственный проверенный slot, закрывает свой fd после каждой пробы, не unlink/replace lock-file и не удерживает его вместо A. Readiness probe не является повторной отправкой пользовательского действия. При недоступном reader witness сценарий остаётся pending; absolute120 измеряется от reader start, не от TCP connect.

Параллельный PG lock probe использует отдельное соединение и только неблокирующие transaction advisory try-locks в прежнем порядке CONTENT_LOCK→AUTH_LOCK (7342810401→7342810301). Всегда rollback/close; он не меняет Page/grants и не держит lock во время измерения A. Получение этих locks доказывает именно эту область, а не отсутствие всех возможных PostgreSQL locks. Дополнительные phase/child/read counters допустимы лишь как отдельно проверенное пассивное test instrumentation, вызывающее настоящие функции без изменения результата. Без него статус503 не доказывает «child не запускался» сам по себе.

## Данные, state oracle и приватность

Предпочтительно переиспользовать без изменения tools/editor_embedded_http_fixture.py SHA256772b02f4721a8fe65e08ac6e17fecf03e7b98e6b5492ce97b58462675c32abb5: seed/observe/close, run-owned owner+assigned/foreign employee, две Page, точный migrated SYSTEM route и сохранение permanent ledgers. Простые синтетические тексты достаточны; network scope не требует создавать фото или fake READY. Fixture не получает произвольных HTTP/FS команд. Если понадобятся новые passive observation операции, отдельный новый scoped helper проходит review; старый frozen fixture не ослабляется.

Перед A, после отказа и после recovery сравниваются current/history payload hashes/IDs, drafts/stages/pins, asset usages/files и content-operation receipts/version audit. DomainHash fixture сам по себе не включает все receipts: их набор и versionAuditCount сверяются отдельно. Auth/session touch и bounded denial audit учитываются отдельно от content mutation. На неполном JSON/Check/Busy/deadline не создаются новый current, draft, stage, successful content receipt или CheckReceipt. Положительный явный Save создаёт только ожидаемую одну версию/receipt; точный replay не создаёт вторую.

Cookie/CSRF/password/checkReceipt/operation body хранятся только в приватной памяти/проверенном private seed, не в argv/URL/evidence/logs. Отчёт содержит fixed case/phase codes, status, числа/времена/byte counts, безопасные own IDs и синтетические hashes. Не сохранять raw socket headers/body, browser trace, request HTML либо дамп пользовательских значений. Проверка no-input emission ограничена реально наблюдавшимися app/ingress/audit/tmp носителями и own canary; один grep не означает отсутствие любых копий. Socket/header readers имеют отдельные верхние bounds, все writers/timers/contexts завершаются до fixture close.
