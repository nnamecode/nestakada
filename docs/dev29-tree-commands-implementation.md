# DEV-29: реализация трёх команд структуры

2026-11-03, **DEV29-Q001 согласован владельцем по D-405**. Исходное предложение/план CMD29-001–008 и его независимое review сохранены с прежним SHA. Это текущий кодовый кандидат, не результат тестов и не завершение DEV-29. DEV-29 около5%, этап8 около31%.

content.tree_commands выполняет rename/move/reorder из autocommit в одной transaction.atomic: общий contentlock → authlock → повторная owner/security/session проверка → все Page rows в UUID-порядке. Согласованный малый домен позволяет блокировать всё дерево на короткую фиксацию, без сети или перекодирования. Повторно прочитанные поля Page.save сохраняют фактические publication/kind/URL/содержимое/Stable и права.

Подписанное основание привязано также к конкретному operationUUID формы. SHA охватывает Page/Route/current revision IDs и число неизменяемых tree receipts; это защищает от A→B→A. Подпись/CSRF/сессия/привязки обязательны и при replay; точный receipt распознаётся до freshnessCAS, но после проверки полномочий. Изменённый ввод с прежним UUID не применяется. Старый успешный replay не откатывает более позднюю команду.

Существующие OperationReceipt/IdentityReservation хранят только разрешённые структурные metadata/hash, action tree_* и result_code tree_applied; result/source/targetrevisionIDs null. Serializer и pages_links audit отдельные от VERSION-процесса. Результат, UUIDreservation и аудит атомарны с Page. Новых таблиц/миграций/TTL/произвольной очистки нет.

Для переноса GET-предпросмотр выбранного раздела показывает подходящих соседей; этот GET не пишет receipt. POST имеет явный URL без query и hidden destination, связанный с основанием. Порядок в БД0..N−1, интерфейсposition+1. При ошибке сохраняются старые operationUUID/token/ввод; свежий token не подставляется незаметно. 503 не заявляет доказанный rollback при неопределённом COMMIT: предлагается точный повтор. Получение актуальной формы — отдельный явный переход. POST success/replay возвращает303 на фактическую текущую ветку.

Кандидат содержит26новых PostgreSQL/Django tests: сохранность current/Stable/URLs, real2connectionCAS/grant/content/Stable races, реальное ожидание advisorylock с последующим ownerreset, подписи/ABA/replay, частичный SQLfailure, injectedENOSPC при receipt/audit с whole rollback и sameUUIDretry, CSRF/privateHTTP/forms.
