# Исправления безопасности локальных базовых образов

2026-10-30. Задача ENV-07; основания **D-314** (разобрать, исправить и независимо проверить) и **D-315 / TEST-Q009** (согласованный состав исправлений). Текущий этап — 7; код сайта, старый сайт и VPS не изменялись.

## Результат для владельца

Подготовлены три закреплённых локальных runtime-образа. Исправлены найденные проблемы неиспользуемых пакетов Nginx, встроенного OpenSSL Python-адаптера и XML-парсеров PostgreSQL. Наши две новые нативные сборки имеют штатные защитные флаги Debian. Испытания выполнены на синтетических данных; контейнеры выключены, старые образы/тома и свидетельства сохранены.

Это подготовка основы для разрешённой в будущем локальной DEV-02/DEV-28, **не готовый сайт и не разрешение его писать или публиковать**. Проверка приложения и production ещё впереди. Реестр не обнулён: неподтверждённые и отложенные поставщиком записи остались видимыми.

Удаление файлов пакетов относится к объединённой runtime-файловой системе. Исходные слои и старые образы остаются в локальном Docker-кэше для воспроизведения и сравнения; это не утверждение о физическом удалении байтов из всех слоёв. Они не выбраны текущим runtime-lock.

Исходники приложения в образах отсутствуют. Компиляторы находятся только в builder; сборки после получения и проверки входов выполняются без сети. Пароли, ключи и данные fixture не передавались в build context или build args.

## Проверки конечных артефактов

- **PostgreSQL:** 231 штатный upstream core regression test прошёл на последней hardened-сборке. Предыдущий запуск того же набора не суммируется с этим числом.
- **Типы и совместимость:** PostgreSQL 18.6 / C-адаптер 3.3.6 / libpq 17.11 работают совместно. Проверены Decimal, JSON, UTF-8/кириллица, обычные SQL-типы, pgcrypto и pg_trgm; runtime CRUD откатывается, запрещённые DDL/смена роли не получают дополнительных прав.
- **Locale:** provider, locale/version и весь контрольный набор сортировки/upper/lower совпали с исходным Debian-стендом. Это характеристическая проверка набора строк, не доказательство равенства всех Unicode-случаев и не новое бизнес-правило.
- **Аутентификация/шифрование:** проверены SCRAM и TLS verify-full с собственным тестовым CA; подтверждён TLS 1.3. Неверные имя сервера, CA и пароль отклонены при доступном исправном сервере. Это не проверка production-домена/сертификата. Тестовый CA однодневный и не предназначен для дальнейшей эксплуатации.
- **Негативные XML-проверки:** XMLPARSE, cast к xml и xpath не исполняют парсер, возвращают штатное отсутствие возможности. Это согласованное D-315 отключение SQL-функции БД; XML-карта сайта не зависит от неё.
- **Резерв/сохранность:** собственные pg_dump/pg_restore с контрольными записями прошли; после пересоздания контейнера с прежним собственным томом данные и TLS сохранились. Старые dev/test-тома в новую сборку не подставлялись. Это проверка инструмента, не полный TEST-08/restore AC сайта.
- **Nginx:** после удаления пакетов повторно прошли host/Docker→loopback→свой upstream, очистка forwarded-заголовков, отказ unknown Host/absolute URL/CONNECT и недоступность БД/чужого app из namespace Nginx. Ограничения D-313 readonly/nonroot/capDropALL/NNP/128MiB/0.25CPU/pids64 сохранены.
- **Python:** CPython 3.14.10, Django 5.2.18 и django-csp 4.0 импортируются; реальный CSPMiddleware сформировал report-only заголовок. Все 8 установленных Python distributions, включая pip, проверены по PyPI metadata — объявленных advisory нет на момент проверки.

Пробы используют реальные процессы/библиотеки/SQL/TLS/HTTP, но не подменяют отсутствующее приложение. **11 FOUNDATION-сценариев приложения не запускались**, полные 140 AC не объявляются пройденными.

Они соответствуют 84 исходным ID; новых совпадений вне исходного реестра не обнаружено. Повторы одного advisory в двух образах не являются отдельными уникальными CVE. Эти записи не объявлены «исправлены все CVE». Production-согласование и принятие оставшихся эксплуатационных рисков этим отчётом не подменяются. При расширении функциональности меняется и применимость старых записей.

### Сборочный setuptools

Source psycopg-c требует setuptools 83.0.0. Его единственный обнаруженный GHSA-xmj3-9gf7-h52w относится к Windows legacy install_as_egg. Наш builder — Linux, pip/offline, проверенные wheels; соответствующий Windows-путь не исполняется. Это конкретная оценка неприменимости, не wildcard-исключение проверки advisory. Setuptools отсутствует в runtime. Любая другая/новая запись по этому набору останавливает подготовку до разбора. Подробное первичное metadata сохранено локально, результат проверяется независимым рецензентом.

## Воспроизведение и свидетельства

- `environment/foundation/images.lock.json` — **только upstream build materials**, не список образов для запуска. Старый PG используется лишь как источник штатного entrypoint, старый Python-бинарный bundle не входит в runtime.
- `environment/foundation/runtime-images.lock.json` — три конечных runtime ID, отдельные OCI export/config digests, hashes рецептов/входов/receipts. Docker-reported .Id/.Image не приравниваются к OCI config digest: текущий containerd-store возвращает иной идентификатор.
- `source-archives.lock.json`, `python-build-inputs.lock.json`, `postgres-build-inputs.lock.json`, `nginx-build-inputs.lock.json`, `requirements.lock` — точные источники, версии и хэши. C-wheel собран для Linux amd64/CPython 3.14 и хранится на T:; он не является скачиваемым PyPI binary wheel.
- `runtime-components.cdx.json` — инвентарь CycloneDX фактически проверенных OS/Python/upstream PG компонентов. Это компонентный SBOM, не заключение о всех лицензиях, статически встроенном коде или неизвестных CVE.
- `receipts/*.json` — BuildKit provenance/identity. Публичные входы сохранены в `work/foundation-security-20261030/`; private-папки, тестовые ключи/пароли и дампы — вне Git с отдельным scope/ACL.

**При пересборке обязательно явно указывать `--file environment/foundation/<рецепт>`**. Исторические `python-context/Dockerfile` и `pg-context/Dockerfile` оставлены для cache/history и не являются текущим определением. Контексты содержат только подготовленные публичные inputs; ни корень репозитория, ни private-папки в build не передаются. Хэши контекстных артефактов проверяются до компиляции, установка Debian-пакетов не использует force-depends. `dpkg --audit` пуст.

Готовые проверенные образы запускаются по зафиксированному Docker ID, а не по меняющемуся тегу. Nginx запускается entrypoint=nginx с конкретным readonly конфигурационным файлом и tmpfs; PG слушает свою internal-сеть по явному `-c listen_addresses=*`, без host-портов. Секреты/сертификаты генерируются отдельно; тестовые секреты не становятся образцом production.

Наша сборка PG и системные библиотеки требуют повторяемой подготовки нового образа при обновлениях. Ничего не обновляет работающий VPS или компьютер владельца автоматически. Старые артефакты сохраняются для воспроизведения, runtime-lock выбирает проверенный конечный состав.
