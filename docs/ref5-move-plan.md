# REF-05J — простой move страниц

Дата: 2026-11-05. Статус: завершено по D-623 (2026-11-06); независимое review `APPROVED`.
Область: только перенос существующей страницы в другой раздел либо в корень с выбором места. Создание/удаление страниц, URL, публикация, schema, legacy-код и production вне инкремента.

## Зачем упрощаем

Старый `move`, как прежние rename/reorder, хеширует всё дерево, все routes/current revisions и счётчик receipts, а затем создаёт новый `OperationReceipt`. Фактически перенос затрагивает только переносимую страницу, исходную sibling-группу, целевую sibling-группу и цепочку родителей назначения, необходимую для запрета цикла.

## Приёмочные сценарии

- **MOVE-001 — права и сессия.** GET/POST доступны только владельцу с актуальными generation/editor-session; authoritative проверка выполняется до разбора token. Сотрудник и прямой запрос не меняют данные.
- **MOVE-002 — точное назначение.** Token связывает actor, generation, page, operation, исходный parent, выбранный destination и снимки затронутых строк. POST не может подменить destination; `before` должен принадлежать выбранному destination либо быть пустым «в конец».
- **MOVE-003 — запрет циклов.** Нельзя назначить parent самой странице или любому её потомку. Проверяется фактическая locked цепочка destination→root, а не только список в интерфейсе.
- **MOVE-004 — локальная транзакция.** Успех атомарно меняет только `parent_id/position` переносимой страницы, позиции siblings исходного и целевого parent и создаёт ровно один `TREE_MOVE` audit. Name/kind/publication, routes, revisions, Stable/drafts/media и остальные ветки неизменны.
- **MOVE-005 — нормализация.** После успеха обе затронутые sibling-группы имеют уникальные позиции `0..N-1`; переносимая страница стоит непосредственно перед выбранной страницей либо в конце. При одинаковом parent работает локальная перестановка без двойной записи группы.
- **MOVE-006 — stale/ABA/concurrency.** Locked PostgreSQL `xmin` target, обеих sibling-групп и destination ancestry отклоняет добавление/удаление/перемещение/изменение relevant row, ABA и второй concurrent submit. Несвязанная ветка не инвалидирует форму.
- **MOVE-007 — no-op.** Команда с тем же parent и фактически тем же порядком/нормализованными позициями отклоняется без audit и записи.
- **MOVE-008 — отсутствие нового ledger.** Новый move не создаёт `OperationReceipt`/`IdentityReservation`. Повтор после успеха или потерянного ответа конфликтует; актуальный GET показывает фактическое дерево.
- **MOVE-009 — rollback.** Ошибка audit откатывает parent и все позиции; DB/OS failure возвращает управляемый 503 без частичного дерева.
- **MOVE-010 — совместимость.** Существующий legacy `tree_move` receipt направляется в прежний exact replay, cross-action UUID конфликтует. Simple rename/reorder не меняются. Delete и REF-Q004 остаются закрыты.

## Проверка

Сначала focused command/HTTP/fault/concurrency тесты, затем полный `content`, затем `media_library + page_versions`. После — независимое review, read-only main DB/login и остановка `foundation-test`. Production, VPS и старый сайт не затрагивать.
