## DEV06-Q001 — политика новых загрузок

| Параметр | Предлагаемый профиль |
|---|---|
| Вход | Только одиночные JPEG (.jpg/.jpeg,image/jpeg), PNG (.png,image/png), WebP (.webp,image/webp) |
| Проверка | Расширение, заявленный MIME и фактически декодируемый формат согласованы. Повреждённые файлы и проверяемые случаи подмены/активных форматов не становятся пригодными Asset; универсальное обнаружение любого polyglot не обещается. Публикуется только вновь закодированный WebP |
| Анимация | Не принимать GIF/APNG/анимированный WebP, не молча выбирать первый кадр |
| Объём | Один файл до1МБ (1000000байт) за запрос, multipart body до11МиБ, до40миллионов пикселей и10000px по каждой стороне; значения не обрезаются для обхода отказа |
| Публикуемый результат | WebP,image/webp; основная сторона до1920px и превью до480px, без увеличения маленьких картинок; сохранение пропорций/прозрачности, ориентация EXIF применена |
| Сжатие | Начальный quality82; оценить на реальных новых фото до приёмки, не обещать одинаковые50–100КиБ для всех сюжетов. Режимlossy называется lossy, не lossless |
| Метаданные | В новом публичном результате нет EXIF/GPS/произвольных текстовых метаданных; приватный исходник хранится отдельно без публичного URL |
| Исключение |214оригиналов галереи копируются побайтно по независимому реестру, без переориентации/сжатия/смены метаданных, даже при использовании вне галереи |

Принятие профиля даёт независимый oracle: позитивные JPEG/PNG/WebP, прозрачность/ориентация, точные byte/pixel/side границы, отклонение MIME/extension подделок, active/animated/повреждённых файлов, приватность исходника и MIME/nosniff результата формулируются до upload-кода и проходят ревью. Сам факт приёма сервером не определяет allowlist.

## DEV06-Q002 — локальный обработчик

Pillow13.0.0: официальный релиз16.10.2026, заявлена поддержка Python3.14. Источник: https://pypi.org/project/pillow/13.0.0/ . Security-профиль и предупреждения о decompression/metadata bombs: https://pillow.readthedocs.io/en/stable/handbook/security.html . Проверено31.10.2026, это не доказательство отсутствия всех CVE.

Предлагается отдельный локальный Docker-обработчик на уже закреплённой Python-основе: Pillow13.0.0 из официального артефакта с SHA256, фактическая инвентаризация его встроенных native codecs/SBOM и проверка advisory перед допуском. Нынешние образы app/БД/Nginx не подменять. Обработчик не получает сеть, Docker socket, пароли/БД/файлы приложения или всю медиатеку. Через отдельный ограниченный exchange получает один новый входной файл и возвращает только заданные результаты. Управление — фиксированный локальный Unix socket в собственном общем Docker-томе, не публичный HTTP и не произвольная команда.

Лимиты:512МиБ RAM/1CPU/pids64 для контейнера, один job одновременно,15с бюджета обработки одного job,128МиБ на отдельное временное пространство/exchange: предлагается общий Docker tmpfs с явным size, а не обычный named volume без квоты. Это расход памяти; жёсткое ограничение и failure-поведение должны быть доказаны фактической проверкой. Непривилегированный UID, readonly rootfs, cap-dropALL/no-new-privileges. Отказ/timeout/заполнение не дают пригодного Asset и не удаляют чужие файлы. Конкретная конфигурация и фактическая изоляция проверяются независимо до использования. Это бюджет работы программы, не срок действий владельца.

Что изменится на компьютере: дополнительный локальный Docker-образ с Pillow/codec-артефактами, один worker service, артефакты наT: и отдельный временный exchange в памяти Docker. Без установки в Windows/PATH/службы/автозапуск и без обращения к VPS. Точное дисковое место измеряется после получения артефактов, до этого не выдаётся за факт. 512МиБ — верхний предел, не постоянное фактическое потребление.

Альтернатива — обработка в контейнере Django; она проще по числу компонентов, но декодер оказывается рядом с секретами приложения. Рекомендую отдельный worker. Если отложить выбор — можно завершать только модели/storage/retention, не объявляя всюDEV-06 выполненной.

После согласования разрешены локальная подготовка/проверка указанного компонента и upload/worker-код только после положительных и boundary сценариев/ревью. Production/VPS/автоматический перенос/внешние хранилища этим не разрешаются. Полный перенос214оригиналов и приёмка всех альбомов — DEV-09/10, когда будут фактические байты и связи.

Независимое предварительное чтение31.10.2026: блокеров вынесения нет; до допуска обязательно доказать положительные40MP+RGBA/ориентация в512МиБ/15с. Если бюджет не подходит, корректировку выносить владельцу, не сокращать молча согласованный формат/размер. Политика tmpfs/exchange проверяется физически, не только полем YAML.
