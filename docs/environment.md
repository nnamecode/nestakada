## Рекомендация для GitHub — ожидает согласования

1. Создать приватный репозиторий `estakada-service` в своём аккаунте. Для подключения существующего проекта оставить его пустым, без автоматически созданных README, .gitignore и лицензии. https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository
2. Передать URL репозитория, имя автора коммитов и GitHub noreply-email (или выбранный адрес). Пароли и токены в чат не передавать. Авторство задать локально только в этом репозитории.
3. Использовать HTTPS с Git Credential Manager либо gh auth login через браузер; возможен SSH. Выбор сделать после проверки доступного окружения. Двухфакторную защиту аккаунта GitHub включить независимо от решения о входе в админку сайта.
4. После появления CI настроить main: изменения через ветки/PR, обязательные успешные проверки и запрет force push, если правила доступны на тарифе. Не требовать второго человеческого одобрения, если владелец работает один.
5. Включить доступные Dependabot alerts/security updates; проверить доступность сканирования секретов и других защит для приватного репозитория на текущем тарифе. Не обещать доступность платных функций. https://docs.github.com/en/code-security/getting-started/quickstart-for-securing-your-repository
6. Actions — минимальные разрешения; secrets отдельно; без автопубликации на живой сайт.

Git хранит историю исходников, а не резервные копии базы и пользовательских фотографий. Встроенный .gitignore — вспомогательная защита, не замена просмотру отправляемых изменений.

## Docker — предложение

Docker упаковывает приложение и зависимости в воспроизводимое окружение. Для проекта рекомендуется Docker Compose: Django и PostgreSQL; прочие сервисы добавлять только по необходимости. Контейнеры не заменяют безопасность и резервные копии; данные базы должны храниться в постоянном томе.

На Windows обычно нужен Docker Desktop с WSL2 и включённой аппаратной виртуализацией. Проверить требования ОС и действующие условия лицензии перед установкой: https://docs.docker.com/desktop/setup/install/windows-install/ . Установка может требовать администратора, изменения Windows и перезагрузки — такие действия отдельно согласуются с владельцем.

Координатор подготовит Dockerfile, compose-конфигурацию, пример env без секретов, healthchecks и команды запуска после согласования архитектуры. Для публичного сервера: отдельная production-конфигурация, база без публичного порта, непривилегированный процесс и резервирование. Образ и зависимости фиксировать на проверенных версиях; не использовать плавающий latest как политику выпуска.

Если Docker пока недоступен, документы и дизайн можно делать без него; локальную разработку можно организовать через venv и отдельный PostgreSQL. CI и рабочее окружение должны использовать одинаковые основные версии базы и Python.
