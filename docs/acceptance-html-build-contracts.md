# Ночные HTML-наборы: подготовка TEST-06

2026-10-30. Основания: D-280/D-281/D-295/D-296/D-300, принятые D-301 AC-047/AC-HTML-005/006/007/010, D-302/D-307/D-308. `acceptance/html-build-contracts.spec.js`:12 частичных экземпляров. Это код проверок, не генератор сайта/реализация builder/gate/controller и не действующий production-резерв. Сайт/VPS/старые файлы не используются.

## Область и ограничения

- Rotation/published-routes/private-exclusion (3): новый набор проходит настоящую сборку/проверку, становится active, прежний active остаётся previous; oracle публичных маршрутов независим от результата. Проверяются фактические небольшие файлы синтетического набора и отсутствие существующих закрытых canary.
- IO-fault phases (5): prepare/validate/retain-media/activate/cleanup. До активации ошибка не выбрасывает два исправных набора. Если ошибка случилась после фактической активации, допускается выбранный новый **целиком проверенный** набор с предыдущим исправным: ошибочный job-state не подменяет факт указателя/байтов/полного manifest/media retention. Cleanup неполон и наблюдаем.
- Validation barrier/media barrier (2): unverified candidate не выбирается заранее, удержание нужных медиа подтверждается до active. Барьеры относятся к настоящей операции, не к модели expected.
- Page coherence (1): в момент сборки владелец атомарно публикует text+H1 одной Page. Успешный набор содержит старую либо новую целую пару, иначе сборка безопасно отклоняется. Не вводится неутверждённая общая транзакция для независимых правок Footer/прайса; эти дополнительные гонки остаются отдельно.
- Day edit (1): в зафиксированном дневном окне настоящая правка Page не порождает новую сборку и не маскируется обновлением snapshotAt. Ночью изменяемые ссылки/цены могут устаревать по D-295/D-300.

Число12 не закрывает целые AT-047/205/206/207/210. Не испытаны фактический пик расхода диска/третий временный набор, атомарность OS/primitives/краш/долговечность, все race с отзывами/путями/прайсами/блоками/кодировками, реальная форма JS/noJS и все каналы утечек. Быстрые10с poll — граница теста маленькой fixture, не SLA сборки или срок реакции владельца.

## Изолированная подготовка

До reset фактический read-only inspectInfrastructureAdmission подтверждает ARC-10/isolation/evidence и html-build-control-v1; отсутствие даёт отказ, не skip. Профиль html-two-good-sets-published-source содержит два действительно завершённых проверенных набора, реальные небольшие HTML/manifest/media и опубликованные маршруты `/`, `/acceptance/night/service/`, `/acceptance/night/second/`. Они синтетические, не новая публичная структура Эстакады. Нет активных клиентов старейшего retired-набора; usableSetIds означает два выбираемых исправных набора, не все исторические записи каталога.

P-NIGHT изначально имеет известные независимые NIGHT-OLD-TEXT/H1; настоящий owner submit-page-direct меняет оба поля одной операцией. Для дневного профиля html-two-good-sets-frozen-daytime test scheduler/часы **собственного процесса стенда** зафиксированы в дневном слоте, задания не просрочены. Реальные часы Windows/VPS/пользователя не меняются, конкретное время ежедневного расписания production не выбирается.

В реальных приватных source-объектах есть четыре разные ASCII-canary для page-draft/page-history/request/technical-token, подтверждаемые html-private-source-proof. Они не копируются в ожидаемую выдачу и не маскируются наблюдателем перед проверкой. В публичных источниках есть NIGHT-PUBLISHED-CANARY: пустой/фиктивный набор не считается успехом. Отрицательная проверка literal canary в сырых файлах не закрывает все возможные кодировки/каналы сериализации.

## Действия и наблюдения

Control-команды на **другом локальном origin вне APP/EDGE**: run-isolated-html-build, set-html-build-fault, clear-html-build-fault, hold-html-build-phase, release-html-build-phase, drain-isolated-html-jobs. Это фиксированные test-only команды настоящего builder/scheduler/IO/barrier, не product endpoints. Они не могут устанавливать state=READY/FAILED, подменять указатель/manifest/байты или вычислять expected. Запуск с trigger=scheduled-night-slot воспроизводит настоящее задание/источник snapshot; не создаёт расписания/cron на машине владельца. Controller атомарно проверяет run/instance/admission/capability до исполнения; одних echo заголовков недостаточно.

Fault допустим только на контролируемой границе IO собственного run/test-storage. Он должен действительно заставлять job выполнить путь отказа; нельзя просто переименовать успешный результат в FAILED. Это логические boundary-fault проверки, не факт заполненного диска VPS/хоста или ресурсной достаточности. Для реального physical-full испытания необходим отдельный ограниченный стенд/подтверждённый ARC-10; чужие/действующие файлы не затрагиваются.

html-set-inventory читает реальные activeSetId/previousSetId/usableSetIds и результат проверки. html-build-run(jobId) связан с конкретным job, даёт фактические state/phase/setId/safeErrorCode/cleanupIncomplete/mediaRetentionVerified. Команда accepted означает лишь настоящее принятие команды, не READY; finish читает отдельный terminal-state. Доказательство сбоя html-build-failure-evidence — реальный incident той операции.

html-build-ledger.jobCount в дневном сценарии — фактическое число **начавших выполнение** builder jobs. Само хранение настройки/дескриптора следующего штатного ночного запуска не объявляется выполненной дневной сборкой. drain исполняет только действительно due задания при зафиксированном дневном времени, не переводит часы в ночь и не запускает новый build вместо проверяемого поведения.

html-set-byte-inventory возвращает только **маленькие синтетические** фактические файлы выбранного набора: source=actual-storage-bytes, relativePath/route/bytesBase64/size/sha256. Тест сам пересчитывает байты/SHA; before/after сохраняет прежние исправные файлы. Источник/полнота списка проверяются при независимом ревью конкретного bridge, метка сама не доказательство. Крупный архив production через stdio не передаётся.

Каждый из трёх независимых ожидаемых маршрутов обязан иметь ровно один actual HTML-file; route в inventory берётся из настоящей связи manifest→конкретный path/байты, не назначается списком expected в observer. Manifest publicRoutes и actual route/file set совпадают без потерь/дублей. У главной есть NIGHT-PUBLISHED-CANARY, у второй страницы NIGHT-SECOND-PUBLISHED-CANARY, у service — её собственный NIGHT-OLD-TEXT либо атомарно опубликованный NIGHT-NEW-TEXT; один файл главной при трёх строках manifest не проходит. Сравнение неизменных файлов сортируется по относительному пути и использует только стабильные path/route/size/hash/bytes, не время чтения/порядок filesystem enumeration.

html-set-manifest/set-media-retention читают настоящий manifest/ссылки и действительные существующие Asset; required/retained/existing списки не вычисляются по ожиданию. Их роль — проверка ещё отсутствующего builder/gate, не применение current Page-файлов вместо снимка. XML/HTTP-публичность самого служебного manifest здесь не объявлена проверенной.

Rotation/media-barrier дополнительно читают html-build-activation-ledger того же job: actual media-retention-committed для конкретного setId имеет строгую меньшую монотонную sequence, чем actual active-pointer-committed. Требуются обе непустые записи и целые sequence; команды/намерение записать удержание не считаются commit. Результат true только к концу job не доказывал бы порядок. Источник ledger должен независимо отражать фактические commits, не заранее рисовать ожидаемую последовательность в observer; физическое доказательство примитива остаётся за ARC-10/реальным стендом.

Инертный parser Page coherence (JS=false, SWblock, HTTP+WS abort) читает H1/текст из фактического HTML. Он не исполняет страницу и не считается полноценной browser/CSP-проверкой. App contexts отдельны. Конкретные bindings/controller/архитектурные примитивы отсутствуют, тесты против приложения не запускались; полный TEST-06/TEST-07/ARC-10 не закрыт.
