# DEV07-RSV — положительные shared writes и конечная калибровка

2026-11-01. **Независимые сценарии до кода**, продолжение DEV-07 по поручению владельца; DEV-07 около96%, этап8 около20%. Основания: [аналитика §7](analytics-content-detail.md), [AT-117/AC-DTL-017](acceptance-version-storage.md), [общие блоки](acceptance-shared-blocks.md), [компонентное восстановление](acceptance-shared-component-restore.md), [профиль SH3-QPROFILE](dev07-shared-quota-profile-proposal.md). Прежние52shared/SJR проверяли свои frozen cohorts; они не доказывают включённые положительные writes. Здесь результата ещё нет.

Цель инкремента — реальные успешные owner Draft/Apply/Restore с filemode и надёжным RC, а не очередной набор только503. Сохраняются256МиБ=268435456B,10000 снимков,75% предупреждение, HTML≤1МиБ, один draft каждого kind, независимая история, запрет автоматического удаления. Нет новых dependencies/томов/ресурсов, изменений старого сайта/VPS или production. Точный RC API/profile/lease и новые journal состояния сначала проходят техническое ревью.

## Oracle и finite calibration

Действия — настоящий HTTP с login/CSRF/правами/child/реальными READY Assets. Ни fixture bridge, ни mock admission не выполняют проверяемый Apply прямой записью. Для подготовки большой истории допустимы явно обозначенные собственные DB/FS fixtures; это не успешные пользовательские writes. После каждого принятого commit независимо подтверждаются actual учитываемые bytes≤cap/COUNT≤10000, файл SHA/UTF8/длина, current/draft/history/pins/typed identities/refs/receipt и RC outcome. Другой блок/Page и прежние snapshots неизменны. Filemode не получает fallback на inline.

Калибровка использует **конечный** corpus: (а) холодное создание обоих блоков; (б) оба1МиБ компонента с четырьмя actual Asset slots; (в)32 последовательных обновления одного draft с накопленным MVCC/старыми файлами; (г) Apply текущего/draft/restore-stage и их metadata batch; (д) уже заполненные metadata/реальные10000 снимков; (е) ошибки после book/blob/fsync/metadata/refs/receipt. Это измерения применимого профиля, не универсальная allocator-теорема.

Для каждого случая фиксируются actual baseline, после durable book, после blob, внутри transaction после последнего write, перед commit/после commit, peak наблюдавшейся аллокации, held amount и observed growth. PG roots/indexes/TOAST/forks, свои каталоги/файлы/orphans и RC metadata не прячутся. Наблюдатели вызывают оригинал; готовые успешные ответы/фиктивные размеры не подставляются. Численный запас выбирается **после** этих наблюдений с явно описанным margin/областью применимости, затем замораживается и проверяется тем же corpus заново. Первое измерение не называется accepted-profile PASS. Непредвиденный рост/неполный measurement сохраняет реальный расход и блокирует дальнейший приём; не увеличивать cap/запас автоматически для зелёного теста.

## Global AssetUsage — техническое назначение доли для ревью

SH07-QUOTA допускает измеренную долю общего отношения. Предлагаемый минимальный вариант после обсуждения с независимым рецензентом: `assignedPhysicalShare = ceil(actualPgTotalAssetUsage * ownRefs / allRefs)` плюс отдельно калиброванный new-reference/transient reserve. Это **назначенная доля**, не точные причинённые байты/математический upper bound. Expose actual relation total, own/all counts, assigned share и reserve отдельно; округление целочисленное.

Own refs определяются постоянным typed shared identity ledger и допустимым Usage kind, включая shared revision/draft identities. Нельзя взять все kind=draft: туда входят Page drafts. Неизвестный shared consumer не исчезает из учёта под видом ownRefs=0. При ownRefs=0 доля0; inconsistent counts/ownership —отказ измерения. Числа получают одним согласованным SQL/domain snapshot, затем свежим precommit measurement. Удаление чужих refs может повысить долю без роста root bytes —последующая запись должна увидеть это и отказать при нехватке. Существующее содержимое не переписывается ради нового соотношения.

Отдельный fault oracle: shared ref INSERT с rollback может оставить физический bloat при ownRefs=0. Нулевая текущая доля/отсутствие receipt **не освобождают** durable held reserve; global actual growth остаётся наблюдаемым, его учёт/покрытие подтверждаются RC reconciliation до release. Самостоятельная недоказанная формула retained charge здесь не назначается.

Уточнение принятого технического проекта RC: при доказанном abort после получения content domain, без угадывания baseline, `SharedBudget.retained_debt_bytes` увеличивается на профильный `UsageAbortDebtAllowance`. В той же transaction создаётся terminal aborted SharedReceipt с result=None и привязками полного book SHA/actor/generation/action/fingerprint/profile. Только после commit этого доказанного outcome разрешён controlled unlink именно своей journal записи с fsync/named checks. Отказ admission **до book** не создаёт receipt/debt. Unknown outcome остаётся закрытым и не освобождается по TTL.

Тот же aborted operation ID возвращает409 с outcomeKnown, не исполняется второй раз и не добавляет debt повторно. Reconciliation при оставшемся после unlink fault book повторно подтверждает существующий terminal receipt и завершает release идемпотентно. Full hold обязан покрывать реальные own FS/PG расходы, компонент retained debt, settle metadata и margin; отсутствующий/недостаточный профиль не обходится. Кандидаты4МиБ full hold/512КиБ UsageAbortDebtAllowance **не проверены и не включены**: их достаточность определяет finite corpus и независимое ревью, не константа сама по себе.

Этот вариант ещё **технический проект до ревью/испытаний**. Whole AssetUsage footprint проще, но приписывает Header/Footer несвязанный Page/Stable bloat; не выдавать его за exact attribution. Байты изображений остаются за пределами shared бюджета. Глобальный audit/WAL относятся к отдельно принятой эксплуатационной/log границе; whole Audit relation не добавляется в256МиБ. Ошибка atomic audit/refs и их наблюдаемый рост проверяются, не превращая shared cap в обещание ограничения всего диска.

Draft filemode существует/verified, current/history не меняются до Apply; Apply создаёт ровно один новый immutable filemode snapshot/receipt, меняет только выбранный current. Private owner GET возвращает actual body; literal canary/Asset bytes сохранены. Полная публичная композиция DEV-08 отдельно |

Apply создаёт новую версию, stage consumed, снимаются только его удержания. Старый snapshot/другой блок неизменны; oldphone возвращён буквально. Неподдерживаемая schema отказывает без partial write |
| RSV-003 | Stale current/base и draft revision из второго owner-сеанса. Отказ без silent overwrite/merge; положительное последовательное обновление одного draft сохраняет один draft ID/новую revision и корректную base/pins. Текст/nonce dirty state не заменяется поздним ответом; никакой неутверждённой автоматической rebase |
| RSV-004 | Exact raw operation replay после потерянного ответа/consumed draft-stage/недоступного прежнего source: тот же result ID, одна версия/квитанция/бронь, честный gone без воскрешения. Изменённый fingerprint/source/action под тем же ID —conflict. Metadata-first replay не перечитывает исчезнувшее body и не создаёт новый резерв |
| RSV-005 | Реальная PG session advisory try-lock lease вне SQL transaction. Собственный crash/session close освобождает lease, но durable pending book не исчезает. Reconciliation проверяет фактический outcome, не TTL |
| RSV-006 | Actual faults до/после durable book, partial blob/file-dir fsync, metadata/ref/receipt и commit; отдельно процесс завершается после commit до ответа. Достигнутые fault checkpoints/hit counts, DB/FS manifests и book state различают commit/rollback/UNKNOWN. Known abort атомарно сохраняет terminal aborted receipt+component retained debt до controlled release; exact повтор409outcomeKnown не выполняет действие/не добавляет второй debt. Нет ложного rollback при committed receipt; orphan/bloat/held/debt остаются в учёте. Prebook denial не создаёт receipt/debt |
| RSV-007 | Два настоящих owner-запроса за последнюю count/byte бронь. Один расходует резерв, второй получает свежий Busy/conflict/space denial без очереди/автоповтора и partial content. Проверка реальными независимыми соединениями; последовательные framework calls не выдаются за HTTP concurrency |
| RSV-008 | Реальные9999→10000 snapshots допускаются при достаточных bytes; следующая publish/restore отказывает без pruning. | RSV-009 | Actual остаток меньше next reservation той же операции: publish/restore целиком отказывает, current/history/оба drafts/refs защищены, вход остаётся в настоящей вкладке. Exact inequalities отдельно: remaining==reservation допускает запись, remaining==reservation−1 отклоняет;75%−1/75%,10000/+1. Арифметический oracle не заменяет PG/FS fill |
| RSV-010 | AssetUsage mixed own/Page/stable/draft corpus: independent SQL total/counts/share; unrelated insert/delete/bloat и own ref замена/удаление вызывают fresh recalculation. Повышение assigned share не обходится старым cached budget; приcap overflow приём закрыт, существующие тела/ссылки неизменны. Каждый положительный кейс проверяет авторизацию заново перед commit, actual receipt и fresh RC outcome. Ошибки пользователя/неподдерживаемый вход не должны оставлять новую authoritative бронь без объяснимого состояния. Unknown/malformed/profile-mismatched book всегда fail closed. Ни примитивный SJR unvetted book, ни HTTP-флаг не включают validated profile. Точный released/held/reconciled протокол/коды и count reservation одного незавершённого Apply фиксируются авторским RC контрактом до кода.

## Native UI — отдельные положительные/UNKNOWN проверки

Root реализует JS/template и браузерные проверки в уже принятом Docker Playwright1.64.1; backend QA не меняет эти файлы и не выдаёт framework/state digest за RAM браузера. Input/epoch/cleanEpoch и uncertain intent хранятся только в памяти страницы. Backend acknowledgement содержит свежую basis/source после действия, а dirty очищается только при совпадении epoch отправленного и текущего ввода.

| ID | Настоящий браузерный сценарий и oracle |
|---|---|
| RSV-UI-001 | Native fill→Save, задержать собственный ответ; пока pending, напечатать новый текст. После ответа принятый прежний текст имеет одну версию, новый DOM input остаётся точным/dirty и не заменяется ack/normalization. Следующий явный Check/Save нового ввода использует fresh basis и новый intent |
| RSV-UI-002 | Настоящий Save достиг commit, ответ не принят приложением браузера. UI показывает неопределённый исход и кнопку **ручного** повтора. Кнопка отправляет те же operationId/body/query, без автоматического запроса/нового nonce. Один actual snapshot/result/book, exact replay; источник подтверждения —реальные HTTP и DB/FS |
| RSV-UI-003 | При UNKNOWN пользователь меняет input, затем вручную повторяет прежний uncertain intent. Повтор использует сохранённый прежний body/ID/query, но новый текст остаётся в открытом редакторе/dirty. Ack старого intent не очищает новый epoch и не публикует новый текст сам; после разрешённого исхода отдельный явный Check нового ввода возможен |
| RSV-UI-004 | До/после pending/UNKNOWN/retry проверить фактические actor URL/localStorage/sessionStorage и HTTP payload границы: HTML canary/password/CSRF/proof не переносятся в URL или Web Storage. Ожидаемые cookies авторизации этим не подменяются. Не сохранять raw секреты/HTML в тестовые артефакты; наблюдать только безопасные boolean/hash evidence |
| RSV-UI-005 | Между Check/Save либо перед ручным повтором действительно сбросить auth generation/сессию. Backend отказывает после fresh auth check, нет новой версии/квитанции/расхода; браузер сохраняет свой текст и предлагает действительный повторный вход. Старая generation/proof не становится разрешением под новой сессией |

Потеря ответа в harness обозначается точно: отсутствие потребления response UI либо реальный transport abort —разные свидетельства. Нельзя объявить отсутствие network delivery по одному непотреблённому ответу. Pending/UNKNOWN управление не создаёт скрытую очередь публикаций или автоматический повтор.

## Большие fixtures без расширения128МиБ tmpfs

Fill≥200МиБ **не запускать** в `/tmp` или media-exchange tmpfs. После отдельного технического ревью runner может подключить уже существующий `state` volume тестового foundation project: имя/labels/env проверяются, dev/main volumes запрещены. Новый том не создаётся. Только собственный namespace `rc-q351/<runUUID>/` и TempDir внутри него, UID10001/0700/no-follow; MEDIA_LIBRARY_ROOT направляется в этот TempDir, прочие данные volume не перечисляются/не меняются. Root предварительно объясняет это подключение владельцу.

Предлагаемые предохранители **тестового опыта**, не новая квота продукта: до512 файлов по≤1МиБ, total own fixture≤384МиБ, перед наполнением actual available≥512МиБ, serial execution. Payload создаётся порциями с ограниченной памятью; badly-compressible тексты и actual st_blocks определяют достижение полосы, не сумма ожидаемых lengths. Новые CPU/RAM/pids/128МиБ tmpfs caps не увеличиваются. При нехватке места/незнакомом volume/пределе fixture —остановить опыт, не расширять ресурсы автоматически.

Состав большой истории сверяется bounded count+ID/schema/payload/reference digests по **всем** rows/files без сотен МБ вIPC. После фиксации результата удаляется только доказанно собственный test namespace по защищённому пути; product orphans не очищаются ради теста. При storage/fault исходе сохраняется безопасная диагностика, ошибка не переименовывается вуспех recovery.

Следующий gate — независимое ревью RC API, profile manifest/accounting и этого corpus; затем ограниченный код/калибровка и **положительные** HTTP/FS/PG проверки. Native RAM/UNKNOWN UI, real Nginx, публичные validators/menu и полный accepted browser corpus отмечаются отдельно, если конкретный прогон их не исполнил. Ни полный DEV-07, ни production заранее не принимаются.
