# Восстановление общих блоков и совместимость компонента

2026-10-30. Этап7, D-301/302/305/308; PR-02 analytics-protocol-contracts.md, AT-405/AC-PRO-005. Только тесты и контракты. Старый сайт/VPS/БД/файлы/настройки не меняются; приложения и его кода здесь нет.

`acceptance/shared-component-restore.spec.js`:4экземпляра, по2 для Header/Footer. Сохраняется прежний BLOCK-compare-restore-* поднабор; новый отдельно проверяет сохранённый payload/schema, буквальный прежний телефон и несовместимый доверенный компонент.

## Действия и наблюдения

Профиль `shared-block-component-history(kind)` создаёт синтетическую историю настоящего общего блока в изолированном приложении: текущий совместимый снимок с `+70000000002`, совместимый старый с `+70000000001`, старый несовместимый schema снимок того же доверенного компонента. Номера только тестовые маркеры, звонков/внешних интеграций нет. Несовместимость возникает из реально отсутствующей безопасной отрисовки сохранённой схемы, не из флага expectedDenied. Профиль не создаёт новый исполняемый тип продукта или произвольный редакторский JS.

Используются существующие реальные UI/HTTP операции `compare-shared-block-version(kind,version)`, `prepare-shared-block-restore(kind,version,base)`, `apply-shared-block-version(kind,version,base,confirmation)`. Compare выводит сохранённые данные безопасным текстом и отличия, не выдаёт новый текущий рендер за исходный экран. Дополнительные result поля `comparison.savedPayload` и `comparison.componentSchemaVersion` извлекаются из фактического ответа, а не из входной fixture. LiteralContactValues — реально показанные значения сравнения.

Совместимый restore требует настоящего подтверждения владельца. Снимок не меняется, появляется одна новая текущая версия выбранного блока, публичная страница содержит прежний буквальный телефон; другой блок не меняется. Совпадение отрисовки с побайтным старым экраном не требуется: доверенная совместимая отрисовка может измениться, сохранённый payload/schema остаётся исходным.

Несовместимый снимок доступен владельцу как данные. Подготовка отклонена с «Версия несовместима». Поддельное прямое применение также отклонено; прежнее текущее/черновик/история/другой блок и публичное содержимое не изменены. Это частичная негативная ветка: гонка изменения версии компонента после настоящего выданного подтверждения не покрыта.

Наблюдения read-only:

- `shared-block(kind)` и `public-with-shared-blocks(page=P-ONE)` существующие actual-db/actual-http; версии/черновик и фактические публичные Header/Footer/pageText.
- `shared-component-history-evidence(kind)` — фактические ID подготовленных сохранённых версий и синтетические oldPhone/newPhone, без готового результата операции.
- `shared-component-block-state(kind)` — actual-db проекция `{currentPayload,draftPayload,currentSchemaVersion,draftSchemaVersion,currentAssets,draftAssets}` фактических текущих/черновых component data и Asset bindings. Равенство до/после incompatible compare/prepare/apply ловит частичное изменение структуры даже при прежнем HTML/revision. Нет whole-DB digest, подмены записями expected или динамических логов в oracle.
- `shared-component-snapshot(kind,version)` — actual-db `{versionId,componentId,schemaVersion,payload,assets:[{id,sha256}]}`. Байты Asset должны быть действительно прочитаны и хэшированы fixture; не переписанные ожидаемые SHA. Полный объект сверяется после compare/restore/отказа.
- `shared-component-runtime(componentId)` — actual-http диагностическое чтение реально выбранного доверенного renderer: `supportedSchemas` и trace фактических вызовов `{invocationId,componentId,schemaVersion,phase}` собственного run. Инструментирование наблюдает настоящий вызов implementation/resolver, не просто входной запрос compare, не имитирует бизнес-ответы и не добавляет публичный endpoint продукта. У неподдерживаемой schema число/состав вызовов неизменны; настоящий текущий публичный render обязан дать новый supported invocation, иначе пустой/сломанный trace не считается доказательством. Последовательность/завершение trace требует проверки concretebindings, без потери/очистки событий в интервале.

Существующий драйвер передаёт действия реальному UI/HTTP и читает actual-db/actual-http, дополнительного произвольного транспорта не требуется. Реальные schema/имена компонент/селекторы/пути неизвестны до приложения и должны пройти независимую проверку. Не требуем отдельного реестра контактов или исполняемых плейсхолдеров.

## Границы результата

Приложения, concretebindings и fixture bridge нет;4сценария не исполнялись, полный AC не пройден. Node syntax/сборка пакета — проверки тестов. Trace проверяет серверный путь выбранного несовместимого компонента, не доказывает отсутствие любого клиентского JS/внешних сетевых обращений/CSP проблем. Все компоненты, unsafe migration, исчезновение Asset, crash/concurrency/version drift и полный аудит схемы остаются отдельными ветвями. Полный TEST-07 и переход к этапу8 не объявляются завершёнными.
