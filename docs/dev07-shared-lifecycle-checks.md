# DEV07-SH-LC — сценарии до реализации

2026-11-01. Сценарии до кода к [DEV07-LC-Q001](dev07-shared-lifecycle-proposal.md), согласованы D-354 после независимого ревью. Согласованный вход SHA0afb03fc83220ed2353b8acd6ca43b2c8fa0cc4eee085928433852484dc43ce9. Это не результаты тестов. Связи: REQ-022/AC-022, AT-115–117, AC-DTL-017/019 и сохранённые правила приватности/owner-only; разрешение ручного удаления дано отдельным ответом владельца.

| ID | Проверка и независимый oracle |
|---|---|
| LC07-001 | Реальные owner/employee/anonymous HTTP: только nesadmin видит закрытые списки/descriptor projection; GET/preview не меняют историю/AssetUsage/jobs/файлы; forged POST/CSRF/чужой block/старый пароль/сброшенная generation не удаляют данные |
| LC07-002 | Preview выбранной проверенной file-version: правильные блок/номер/дата/автор/размер и зависимости. Current, draft base, source/base любого stage (held/consumed/released/invalidated), pin и unknown protection/legacy исключены с видимой причиной; terminal stage metadata не удаляется. Подмена ID/descriptor/token не расширяет выбор |
| LC07-003 | После preview другой owner-контекст делает выбранную версию текущей либо удерживает её в draft/stage: confirm отклонён целиком, никакого unlink/отсоединения refs. Истёкшее подтверждение требует нового preview, ввод редактора сохраняется |
| LC07-004 | Реальное удаление одной допустимой версии: новая текущая/другой блок/страницы/черновики неизменны; удалена ровно выбранная history row; постоянные identities/старые receipts сохранены; Asset с другой ссылкой побайтно цел. Последующий exact replay старого Save даёт gone без воскресания. Принудительное совпадение нового UUID с retired blob key отклоняется writer без переиспользования/удаления нового файла |
| LC07-005 | Два параллельных confirm/повтор с тем же намерением дают один job и одно удаление. Изменённый target/fingerprint с тем же operation UUID отвергнут. Потеря ответа после SQL commit разрешается чтением/ручным продолжением того же job, не новым удалением. После password reset/new session старые подтверждения отклонены; тот же immutable job продолжается только после нового owner подтверждения/пароля |
| LC07-006 | Сбой до durable job/перед metadata commit: история и refs целы; rollback bloat учтён. После metadata commit до/во время unlink: честный частичный результат, descriptor сохранён, orphan учитывается. Crash после unlink до job update: отсутствие ожидаемого файла завершается только при доказанной фазе, отсутствии refs и fresh nofollow/fsync parents. Сбой fsync/подмена inode/symlink/hardlink/не тот SHA/не та фаза не дают полного успеха и не удаляют чужой файл |
| LC07-007 | Новая связь/незавершённая запись конкурирует с cleanup под той же lease/content domain: нет dangling live descriptor. Повтор после настоящего завершения процесса использует сохранённый job, не только in-memory seam; отсутствие descriptor/расхождение фаз блокирует изменение |
| LC07-008 | Новый profile фактически учитывает все собственные PG roots/индексы/TOAST, jobs, держатели и свои FS остатки. На границе отказа Save допустимая очистка укладывается в256МиБ; большой и малый HTML, PG rollback/поздние status updates/AssetUsage share jump не прячутся. Кандидат выключен до измерений и независимого ревью |
| LC07-009 | Настоящий браузер: выбрать версию→просмотр→пароль/подтверждение→результат; отмена не удаляет, непотреблённый/оборванный ответ не показывает ложный успех. HTML/пароль/токены не попадают в URL/Web Storage/логи; несохранённый редактор не очищается |
| LC07-010 | Диагностика known commit/abort показывает actual receipt/book и проверяемый исход; ручная reconciliation не создаёт версию. No-receipt/corrupt/mismatch/fault остаются held/blocked даже после нового сеанса; ошибка измерения показана неизвестным размером, не нулём. Без кнопки обхода, TTL и обнуления debt |
| LC07-011 | Аддитивная миграция сохраняет все старые поля/данные/книги;0001–0004 hashes неизменны. Изменённая/неизвестная схема не проходит старый runtime signature. Backup/restart учитывает незавершённый job; старые RC regressions повторены на точном frozen source |

План исполнения: независимое ревью этих условий→ответ DEV07-LC-Q001→ограниченная реализация/QA→фактическая калибровка→повторное ревью→shared regression и новые HTTP/Chromium сценарии. Реальный kill процесса/возобновление и partial-FS не объявлять доказанными по одной mock-ошибке. Физическое отключение VPS, массовая очистка orphan и новый механизм Stable не входят в этот срез.
