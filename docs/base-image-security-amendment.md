# TEST-Q009: поправка к составу локальной основы

2026-10-30. **Согласовано владельцем TEST-Q009 / D-315**. Подготовка и испытания выполнены; [текущие результаты](base-image-security-remediation.md). Ниже сохранено содержание предложения до ответа.

## Причина

Удаление неиспользуемых пакетов исправляет Nginx без смены версии. Для оставшихся проблем нужны две поправки к D-311:

- psycopg-binary 3.3.6 поставляет собственный OpenSSL 3.5.8. Системные обновления его не заменяют. В Debian libssl3t64 3.5.7-1~deb13u3 уже содержит нужные vendor backports; можно использовать системные библиотеки через **psycopg[c] 3.3.6**. Libpq из стабильной Debian — **17.11**; это версия клиентской библиотеки, сервер остаётся **18.6**. Подготавливается отдельный кандидат, после D-315 основной lock обновлён по проверенному собранному wheel.
- Стабильные Debian и проверенный официальный Alpine-вариант PostgreSQL 18.6 пока не предоставляют исправления всех отмеченных XML-путей. Смена libc сама по себе ничего не исправляет. Для проекта не определены данные типа SQL XML или XSLT в БД; XML-карта сайта создаётся на уровне сайта и не зависит от этой функции PostgreSQL.

## Рекомендуемый ограниченный вариант

Сохранить **Python 3.14.10 / Django 5.2.18 / PostgreSQL 18.6**, заменить binary-адаптер на **psycopg[c] 3.3.6** с системной libpq17.11 и собрать PostgreSQL18.6 из официального release-архива **без опциональных SQL XML/XSLT**. Debian/glibc и обычные текст/JSON/числа/даты, SCRAM и TLS остаются. Для сборки сохраняются источник/SHA256, точные зависимости и параметры; компиляторы только в builder, не в runtime и не в Windows.

Это сборка инфраструктурного инструмента, не код сайта. Контейнер БД перестанет поддерживать SQL XML-функции/касты; они должны возвращать штатный отказ отсутствующей возможности. Нужно проверить отсутствие libxml2/libxslt в runtime и реальную работу сервера/клиентов/pg_dump/pg_restore, обычных типов, миграционной и runtime-ролей, PostgreSQL-contrib, сохранность и сеть. Сборка не объявляется рабочей до этих проверок и независимого ревью.

В отличие от готового официального образа появится обязанность воспроизводимо пересобирать нашу инфраструктурную сборку при обновлениях PostgreSQL и зависимостей. Версии и источники должны оставаться закреплёнными. Production этим не выбирается. Для испытания — новые собственные тома; прежние тома не подменять и не удалять. Неизменность сортировок/locale нельзя предполагать: значения и контрольные примеры сравниваются явно, новые бизнес-правила сортировки не вводятся.

Альтернатива — оставить исходный сервер без самостоятельной пересборки и ждать проверенного vendor-исправления XML. Тогда эти advisory остаются открытыми; назвать их устранёнными нельзя. Простое скрытие findings или замена Debian на Alpine с той же уязвимой библиотекой не являются исправлениями.

## Вопрос

**TEST-Q009:** согласовать подготовку/проверку PostgreSQL18.6 без SQL XML/XSLT и переход на psycopg[c]3.3.6 с системными библиотеками как пакет исправлений локальной основы?

1. **Подготовить и проверить вариант — рекомендую.** Понадобится наша воспроизводимая сборка БД; SQL XML не будет доступен. Окончательные hashes и результаты фиксируются после сборки, runtime-допуск не выдаётся заранее.
2. **Ожидать исправленного официального образа.** Не собирать сервер самостоятельно; XML-остаток пока не закрывается.

Код сайта, старый сайт и VPS этим вопросом не разрешаются. Согласование требуется потому, что меняются непосредственно принятый вид адаптера и состав сборки БД (AGENTS.md: «Конкретная архитектура, версии и зависимости проходят отдельное согласование»).
