# Ручные операции версий и логов — исправления ANA-R002/ANA-R003

Версия 0.1, 2026-10-30. Дополнение ANA-01 в ходе независимого ANA-02. Основания: D-029/D-030/D-031/D-044/D-046/D-093/D-095/D-098 и утверждённая архитектура §10. Новые детали ниже — **технический профиль к согласованию пакета**, не самостоятельное решение владельца и не код. Связи: REQ-062/REQ-063, AC-062/AC-063; существующие REQ-013/REQ-017–REQ-024/REQ-028/REQ-029/REQ-038–REQ-042.

Действия только с актуальной сессией и серверным правом `nesadmin`, через защищённый POST; GET/просмотр не создаёт версию и ничего не удаляет. Сотрудник не получает действия прямым запросом, восстановлением, подменой типа или ID. Дополнительный повторный пароль для этих двух обычных ручных действий не вводится: принятые отдельные требования для удаления всей страницы/заявки/снятия Stable/restore сохраняются.

## MAN-01. Создание ручной контрольной Page-версии

### Источник и метаданные — предложение

Контрольная версия создаётся из **явно показанного текущего сохранённого состояния Page (`currentRevision`)**, а не из произвольного тела запроса. Показываются страница/точный URL, ID/серверный момент исходной редакции, публикация и сравнение при отличающемся открытом редакторе. У непубличной Page это её допустимое сохранённое состояние; действие не публикует её.

Отдельный административный черновик не становится источником обычной общей истории Page по умолчанию: иначе его можно незаметно раскрыть сотруднику, который по D-046 видит всю историю назначенной страницы. Несохранённый ввод не сохраняется/не публикуется от нажатия «Создать контрольную версию». Если редактор отличается, владельцу явно сообщается: «Сохраняется показанная сохранённая редакция; несохранённые изменения и отдельный черновик в неё не входят». Ввод остаётся в открытой вкладке. История отдельного черновика не создаётся этим дополнением как новая функция.

Ручной профиль: название до 200 символов (непустое либо явно показанная системная подпись «Контрольная версия»), комментарий до 1000, пользовательская дата обновления в явном формате; real created_at/author/source revision — отдельные серверные значения. Пользовательская дата не меняет сортировку реальных сохранений/очистку. Эти длины предлагаются вместе с остальными полями, не являются поисковым ограничением/внешним нормативом.

Если `currentRevision` сменилась после подготовки действия, создание отклоняется как устаревшее с показом нового источника/сохранением ввода; нельзя сохранить незаметно иной снимок под прежним подтверждением. Подпись/автор и ID исходника не принимаются из доверенного клиентского поля.

### Успешное постусловие

- Создана одна новая неизменяемая версия с новым непереиспользуемым ID и типом `manual`, точным допустимым payload показанного источника и удерживаемыми ссылками Asset.
- Текущая публикация, `currentRevision`, отдельный административный черновик, URL/родитель/порядок/публикация не меняются. Создание контрольного снимка не является публикацией или восстановлением.
- Версия обычная; Stable не наследуется. Назначение Stable остаётся отдельным явным действием владельца по существующим правилам, не выводится из слова «стабильная» в комментарии.
- Снимок входит в общий предел десяти обычных Page-версий. Применяется удаление старейшей допустимой обычной, исключая текущую публикацию и Stable; Asset, нужные оставшимся потребителям, сохраняются. Новый снимок не получает искусственную старую серверную дату из пользовательского поля.
- Записан безопасный аудит автора/страницы/ID новой и исходной версий/результата. Полный текст страницы и комментарий не копируются в логи. Отказ фиксации не выдаётся за созданную версию, новая история не возникает частично.

Повтор после потерянного ответа использует тот же защищённый ID операции/receipt; не плодит несколько ручных версий. Это служебный повтор административной операции, не публичная квитанция заявки. Профиль Header/Footer этим действием не расширяется.

## MAN-02. Удаление выбранной обычной Page-версии

Предлагаемое подтверждение: страница/URL, ID версии, тип, имя, пользовательская и серверная даты, реальный автор, текущее состояние Stable/использования. Кнопка удаляет **одну показанную версию**, не страницу/поддерево/все версии. Количество и общий состав истории не служат разрешением удалить любую запись по позиции списка.

Перед исполнением повторно проверяются актуальная сессия/права, принадлежность версии странице и её состояние в общей точке фиксации контента:

- нельзя удалить Stable, текущую опубликованную редакцию или используемую сохраняемым черновиком/операцией основу, пока эта зависимость не разрешена явным допустимым действием;
- если после подтверждения назначена Stable/изменилось использование — отказ с актуальной причиной, а не автоматическое снятие защиты;
- если версия уже выбыла по лимиту/удалена другим подтверждённым действием — показать её отсутствие, не удалять «следующую» по индексу; повтор той же операции возвращает её результат;
- файлы других текущих страниц, общих блоков, версий/Stable, черновиков и двух HTML-наборов остаются. Утрата последней ссылки делает Asset только кандидатом для отдельной ручной очистки D-263, не автоматически удаляемым файлом.

После успеха выбранный снимок недоступен в истории, остальные версии/текущая страница/публикация не изменены. Не создавать взамен новую Page-версию только ради удаления записи истории; создаётся отдельный безопасный аудит операции. Ошибка/конфликт не удаляет часть снимка/ссылок и не меняет публичный валидатор без изменения его настоящих зависимостей.

## MAN-03. Ручное удаление логов выбранной категории

### Подтверждённый набор

Владелец выбирает одну из девяти серверных категорий, не произвольный путь/SQL-фильтр. Подтверждение показывает её название, период/верхнюю границу, число событий/групп, данные БД и физические файловые байты с маркировкой точности оценки. Один сгруппированный сканерский ряд не выдаётся за одно исходное событие. Секреты/тела заявок в предупреждение не добавляются.

Проект границы: непереиспользуемый ID операции, верхний порядок событий категории `L` и перечень её сегментов/стабильных диапазонов с поколением/контрольной суммой. Это **зафиксированный набор до подтверждённой границы**, не команда «удалить всё, что окажется в категории к концу операции». Новые события после `L` остаются новыми и не удаляются. Если существующий подтверждённый диапазон/его состав меняется, требуется новое актуальное подтверждение; простое добавление событий вне границы не расширяет удаление.

Для активного append-only сегмента допускается только подтверждённый стабильный префикс; при ротации идентичность диапазона сохраняется. Новые байты/агрегаты после границы не исчезают вместе со старым именем файла. Если текущая модель сегментов не может доказать диапазон без захвата новых событий, удаление этого файла отклоняется/остаётся явно незавершённым до безопасной ротации; удалить файл целиком «для простоты» нельзя.

### БД и файлы не объявляются одной транзакцией

1. Проверить права/подтверждённый набор и зарезервировать ограниченный журнал операции. Нельзя показывать полный успех, если негде зафиксировать результат/защищённый аудит.
2. В согласованной операции удалить/скрыть выбранные структурированные события и отметить подтверждённые диапазоны файлов как логически удалённые; записать состояние исполнения. События за границей не затрагиваются.
3. Физически убрать допустимые закрытые сегменты/диапазоны с повторной проверкой принадлежности/границ. Общие/чужие категории и новые события не удаляются.
4. Успех «Удаление завершено» только после проверки БД и файлов. Если физическая очистка не завершилась, статус «Записи удалены, очистка файлов не завершена», с фактическими числами/объёмом и возможностью повторить **ту же операцию**, а не расширить область.

Состояния предложения: `PREPARED`, `LOGICAL_DONE_FILES_PENDING`, `COMPLETED`, `FAILED_BEFORE_COMMIT`, `RESULT_UNKNOWN`. Неопределённый коммит сначала выясняется по ID, не считается автоматически отказом/успехом. Нельзя вернуть в список логически удалённые события только потому, что их байты пока ждут очистки; физический размер при этом не показывается нулевым. Неполнота видна явно.

При переработке части сегмента нужен запас в **том же общем 1 ГиБ**, включая старый/новый/временный файл/манифест. Нехватка не позволяет превысить квоту или удалить новые события: физическая стадия ждёт безопасного места/ротации и остаётся незавершённой. Нет фиксированной квоты на категорию, новой автоматической очистки заявок/медиа или изменения 30-дневной политики важного аудита.

### Защищённый аудит и счётчики

Безопасное доказательство удаления находится **вне подтверждённого удаляемого набора**, в другой защищённой категории либо внешнем техническом журнале по архитектуре §10. Предлагаемый основной выбор категории: «Действия пользователей», а при удалении её самой — «Резервирование и обслуживание». Запись не содержит удалённого тела, хранит автора/категорию/границу/число/объём/результат/ID операции. Последующая очистка другой категории также оставляет своё новое доказательство за её границей; операция не может незаметно удалить собственный актуальный аудит. Внешний журнал, если выбран, имеет отдельные права/ротацию/квоту, не выдаётся за бесплатное неограниченное хранилище.

Логическое удаление не двигает `LogReadCursor` и не имитирует «Отметить просмотренными». Значок пересчитывает **оставшиеся** новые события: при удалении последних оставшихся непрочитанных он может стать нулём вследствие отсутствия записей, но это не отметка просмотра. Новые события после подтверждённой границы сохраняют непрочитанность. Неисполненная физическая очистка показывается отдельным состоянием/объёмом, не подменяет число текущих видимых записей.

Удаление не закрывает обычный notification cycle и не создаёт новый цикл одним фактом очистки; D-095 связывает повтор обычного уведомления с явной отметкой просмотра и новым событием. Кнопка отметки доступна и при пустом списке, если ещё есть неотмеченная граница/цикл. Для неё используется стабильная граница журнала, а не только максимальный ID оставшейся строки. Для владельца показывается различие «записей нет» и «проблема исправлена/цикл подтверждён» без ложного recovery.

Открытый critical/состояние доставки живёт независимо от удаляемого тела событий: ручная очистка/просмотр не подтверждают техническое восстановление. Новый другой critical остаётся уведомляемым по D-273, даже если категория была очищена. Ограниченный отдельный журнал исполнения удалений/состояния инцидентов не является бессрочным архивом всех удалённых логов; не добавлять их тела ради сохранения циклов.

## Постусловия для общей карты операций

| Операция | Успешный результат | Неуспех |
|---|---|---|
| Контрольная Page-версия | Один снимок показанного сохранённого currentRevision, метаданные/Asset/обычный лимит, без публикации/автосохранения ввода | Нет частичной версии, источник/ввод сохранены; устаревшее основание требует нового просмотра |
| Удаление обычной версии | Только показанный допустимый снимок удалён; текущая публикация/Stable/чужие Asset сохранены | Конфликт/Stable/актуальное использование/отсутствие показаны без удаления другой записи |
| Удаление категории логов | Подтверждённая граница исполнена в БД/файлах, новые записи/чужие категории/аудит сохранены | Частичный/неизвестный результат наблюдаем; повтор только того же набора, без сброса critical/чтения |

## Граница исправлений

Документ закрывает пропуски контрактов ANA-R002/ANA-R003 на уровне проекта. Принятые функции не заменяются автоматической очисткой/удалением всей страницы. Точный формат сегментов/receipt/синхронизации/защищённого аудита и размеры проверяются при выборе реализации; необходимые свойства/отказы заданы до кода. Независимый рецензент должен отдельно подтвердить исправления; автор не закрывает замечания вместо него.
