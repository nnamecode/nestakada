`acceptance/editor-safety.spec.js`: **30 экземпляров**. Один положительный сценарий проверяет сохранение допустимых H2/абзаца/выделений/списка/обычной текстовой таблицы;16проверяют атомарный отказ владельцу и назначенному сотруднику для8вариантов активного HTML/CSS/шаблонного синтаксиса;3проверяют разрешённые local/http/https ссылки;10 — запрещённые схемы, HTML-сущности/смешанный регистр/контрол, неоднозначные protocol-relative/userinfo/backslash URL.

Обычная тестовая таблица не содержит прайс и не даёт сотруднику отдельного права менять цены. Отдельный главный H1, SEO, медиа, прайс и административный черновик при положительной текстовой правке сохраняются. Внешние example.invalid адреса — только литералы ввода, ни одна ссылка не открывается и не вызывается.

## Контракт реального тестового подключения

Используется принятый профиль `assigned-page-with-owner-draft`: назначенный сотрудник имеет право на основной текст, отдельное право прайса выключено, есть непустые опубликованные данные/версия и отдельный административный черновик. Профиль не создаёт ожидаемые результаты публикации. Существующий `page` возвращает фактические поля, историю, текущую версию и её основание.

- `act(actor,publish-rich-text-direct,{page,base,html})`: настоящий прямой запрос явного сохранения/публикации области rich text. Для сотрудника допустимый текст выходит сразу; для владельца выбирается именно явное применение к публикации, а не сохранение черновика. Это тестовое название для настоящего согласованного UI/HTTP-пути, не новый endpoint сайта. Прямой запрос не проходит браузерную очистку, maxlength или собственный sanitizer адаптера; байты HTML/сущностей сохраняются. Результат accepted/denied подтверждается фактическим серверным ответом, не одним HTTP200.
- `observe(page-rich-text-html,{page})`, actual-db: `{pageId,revision,versionId,html,versionHtml}`. html читается из реально сохранённой текущей области; versionHtml — из конкретной текущей автоматической версии, связанной versionId. Если схема хранит структурированные узлы, их фактическая безопасная сериализация не должна достраивать отсутствующие данные из отправленного тестового payload. Чтение не исполняет HTML.
- `observe(public-rich-text-html,{page})`, actual-http: `{pageId,status,html}` из настоящего публичного ответа; html — собственная область материала, исключающая общую шапку/меню/Footer. pageId доказывается фактической связью маршрута с объектом, не echo fixture. Не возвращать body из БД вместо ответа сервера.

Положительный HTML инертно разбирается собственным DOMParser теста при JavaScript disabled/service workers block/HTTP и WS abort. Проверяются содержательные узлы и смысловые ячейки независимо в сохранённом материале, его версии и публичном ответе. Для `_blank` сохраняются назначение ссылки относительно фактического origin стенда и подпись, присутствует `rel=noopener`; дополнительные rel не навязываются. Допустимая сериализация локального пути как абсолютного URL того же origin не считается ошибкой. Это проверка разрешённой структуры, не доказательство runtime-безопасности браузера.

Отрицательные пробы требуют полного отказа, неизменённых основных/защищённых полей, черновика, истории/редакции и фактической сохранённой/public области. Нельзя молча вырезать опасный атрибут и опубликовать остаток. Затем тот же actor через ту же операцию со свежим разрешённым безопасным HTML успешно публикует новую автоматическую версию; недоступный обработчик/потерянное право не считаются достаточным отрицательным результатом. Отдельный безопасный аудит отказа допускается.

Названия действий/наблюдений не задают HTTP-поля/ORM/селекторы реализации; конкретные bindings/bridge отсутствуют и потребуют независимого ревью. Ни в одном тесте нет sanitizer, эмуляции бизнеса или результата `executed:false` вместо наблюдения исполнения.

## Остаток и проверки

Полные AT-104/106 не закрыты. Отдельно остаются границы1МиБ/200000символов/20000узлов/depth32, числовые стили и нормализация Word до сохранения, восстановление безопасной версии, все атрибуты/контексты/Unicode/IDN/якоря, protected меню/кнопки, double-percent encoding, фактическое отсутствие серверного fetch/SSRF, JS-enabled исполнение/CSP/внешние запросы и независимые runtime canaries. Percent-encoded строка может быть безопасным буквальным относительным путём; общее требование запрета исполнения не подменяется выдуманным требованием отклонять любую такую строку.

Новые бизнес-сценарии не запускались: нет приложения/конкретных bindings. Проверены синтаксис файла и формат diff; целевое независимое ревью новых существенных замечаний не нашло. [Отчёт](acceptance-editor-time-review.md). Самостоятельный DOMParser не означает проверку настоящего редактора или запуска scripts. Полные AC/TEST-03/TEST-07/UX-07/ARC-10 остаются открытыми; этап8/production не разрешены.
