2026-11-02, D-379/D-380. Профиль и этот план согласованы владельцем по DEV15-Q002 в конце смены. Реализация и локальные испытания разрешены со следующей смены; активация только после соответствующих code/QA/capacity gates. Принятые локальные пределы:1000операций/4096историческихссылок/1024tombstones, прежние64+16МиБ; до16policyrows по32КиБ учтённого размера и прежние4recovery receipts. Это сценарии до кода, не PASS; новый профиль пока не реализован. Старый сайт/VPS/DEV-29/внешние подключения не входят. Связанный документ — dev15-runtime-admission-proposal.md.

## Порядок

1. Независимое ревью предложения и этого плана, затем DEV15-Q002 владельцу. Ответ разрешает подготовку и испытания, но не заменяет code/QA/capacity gate активации.
2. Сохранить исходные source/config/Head/counts/legacy pin/ключевые SHA и точный intent. Подготовить небольшие изменения validator, additive0003, операторскую команду и потоковый full-state digest. 0001/0002, APP и прежнюю историю не менять.
3. Code/QA review до запуска. Один guarded Start disabled → unit/integration на проверенной UNIT с проверкой прежнего архива → Stop. Baseline97 проверяется на новом source; число новых тестов фиксируется по факту, прежний PASS не подменяет новый прогон. Миграция MAIN без политики оставляет запись закрытой.
4. Проверить capacity/fault corpus только в точной UNIT после проверки принадлежности и пустоты. Собственный attempted receipt фиксируется до процесса; старый calibrationAttempted не сбрасывается. Новый corpus сохраняется. Для последующих unit сначала потребуется проверенная процедура сохранения второго corpus с фиксированным новым именем и подписанной квитанцией, без стирания первого архива.
5. Независимое ревью capacity/ресурсов/source/schema. Затем — закрытая операторская активация MAIN по точному текущему состоянию. Для имеющегося набора ожидается Head9/epoch2, при активации generation намеренно увеличивается до10; прежние данные и legacy pin сохраняются. Иное фактическое состояние означает отказ и разбор, не подгонку expected.
6. Ограниченный native набор: новые IDs без trial whitelist, replay, UNKNOWN/terminal lost body и transport cases. Полные 5120 snapshot items искусственно не добавляются в MAIN: их HTTP-чтение измеряется на сохранённом UNIT corpus. Временный readonly тестовый API использует только точную UNIT DB, прежние images/networks/caps; writer disabled. Перед возвратом к MAIN — Stop, пересоздание и проверка identity/config. Эта test-only конфигурация является частью предложения Q002, не разрешает APP доступ к TRUST.
7. Final source/schema/config/evidence/privacy/архивы/данные/Stop и независимый local completion review. Обычный финал — disabled, неактивный lease, Stop, сохранённые данные. DEV-29 и production автоматически не начинаются.

UNIT-калибровка не может заранее ссылаться на SHA собственного незавершённого отчёта. Используется закрытый code-owned test context, допустимый только для точной UNIT DB: он обходит лишь отсутствующее окончательное операторское evidence, но не испытываемые типы, effective caps, авторизацию операций, CAS, квоты и транзакционные правила. Это не действующая MAIN policy и не ENV-переключатель. Полный HTTP-снимок читается отдельно при disabled writes. Только завершённый PASS-отчёт после review входит в настоящую MAIN policy. Никакой dummy SHA не выдаётся за фактическую калибровку.

Новый код или обязательный FAIL инвалидирует соответствующий source/evidence: исправление → целевое ревью → необходимые регрессии. Старые одноразовые write/Calibrate не перезапускать ради результата; attempts/pin не сбрасывать, лимиты автоматически не повышать. Согласуется конкретное изменение архитектуры/полномочий, а не всякая обычная исправляющая правка в уже принятом профиле.

## Фикстуры и ограничения

MAIN используется только для сохранной миграции/operator activation и ограниченных новых native operations. Его прежнее состояние4operations/Head9/epoch2 не подгоняется задним числом. Максимальные наборы — UNIT с собственным attempted receipt; оба архива сохраняются. Не заполнять SSD, не отключать весь Docker/Windows/host network, не менять системные часы. Physical power loss и rollback всей внешней TRUST здесь не проверяются.

TLS negatives могут потребовать временные сертификатные fixture существующего OpenSSL из того же pinned image. Original TRUST TLS bytes сохраняются приватно; fixture применяется только в изолированном TRUST при stopped front/disabled writes, затем восстанавливаются исходные byte SHA и readiness. Windows trust store и сертификаты живого сайта не меняются. Генератор работает вместо front либо внутри существующего cgroup, не четвёртым сервисом сверх896 МиБ. Воспроизводимость сертификатной fixture проверяется до native, не объявляется заранее.

Disk/SQL injection обозначается именно injection, не физическим ENOSPC. Fault-набор конечен RP13–19, без произведения каждой фазы на каждый fault/браузер. Тестовые механизмы не становятся публичными API/ENV пользователя.
