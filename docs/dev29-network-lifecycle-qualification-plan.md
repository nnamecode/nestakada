## Подготовка и once

После ответа владельца: отдельный закрытый инструмент и fixtures; syntax/static → mocked clock/process/once/privacy/cleanup tests после PASS → независимое code review. Failed observer не импортировать и не квалифицировать повторно. Разрешены изученные working capture patterns, но не обход P29 guards для запуска SQL. Code review проверяет fixed body, handshake, deadlines, exact ownership, отсутствие произвольных аргументов и утечек.

Native проход — только после этих gates и один раз. Plan/source/review hashes, compiled allowlist, отсутствие attempt/report, доступ и размер namespace проверяются до dispatch. Attempt.json создаётся wx до native прохода. Parent env очищается от5 Docker override names case-insensitive; fixed resolved docker.exe, noshell/windowsHide. Не читать private keys, credentials, config или daemon logs. При отказе штатного доступа — STOP без blind ACL.

Ровно один network create, один container create и один start. Network и helper имеют отдельные immutable wx intent/attempt records с name/nonce/profilehash до соответствующего create. Неизвестный исход create не повторяется: максимум один recovery inspect точного имени именно текущей uncertain mutation. После любого uncertain outcome квалификация дальше не продолжается, даже если recovery нашёл owned ID: только cleanup. Если uncertain network create — container create не допускается. Если uncertain container create — сначала разрешить и очистить helper, затем уже подтверждённую network. Чужой/неподтверждённый объект не удалять. Если create ещё может завершиться, а recovery не доказал его завершение/ownership, пустой текущий inventory не превращает aggregate в cleanup PASS: UNPROVEN. Никаких overwrite, retry или fallback.

До attempt/native dispatch установить cancellation latch и SIGINT/SIGTERM handlers. Первый наблюдённый signal/cancellation запрещает новые stages и release byte, переводит тот же flow в finally exact-owned cleanup под прежним absolute deadline, без renewal. При блокирующем OS call latch обрабатывается на первой доступной границе — мгновенное прерывание не обещается. Повторный signal не создаёт новых mutations или retry: прекращает обычную работу, сохраняет только оставшуюся разрешённую cleanup-ветку; если она не может завершиться, cleanup UNPROVEN. Handlers снимаются после terminal/report либо честно зафиксированного reportUnproven. SIGKILL/crash не перехватываются; отсутствие полного terminal/report не является доказанной очисткой. Registry/intents сохраняются для отдельного решения владельца, автоматического повторного запуска нет.

## Нативная последовательность

1. **Готовность.** Fresh same-engine/pinned-image/no-owned-conflict. Начальная пара info+filtered inventory использует изученный Q022 READINESS_ONLY90с, каждый requested≤45с/native≤44с с trace reserve. UI и прежние результаты не заменяют готовность; qualification filter не переиспользует старые Run/attempt/admission.
2. **CREATED.** Создать owned internal network и helper, зарегистрировать exact IDs/nonce. Проверить image/команду/stdin/caps/mountsnone/portsnone/ownership и never-started state. Сделать по одному container inspect и network inspect. Проверить exact intended network name/key, Statuscreated/Runningfalse/StartedAtzero/RestartCount0. Поля имеют строковый тип. CREATED допускает только три согласованные формы: (A) NetworkIDempty/EndpointIDempty/membersEMPTY; (B) NetworkIDowned/EndpointIDempty/membersEMPTY; (C) NetworkIDowned/EndpointIDnonempty/membersOWN_HELPER_ONLY, причём network.Containers[helperID].EndpointID точно равен container EndpointID. NonemptyNetworkID всегда равен exact owned network ID; nonemptyEndpointID — valid hex ID. Любой additional/foreign member, несовпадение helper ID/endpoint, foreign network, иной тип или несогласованная пара снимков — FAIL/UNPROVEN, следующий start не допускается. Снимки не атомарны; переснимать до согласования нельзя. Это диагностическое наблюдение безSQL, не разрешение пустого ID для production RUNNING.
3. **Начало работы.** Start--attach--interactive со stdin pipe, но пока без release byte. Fixed script устанавливает alarm60с, выводит ровно один READY marker с flush и блокируется на чтении одного байта. Он не открывает sockets/файлы и не исполняет вход как код. Это даёт стабильное RUNNING-окно без polling/sleep. Нет READY в бюджете — FAIL/cleanup.
4. **RUNNING.** По одному container inspect и network inspect. Требуются Runningtrue/Statusrunning/RestartCount0, actualNetworkID==owned network ID, непустой EndpointID, точные mode/key, Internaltrue и members ровно из одного owned helper. Пустой runtime ID/чужая сеть/member — FAIL, release не отправлять.
5. **EXITED.** После успешного RUNNING proof отправить один fixed release byte и EOF. Script проверяет байт+EOF, выводит один DONE marker и exit0. Сделать по одному container/network inspect. Status exited/exit0 обязательны, а ID/member presence являются **наблюдением**: заранее не угадывать, остаётся ли NetworkID. Для наблюдения разрешены только пустые или ранее подтверждённые owned network/endpoint IDs; members∅ либо тот же helper. Чужое/невалидные типы — FAIL. Не переснимать до «удобного» ответа. Зафиксировать время снимка и возможную асинхронность отключения, не объявлять универсальный контракт всех версий.
6. **Очистка.** При успехе или ошибке — bounded exact-owned stop/kill при необходимости, remove без-v, затем network remove после ownership/Internal/member проверок. Подтвердить absence и same-engine final inventory только этого scope. Failed mutation не повторять; неизвестное/чужое не удалять. Alarm60 ограничивает жизнь процесса при потере хоста, но не заменяет cleanup proof.

Один absolute totalDeadline=T0+210с устанавливается перед attempt wx и не обновляется. В нём явно резервируются readiness≤90с, work≤85с (create/start/READY/снимки/EOF/exit), cleanup≤30с и report≥5с. Readiness deadline=min(T0+90с,totalDeadline-120с); work deadline=min(workStart+85с,totalDeadline-35с); cleanup deadline=min(cleanupStart+30с,totalDeadline-5с); report deadline=totalDeadline. Пропущенная/быстро завершённая фаза не создаёт renewal; failure/cancellation сразу использует остаток cleanup/report. Trace/storage расходы включены в эти границы. После report write нужен внешний post-write clock check: write после total не является соблюдённым budget, даже если файл сохранился; вернуть reportBudgetUnproven/NOTQUALIFIED без переписи wx artifact. Ordinary metadata/mutation calls≤9с, readiness≤44с. Долгоживущий start--attach stream не является такой короткой командой: его отдельная hard-граница равна оставшемуся work deadline=min(workStart+85с,totalDeadline-35с), без renewal; alarm60с внутри script остаётся обязательным.  команды, traces и report используют остаток исходной границы, без renewal. На deadline новые этапы запрещены, остаётся только разрешённая очистка. Overrun/неподтверждённое удаление/outcome — FAIL/UNPROVEN, без второго прохода и увеличения бюджета. Мгновенное прерывание внутри OS call не обещается.
