# Проверка локального входа Nginx по TEST-Q008

**Актуальная поправка D-315:** локальные runtime заменены проверенными сборками из [итога исправлений](base-image-security-remediation.md). В текущем наборе psycopg[c]3.3.6/system libpq17.11, PostgreSQL18.6 без SQL XML/XSLT и минимальный Nginx1.30.6. Ниже сохранена историческая версия соответствующего этапа; источники исходных образов не являются текущим runtime-lock. Код сайта по-прежнему запрещён.

2026-10-30. Основание: **D-313**, ответ владельца «Согласовать и проверить локально». Проверяется инфраструктурный транспорт со статическим/диагностическим маркером. Код приложения, Django settings/модели/миграции, Dockerfile приложения и Compose сайта не создавались.

**Сетевое исправление прошло локальные проверки. Полного допуска основы по безопасности пока нет:** инвентарь образа выявил пакеты, для которых Alpine публикует исправления. Они не скрыты и не обновлены молча.

## Закреплённый образ и конфигурация

- Nginx **1.30.6**, фактический пакет 1.30.6-r1; Alpine **3.24.3**, linux/amd64.
- Официальный исходный index: `sha256:0e52bd054126cdc040b1276c0af347aeb02a41b9cfe305d6094767ac30e97949`.
- Скачанный platform manifest: `sha256:84ed8c0dd296c188bfc24ed506f46589e9285fb0b11cf3a04d91d524d3067e11`. Он записан в `environment/foundation/images.lock.json`; config image ID сохранён отдельно в локальном inspect. Производный образ не собирался.
- `environment/foundation/nginx-preflight.conf` — конфигурация именно временного сетевого испытания. Один фиксированный upstream `preflight-app:8000`, whitelist локальных Host, без доверия к переданным forwarded-заголовкам; access_log отключён. Временные файлы и PID только в tmpfs `/tmp`.

Нативная установка Nginx/службы Windows не выполнялась. Образ получен в существующий Docker на T:, конфигурация — в проекте. Firewall/hosts/PATH/автозагрузка не менялись.

Сетевые пробы выполнялись одноразовыми Python-процессами в соответствующих network namespaces без доступа к Docker socket или секретам. Приложение заменял только явный диагностический HTTP-маркер; бизнес-поведение/права/ответы Django не моделировались.

В одном измерении простоя Nginx потреблял **3.168 MiB (dev) и 3.238 MiB (test)**, по два процесса. Это не нагрузочное испытание и не прогноз потребления VPS. 128 MiB — верхний лимит, не постоянный расход.

## Первый отказ и исправление

Первый запуск остановился: Nginx пытался создать стандартный `/var/cache/nginx/fastcgi_temp` в readonly root. Поэтому первый host-запрос получил connection refused. Проверены логи и inspect; до повтора добавлены **все** оставшиеся fastcgi/uwsgi/scgi temp paths в `/tmp`. Затем прошёл `nginx -t` под теми же ограничениями, контейнеры запущены повторно, HTTP/отрицательные пробы прошли. Readonly/nonroot не отключались. Это исправление конфигурации инструмента, а не кода сайта.

Исходная проблема D-312 с отсутствующей публикацией из единственной internal-сети сохраняется как исторический факт; она устранена новой согласованной топологией D-313, а не скрытым включением внешнего порта или ослаблением сети app/БД.

## Проверка известных advisory

Сняты **71 установленный APK**, загружены публичные Alpine v3.24 main/community SecDB. Штатным `apk version -t` выполнены **440 сравнений версий**. Для трёх пакетов найдены версии ниже указанных в базе исправлений:

| Пакет | В официальном образе | Версия исправления по SecDB |
|---|---|---|
| brotli-libs | 1.2.0-r1 | 1.2.1-r0 |
| curl | 8.22.0-r0 | 8.23.0-r0 |
| libcurl | 8.22.0-r0 | 8.23.0-r0 |

В этих записях **25 различных CVE**, curl/libcurl разделяют один набор. Это результат сопоставления с базой поставщика, не оценка эксплуатируемости каждого пути. Версии, affected rows и SecDB сохранены в work. Nginx из официального upstream-репозитория проверялся отдельно от Alpine nginx: фактическая версия 1.30.6 соответствует исправленной stable-ветке в актуальной [таблице Nginx](https://nginx.org/en/security_advisories.html). Это не общий вывод о безопасности всего образа.

`ldd /usr/sbin/nginx` в проверенном образе не показывает curl/libcurl/brotli среди библиотек основного бинарника; внешние динамические модули конфигурацией пробы не загружались, entrypoint-скрипты образа не запускались. Это ограничивает проверенный путь, но **не закрывает advisory установленных пакетов**. Перед полноценным допуском нужно подготовить проверяемое исправление/обновлённый образ, закрепить его состав и повторить относящиеся проверки. Произвольного `apk upgrade`, сборки производного образа или смены approved pins в этой задаче не было.

Источники: [Alpine SecDB main](https://secdb.alpinelinux.org/v3.24/main.json), [Alpine SecDB community](https://secdb.alpinelinux.org/v3.24/community.json), [Nginx advisories](https://nginx.org/en/security_advisories.html). База advisory неполна по определению; отсутствие дополнительных совпадений не означает отсутствие неизвестных проблем. Оставшиеся Debian/native вопросы из [предыдущей подготовки](local-foundation-preparation.md) также не закрыты этим испытанием.
