### CLOSE-01: статически подтверждённый интеграционный остаток

Наблюдения NH-001–003 независимо подтверждены чтением файлов, **не запуском обычного стенда/проверкой404**:

- NH-001: app/estakada/urls.py включает shared/media/versions/accounts, но не editor/http_urls.py и editor asset handlers. app/page_editor/urls.py — валидатор ссылок, а не URLConf: включать его по имени нельзя. В app/estakada/settings/base.py нет page_editor в INSTALLED_APPS, TEMPLATES.DIRS пуст, EditorAdmissionMiddleware не включён. QA-host добавлял routes/templates/middleware через probe_settings/price_test_urls.
- NH-002: scripts/local-foundation.ps1 выбирает python-runtime из foundation lock. Обычный runtime094…/environment/foundation/requirements.lock не содержит html5lib/tinycss2/nh3; принятый editor package лежит отдельно в environment/editor-package, candidate782… подключался временным overlay. Нужна нормальная сборка/фиксация **уже принятых** пакетов, не повторный выбор framework.
- NH-003: обычный local-nginx.conf содержит login16k/media11m и общий location / без editor allowlist; используется общий default body limit. D-331 задаёт на Nginx64MiB/streaming только для3 точных Page POST; text5MiB без price-права и shared4MiB — бюджеты application reader, а не отдельные статические ролевые лимиты Nginx. Shared остаётся под согласованным внешним11MiB envelope. Эту связку ingress/reader и отдельные small-action ограничения нужно подключить в обычном профиле. Общая антибот-защита DEV-20 — отдельно, но транспорт собственных editor actions относится к DEV-07.

Точные версии/лимиты не повышаются автоматически. Если конкретный normal-profile diff введёт новый компонент/зависимость/существенную настройку, применяется обычный gate AGENTS.md; сам аудит ничего такого не согласовывает и не устанавливает.

### CLOSE-02: граница отмены

Основания SC-001: dev07-editor-contract.md §6 явно предусматривает cancellation/consume/terminal invalidation и owner stage-cancel endpoint; dev07-shared-lifecycle-results.md прямо оставляет stage lifecycle/cancel открытым. В текущих shared_content/urls.py нет такого действия, commands/services не имеют cancel-ветки, commits.py выполняет held→consumed. Это предусмотренный незавершённый workflow, а не новая опция из непроверенной тестовой комбинации.

**Отмена не означает очистку диска.** lifecycle._target защищает source/base всех stage metadata, как принято LC. Не удалять terminal metadata/версии/фото, не вводить TTL/массовую очистку и не применять force-release к UNKNOWN. Локальный runtime profile/256МиБ и его reservation/maintenance guards сохраняются; конкретный путь учёта cancel проверяется до включения.

### CLOSE-04: конечный состав

Использовать существующие сценарии и доказательства; не переписывать все тесты и не повторять неизменённые векторы без причины. Финальный app source/конфигурация фиксируются одним manifest, различия с прежними доказательствами явно связываются.

1. **Основной рабочий путь:** normal navigation/editor/assets, owner и assigned employee, Check/normalization/Save, price-only права и прайс, простая таблица, draft, selected restore, независимые Header/Footer Apply/restore и новая отмена. Несколько прямых запретов подтверждают сохранность защищённых полей, session/CSRF и раннюю границу тела. Публичный Page renderer этим не подменяется.
2. **FMT004 / AC-013/DTL-004:** конечный сложный table corpus caption/Unicode/marks/head/body/scope/rowspan/colspan/grid/padding → Check→Save→history→selected restore→явный Save без потери структуры. Разрешённый exact HTML/opaque fallback сохраняется. Новые кнопки merge/split не добавляются только из технического упоминания: D-358/TP2 допускает ограниченный simple GUI; FMT004 требует доказать сохранность сложной структуры, а не придумать новый UX.
3. **Два критических media-свидетельства из M07/I07:** один управляемый случай cleanup/новой ссылки при сохранении с настоящими READY bytes/refs и одним допустимым исходом; один selected-source actor switch либо unknown-intent с **непустыми** media/picker/permit maps. Сохранённая версия не ссылается на удалённый файл, чужие активные локальные media-данные/намерение не отправляются. Текстовый SID не выдаётся за эти media-доказательства. Существующие подходящие exact-source доказательства можно переиспользовать после независимой проверки достаточности.
4. **Крупный допустимый ввод:** представитель уже принятого FR07-006/CM-001–003/D-331 corpus проходит обычные ingress/producer/GUI в прежних caps; измерение привязано к этому corpus. При отказе допустимого ввода это конкретный локальный blocker; лимиты не повышать автоматически. Универсальный ресурсный/нагрузочный worst-case всего сайта остаётся TEST-09.

Этот список ограничивает компонентный завершающий набор, не сокращает принятые REQ/AC и последующие TEST-08/09/10. Если прогон выявит конкретный дефект, он получает свой ID и исправляется с затронутыми проверками, а не расширяется в неопределённую матрицу сочетаний.
