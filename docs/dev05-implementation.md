# DEV-05 — локальные версии, Stable и восстановление

2026-10-31, D-327/D-328. Ограниченное ядро и закрытый интерфейс истории реализованы, проверены и прошли итоговое независимое ревью. Реализационная задача DEV-05 завершена в описанной ниже границе.

## Поведение

- Успешное сохранение через доверенный API атомарно создаёт неизменяемый снимок и переключает current. Сбой не оставляет частичной версии, ссылок на медиа или квитанции успеха.
- Хранятся десять ordinary, включая manual и ordinary current, плюс все Stable. Старейшая допустимая определяется серверным временем и последовательностью. Current, Stable и действующие основы защищены. Если новый ручной снимок нельзя сохранить без удаления защищённой основы, операция целиком отклоняется.
- Только nesadmin создаёт ручные версии из показанного сохранённого current, меняет их название/комментарий/пользовательскую дату, назначает Stable после просмотра, снимает её после актуального подтверждения и текущего пароля, удаляет конкретную допустимую ordinary. Manual не копирует чужой черновик и не наследует Stable.
- Сотрудник видит всю историю назначенной страницы. Чужая история и отдельный черновик владельца закрыты. Восстановление сотрудника ограничено его текущими текстовыми правами; права повторно проверяются перед фиксацией.
- Восстановление имеет отдельные шаги сравнения, подготовки, удержания основы и отмены. Сам HTTP-запрос подготовки не меняет current. Доверенные commit API проверяют последующее отдельное сохранение; полноценный редактор и его браузерный save-процесс относятся к DEV-07.
- Данные снимка строго версионированы. История экранирует содержимое, не исполняет Django/HTML/JavaScript. Несовместимую версию можно безопасно прочитать; восстановление отказывает целиком. Защита Stable не требует пригодности старой схемы к восстановлению.
- Current/ordinary/Stable/draft используют настоящие AssetUsage. Очистка истории снимает только её ссылки, физические файлы не удаляет. Исторический WebP выдаётся только через проверяемую связь Page → Revision → AssetFile; private-source не выдаётся даже владельцу.

URL, дерево, публикация страницы, права, общие Header/Footer и метки Stable не откатываются вместе с содержимым. Полное удаление страницы здесь не реализуется: DEV-29.

## Повторы и удержания

Минимальные OperationReceipt и резервации UUID сохраняются без автоматического TTL, без содержимого страниц, паролей, CSRF и session key. Повтор проверяет актуальные права и возвращает сохранённый результат; изменённые параметры с тем же ID не выполняются. Исчезнувший снимок не воссоздаётся из квитанции. Повтор подготовки после отмены/использования показывает её завершённое состояние без повторной подстановки.

Устаревшие stage-основы освобождаются лениво при следующей мутации/очистке истории после проверки current/generation/прав. Это не действие внутри транзакции отзыва прав accounts. Доступ прекращается сразу по актуальным правам. Отдельная основа owner draft автоматически из-за смены current не освобождается; нужны явные действия с черновиком.
