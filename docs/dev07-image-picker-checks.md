## Точная область

Только два внешних поля main_image/preview_image: owner selection/metadata/null и contextual display. Embedded markers/layout/pending_assets E1 не подключаются к HTTP/UI; прежний default unsupported сохраняется. Нет новых типов страниц/компонентов, arbitrary HTML renderer, raw img/src/Snapshot writer или нового Page-local запрета общего Asset.

Переданный API:

- Owner GET `edit/media/?folder&q&after` в контексте Page: `{items:[{assetId,label,folder,mainFileId,previewFileId,mainUrl,previewUrl}],nextAfter}`.50 записей на страницу — техническая пагинация, не лимит фото. Query≤16KiB, только разрешённые параметры; eligible READY с MAIN/PREVIEW. Owner может повторно использовать разрешённые READY assets между Page. mainUrl/previewUrl ведут в НОВЫЙ per-Page `edit/media/picker-files/<FileUUID>/`: owner-only с поздней повторной session/owner проверкой. Существующий `/manage/media/files/` endpoint не меняется и в новом потоке не используется; generic download-by-key не создаётся.
- Contextual GET `edit/media/files/<FileUUID>/` с прежним D07 source selector. Допуск только MAIN/PREVIEW по actual выбранным external-image refs и ledger: current — Page current usages; draft — exact owner draft id/revision/draft usages; held stage — фактический результат `candidate_for_stage`, а не одно предположение о source revision. В принятой совместимой fixture owner candidate берёт исторические external images, employee candidate сохраняет current/base protected external images, но membership всегда выводится из реально вычисленного candidate. Один UUID не является полномочием. Свежие session/grants/membership/descriptors проверяются до и после actual open_verified+WebP header. Ответ private/no-store/nosniff; original/private-source не выдаётся.
- `initial.media` содержит два поля `{reference,url,thumbnailUrl}`. Owner values содержат ImageRef/null; employee values не содержат image keys, хотя может получить разрешённый readonly display. ImageRef — closed `{asset_id,alt,alignment,width_px,height_px}` по DEV05, alt≤300 codepoints, alignment left/center/right, размеры null либо positive integer; bool не integer.
- Child проверяет typed ImageRef/null. Parent media preflight до checkReceipt охватывает ВСЕ effective final image refs: новые и сохранённые из actual selected source, а не только присланные изменённые поля. Затем повторно проверяются свежие identity/grants/source/descriptors. Save использует существующий engine preflight/final descriptor checks. Permanent exact replay идёт до новой проверки media availability, но не обходит текущие identity/session/grants. Actual code/error names и `url`/`thumbnailUrl` variant mapping подтверждаются перед тестами.

Запросы new picker/contextual files используют текущий private origin и не получают64MiB body allowlist автоматически. Никакого внешнего URL fetch, client key/path/MIME/filename/base64 image в ImageRef. История, Stable и физические источники остаются неизменными.

## Независимый oracle и fixture

Повторно используются только `work/dev06-http-20261031/inputs/inputs.json` и существующие valid.png/valid.jpg/valid.webp:206/740/88 байт,100×50 synthetic. Не генерировать новые картинки и не использовать214 gallery originals. Минимум два Asset A/B создаются настоящим existing upload→worker, без ORM READY/AssetFile. Предпочтительны alpha PNG/JPEG, но различие доказывается фактическим derivative SHA, не названием файла. Если производные совпали, контроль нельзя назвать различающим mapping.

Oracle связывает manifest SHA/bytes исходного corpus, реальные AssetFile IDs/kinds/descriptors, actual storage.manifest и HTTP body SHA/length. RIFF/header/status200 или img.complete без byte proof недостаточны. Browser image дополнительно имеет loaded natural dimensions и фактический src того же origin. Ни одно из этих наблюдений не подменяет actual refs/ACL.

Нужна отдельная будущая E2 fixture, а не ослабление старого D07 forbidden-Asset guard. Reuse проверенные own run UUID/user canaries/Page/Route, system Route whitelist, permanent identities/receipts/audit; добавляются только actual-upload Asset IDs, File facts и полный usage kind/consumer/slot. Host накапливает knownFiles исключительно из прежних real DB observations; browser не передаёт arbitrary filesystem paths. null physical допустим только для missing leaf, недоступный parent — ошибка/unknown, не доказательство удаления. Перед close остановить own writers/контексты; content→auth locks и проверка всех owned IDs/refs; cleanup собственных отвязанных assets только существующим prepare/confirm, реальная проверка FS. Чужие данные сохраняются и останавливают уборку.

Backend positive не требует fake READY: после gate тестовый `uploads.upload(actor=..., page_id=..., upload=SimpleUploadedFile(existing_synthetic_bytes,...), expected_generation=...)` вызывает настоящий WorkerClient через уже смонтированный shared exchange socket. Существующий `scripts/test-editor.ps1` использует approved worker/media-exchange; MEDIA_LIBRARY_ROOT допускается собственный TemporaryDirectory внутри тестового контейнера, куда upload после реального decode сам пишет source/main/preview. Будущий test corpus может содержать immutable base64 прежних synthetic PNG/JPEG с независимо закреплённым expected source SHA. Это реальные PG/session/child/worker/FS проверки; они не выдаются за browser upload→picker. Нового worker/image/volume/dependency/resource этим не вводится; запуск — только координатором после freeze.

## API expectations перед исполняемыми тестами

После root/reviewer gate автор подтверждает exact route names/query/cursor grammar/errors, variant mapping `initial.media.url/thumbnailUrl` и slot-specific contextual membership. Нужны actual code seams для cheap admission/slot/all-final-ref preflight/late auth и фиксированные fault outcomes без raw input. Owner orphan preview использует НОВЫЙ per-Page picker-files endpoint с поздним owner/session recheck; существующий `/manage/media/files/` не меняется и не подключается в новом потоке. Contextual selected source не предоставляет generic read к любому READY Asset. UI-S020–023/057 требуют конкретные материал/место, старое+новое, явную «Заменить здесь»/«Добавить здесь» в RAM до Check+Save; глобальная замена не возникает.

Fixture/observer должен различать и возвращать реальные current/draft/stage external refs, usage slot/kind/consumer, File IDs/kinds/descriptors и bounded actual physical manifests. Credentials передаются только в readonly private mount/stdin, без trace/HTML dumps/секретов в stdout. Observer query не выполняет tested action и не принимает произвольные FS paths. Native UI selection/metadata/save, реальные ACL bytes и изолированные PG/FS fault tests проверяются разными подходящими когортами, не обещаются одной e2e автоматизацией.

Пагинационный corpus создаётся теми же existing synthetic upload bytes через worker; это больше genuine uploads, не новая программа/служба/порт/память/CPU/зависимость. Если подготовка/максимум не укладываются в прежний approved профиль, сохраняется факт отказа и новое решение запрашивается отдельно; скрытого resource bump не происходит.

Все M07 **НЕ ВЫПОЛНЕНЫ**. На этом шаге создан только данный документ, application/test/tool code не пишется до отдельного gate. Runtime/Docker/install/network, реальные интеграции, старый сайт и галерея этим QA-агентом не затрагивались. Новые решения не выводятся из прежнего чата: ссылки выше остаются источниками требований. Первая ошибка сообщается с новым основанием повтора; вторая эквивалентная без нового условия останавливает работу по AGENTS.
