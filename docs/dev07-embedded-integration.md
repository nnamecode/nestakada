## Закрытая выдача серверных идентичностей

Owner-only CSRF POST `/manage/pages/<PageUUID>/edit/embedded/issue/` принимает существующий D07 source selector. Это отдельное малое JSON-действие≤16KiB, без расширения большого allowlist. Exact body: `{generation,baseRevisionId,field,action,image,markerId,priorPermit}`. field только intro_text/main_text; action insert/replace; image — существующий closed ImageRef; markerId null для insert либо canonicalUUID для replace; priorPermit null либо строка предыдущей выдачи этого ещё не сохранённого marker. SourceStamp/права сервер берёт из actual selected current/draft/stage, не из присланного hash.

Insert первого инкремента создаёт отдельный защищённый блок **между обычными top-level blocks**. Toolbar сообщает это явно. Сервер выдаёт новые UUID layoutId,parentId,markerId,imageId,slotBeforeId,slotAfterId; клиент их не выбирает. Блок содержит пустые before/after slots, которые затем разрешено наполнять. Вставка внутрь существующего защищённого parent, arbitrary split/join/reparent/reset пока controlled unsupported, не постоянный бизнес-запрет.

Replace сохраняет layoutId,parentId,markerId и slot IDs, но **каждый раз выдаёт новый server imageId/reference UUID**, в том числе при выборе того же Asset. Поэтому общий старый EmbeddedImageRef, на который ссылается другое место/field, не мутирует вслед за заменой одного marker. SourceMarkerFingerprint и прежний reference/metadata сравниваются с действительной выбранной основой. Для pending replacement priorPermit проверяется родителем криптографически и по source binding; результат выдачи — самостоятельное разрешение новых IDs/image, без цепочки permit в DB/RAM/HTML. Идентичности остальных мест сохраняются; старые версии/Stable не меняются.

Exact issue response: `{permit,field,action,ids,image}`, где ids ровно `{layoutId,parentId,markerId,imageId,slotBeforeId,slotAfterId}`. permit подписан существующим Django signing с отдельным domain salt; closed claims `{v,action,actorId,generation,pageId,sourceStamp,field,ids,image,sourceMarkerFingerprint,oldImageId}`. Для insert последние два null. Для замены source или pending previous permit определяет их реальные значения. Подпись/секрет остаются только parent, не передаются child. READY/файлы и late actual session/grants/source проверяются до ответа; issuance не меняет current/draft/history/refs. Повтор запроса не обещает тех же вновь выданных IDs, поскольку это ещё не сохранение.

## Проверка, повторная проверка и сохранение

UI хранит issuance в RAM по markerId. В **Check projection** соответствующий пустой marker получает transient `data-es-media-intent=permit`. Весь токен и полная image metadata входят в прежний source1MiB budget field; отдельного client embedded_images/layout массива нет. В canonical normalisedChanges, Save projection и сохранённом HTML transient attr отсутствует. После accept и правки текста повторный Check снова инжектирует актуальные RAM permits, сохраняя уже выданные IDs. HTML-mode остаётся инертным; projection строится закрытым сериализатором/проверенным lexical adapter, не live DOMParser сырого HTML. После доказанного Save новая основа доверена через DB; соответствующие permits очищаются. Identity change/destroy очищает все адресуемые source/permit/preview копии.

Внутри прежнего единственного EditorSlot child получает actual selected source richHTML+closed layout/embedded subset; не весь price payload для source map. `build_protected_context(...,url_context=URLContext(...))` расширяется только строгим optional actual Page path/origin, чтобы source relative/anchor links проверялись без угадывания. Canonical source map строится E1; ambiguous legacy/unknown protected_ref остаётся fail-closed. Ни parent full HTML parse, ни второй worker/рост20s budget не добавляются.

После whole unsafe guards child допускает только закрытую provisional owner transformation. Возврат дополняется server-only metadata:

```text
derived: {embedded_images, layout, mapHash},
intentBindings: [{field,token,ids,image,sourceMarkerFingerprint,oldImageId}]
```

Все keys/types закрыты. Они выведены из actual candidate дерева, не скопированы как полномочия из клиентского dict. Parent самостоятельно signing.loads каждого token и сверяет каждое claim с actual actor/Page/generation/sourceStamp, action, field, actual old marker/ref и каждым candidate binding. Полный набор новых IDs/изменённых refs должен равняться разрешённым фактам, без дубликатов, foreign/missing IDs и неразрешённых metadata edits. Parent не доверяет worker флагу «подпись верна» и не передаёт child HMAC key. Provisional worker admission не выдаёт права на DOM/publication/proof.

Нормализованный HTML создаёт закрытый serializer, удаляя transient attr. Только после независимой проверки permits, всех retained/new READY/FS и late actual session/source/grants родитель выдаёт CheckReceipt, связывающий normalizedChanges hash, derived.mapHash и действующие source/policy bindings. В receipt только digest карты, не неограниченный список; существующий8192 предел не растёт. Preview mapping возвращается только после этого parent gate.

Save отправляет точный canonical input с прежним checkReceipt и operationId, без transient permits. Child выполняет tentative закрытый derivation; parent проверяет настоящую подпись receipt, точные normalized hash/mapHash/source и реальные assets. Подставной receipt не авторизует IDs. Сначала actual session/grants и permanent exact replay, **до** availability/FS; default-current D334 fingerprint остаётся прежним. Current/draft/stage consume, новая automatic, refs/prune/receipt/audit — существующая единая транзакция. Нет предварительного autosave draft.

Owner snapshot собирает сервер из actual selected payload+checked fields+проверенных derived refs/layout. Замена меняет только нужный marker reference: старый ref удаляется из нового embedded_images лишь если на него больше не ссылается ни одно место нового snapshot. Employee получает actual map, может менять только разрешённые slot text/format, не IDs/Asset/placement/metadata; employee merge сохраняет source layout/embedded. Owner insert может пересчитать paths/fingerprints старых родителей только при доказуемом сдвиге от разрешённых новых top-level blocks: projection удаления новых blocks воспроизводит прежнюю protected map. Прочая структурная операция не объявляется поддержанной. Multiple text-layout descriptors связываются по marker ID, не первым field descriptor.

## PM и серверные URL

Согласованная PM-модель первого инкремента: esProtectedParent — block container; esSlot — **block textblock** с inline* content; esProtected — **block atom** без editable content.
